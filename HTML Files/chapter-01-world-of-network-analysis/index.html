Model Answer
The first two ARP packets reveal the IP addresses and hardware addresses of both the client and the DNS server/router. From ARP alone, we can determine the network topology — specifically that the DNS server is on the same local network as the client, since ARP is non-routable. The OUI portion of the hardware address also indicates the manufacturer of each device.
Q6

What can we learn just from the first two ARP packets?

Your Answer
Model Answer
The DNS query/response pair shows how name resolution works before any HTTP connection is made. The client sends a query to its local DNS server asking for the IP address of maps.google.com, and the response returns a CNAME record plus multiple A records. The presence of multiple IP addresses indicates Google uses load balancing or anycast, giving clients multiple connection options.
Q7

Examine packets 3 and 4 (DNS query/response). How many address records are provided in the DNS response?

Your Answer
Model Answer
The client sends the TCP SYN to the router's MAC address but uses the remote IP address of maps.google.com as the destination IP. This demonstrates how routing works at the packet level: the MAC header targets the local gateway while the IP header targets the final destination, and routers swap out MAC headers at each hop while keeping the IP header intact.
Q8

Examine the TCP connection in packets 5, 6 and 7. What dynamic source port is the client using?

Your Answer
Model Answer
The HTTP GET request is the client's way of requesting the root page from the server. The server responds with an ACK first (acknowledging receipt of the GET), then sends the actual page data in subsequent packets. This separation between the transport-layer acknowledgment and the application-layer response illustrates TCP's reliable delivery mechanism.
