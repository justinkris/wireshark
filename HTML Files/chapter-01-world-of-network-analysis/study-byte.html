gen-googlemaps.pcapng 4 questions

Download the trace files available in the Download section of the book website, www.wiresharkbook.com. There are many trace files and other book supplement files available on the book website. Consider copying them all to your drive now.

In Wireshark, open gen-googlemaps.pcapng. This trace file contains the traffic from a web browsing session to maps.google.com.

Our client is 192.168.0.106. Our default gateway, 192.168.0.1, offers DNS services as well.

Answer the following questions about this trace file.

Q1

What is the hardware address of the client that is browsing to maps.google.com?

Your Answer
Model Answer
The client hardware address is AsustekC_b0:30:23 (full form: 00:17:31:b0:30:23). It appears in packets 1 and 2 (ARP request/reply). In packet 1, the ARP request Source field shows the client sending from this address. Wireshark resolves the first 3 bytes (OUI = 00:17:31) to AsustekC, identifying the network adapter manufacturer as ASUSTek. You can also see it inside the ARP packet itself in the Packet Details pane under “Sender MAC address.”
Q2

What is the IP address of the DNS server (which is also the router)?

Your Answer
Model Answer
The DNS server IP is 192.168.0.1. This is visible in packet 1 (ARP request target IP = 192.168.0.1) and confirmed in packet 3 (DNS query Destination IP = 192.168.0.1). Since the DNS server is the default gateway on this /24 network, it also acts as the router for traffic leaving the local segment. ARP is used to discover its hardware address before the DNS query can be sent.
Q3

What is the hardware address of the DNS server/router?

Your Answer
Model Answer
The DNS server/router hardware address appears in packet 2 (ARP reply) where the router responds with its MAC address as the ARP Sender MAC. The Packet List pane shows it in the Destination column of packet 1 and the Source column of packet 2, displayed in OUI-resolved form (the first 3 bytes identify the manufacturer). Look inside the Ethernet II header of packet 3 — the Destination hardware address matches the router’s MAC that was learned from the ARP exchange.
Q4

What IP addresses are associated with maps.google.com?

Your Answer
Model Answer
The DNS response (packet 4) returns 7 records: one CNAME record indicating that maps.google.com’s canonical name is maps.l.google.com, and six A records with IPv4 addresses. The first address listed is 74.125.19.147. The presence of multiple A records indicates Google uses load balancing or anycast — the client will connect to whichever IP it picks first (typically the first one). Expand the Answers section in the DNS response in Packet Details to see all six addresses.

gen-googlemaps.pcapng

This trace file depicts a simple web browsing session to www.google.com. The client performed an ARP query to get the hardware address of the DNS server and then sent a query to that DNS server to resolve the IP address for www.google.com. After receiving a successful response, the client makes a TCP connection to the server on port 80 and requests to GET the main page. The page is downloaded successfully.

icmp-ping-basic.pcapng

This is the simplest of all ping operations — it begins with the DNS resolution process for the target name and continues to an IPv4 Echo Request followed by an ICMP Echo Reply. Refer to Chapter 18: Analyze ICMP Traffic.

sec-nessus.pcapng

Nessus (www.nessus.org), the penetration testing tool, doesn’t try to be sneaky. Use the Find feature to search for the string ‘nessus’ in this trace file (do not search case sensitive). You’ll find the ‘nessus’ signature all over in this trace file. In addition, you’ll see the unusual ping packet (packet 3) used by Xprobe2 when the Nessus scan runs. Refer to Chapter 32: Analyze Suspect Traffic.

telnet.pcapng

Someone makes a telnet connection to a Cisco router to run the ‘show version’ command which is echoed back, as is the exit command. The password, however, is not echoed back. Follow the DO, DON’T, WILL and WON’T command as the client and server negotiate the connection behavior. Refer to Chapter 20: Analyze TCP Traffic.

This trace shows an X11 communication on a VLAN. You can see the VLAN tag directly after the Ethernet header and before the IP header. Refer to Chapter 3: Capture Traffic.

Review Questions
These are the official WCNA exam-style review questions from the end of Chapter 1. Write your answer before revealing the model answer.
Q1.1

What is the purpose of network analysis?

Your Answer
Model Answer
Network analysis offers an insight into network communications to identify performance problems, locate security breaches, analyze application behavior, and perform capacity planning.
Q1.2

Name at least three troubleshooting tasks that can be performed using network analysis.

Your Answer
Model Answer
Any three of the following: (1) Locate faulty network devices, (2) Measure high delays along a path, (3) Locate the point of packet loss, (4) Identify device or software misconfigurations, (5) Identify network errors and service refusals, (6) Graph queuing delays, (7) Identify asynchronous traffic prioritization.
Q1.3

Why is network analysis considered a security risk by some companies?

Your Answer
Model Answer
Some companies consider network analysis to be a security risk because it involves tapping into network traffic and eavesdropping on communications. These companies fear that unencrypted information (data, email, etc.) may be seen by the network analyst. In reality, however, the network analyst can identify unsecure network communications to prevent unauthorized eavesdroppers from gaining insight into confidential communications.
