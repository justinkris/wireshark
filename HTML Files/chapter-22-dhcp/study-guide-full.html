💭THINK FIRST · DHCP BASICS

DHCP provides dynamic IP address and configuration assignment over UDP. The DORA sequence (Discover-Offer-Request-Acknowledge) happens when a client boots outside its lease. If inside the lease, only Request-Acknowledge is used. Clients remember their last IP address — dynamic IP assignment is less dynamic than it sounds.

  • If a DHCP server is on a different subnet from the client, how can the DHCP Discover broadcast reach it? What device must be present?
  • When a DHCP client sends a Decline, what condition caused it, and what happens next?

Model Answer 1: DHCP Discover is a broadcast (destination 255.255.255.255), which routers do not forward. A DHCP Relay Agent (typically configured on a router or Layer 3 switch) must be present on the client's local segment. The relay agent intercepts the broadcast, converts it to a unicast packet addressed to the remote DHCP server, and forwards it. The server's response is sent unicast to the relay agent, which then forwards it to the client. The relay agent's IP address appears in the DHCP packet's Relay Agent IP Address field.

Model Answer 2: A DHCP Decline is sent when the client discovers the offered IP address is already in use by another host. This is detected through a gratuitous ARP (or ping) — the client sends an ARP/ping for the offered address and receives a reply from another host. After declining, the client must restart the DORA process and request a different address. The DHCP server should exclude the conflicting address or investigate the conflict. Common cause: a host with a statically-assigned IP in the DHCP server's dynamic pool.

The Purpose of DHCP

DHCP enables clients to obtain their IP addresses and configuration information in a dynamic manner. Based on BOOTP, DHCP is the standard for address/configuration assignments over UDP ports 67 (server) and 68 (client). The current definition for DHCPv4 is RFC 2131.

DHCP Message Types

TypeNameDescription
1DiscoverClient broadcast to locate available DHCP servers (src: 0.0.0.0, dst: 255.255.255.255)
2OfferServer to client in response to Discover, offering IP and configuration parameters
3RequestClient to server: (a) requesting offered parameters, (b) confirming address after reboot, or (c) extending lease
4DeclineClient to server: offered address is not acceptable (already in use, discovered via gratuitous ARP)
5AcknowledgmentServer to client: configuration parameters confirmed
6Negative AcknowledgmentServer to client: address is incorrect or lease expired
7ReleaseClient relinquishes network address and cancels remaining lease
8InformationalClient requesting only configuration parameters; already has an externally configured IP address

DHCP Relay Agents

Since DHCP relies on broadcasts for the initial Discover, either the DHCP server or a DHCP Relay Agent must be on the same network segment as the client. DHCP Relay Agents forward messages between DHCP clients and DHCP servers on different networks. The relay agent's IP address is listed in the DHCP Request's Relay Agent IP Address field.

CAUTION: Don't Use Capture Filters for Boot Process Analysis If you use a capture filter for only DHCP traffic (port 67 or 68), you'll miss the gratuitous ARP or ping that the client uses to test for duplicate IP addresses. Use display filters instead so you can see the full context when a client sends a Decline.

💭THINK FIRST · DHCP LEASE LIFECYCLE

A DHCP lease has three time values: Lease Time (LT), Renewal Time T1 (50% of LT), and Rebind Time T2 (87.5% of LT). At T1 the client sends a unicast renewal. At T2 it broadcasts. If LT expires with no acknowledgment, the client returns to the uninitialized state.

  • A DHCP client entered the rebinding phase. What exactly happened between T1 and T2 that caused this?

Model Answer: Between T1 and T2, the client attempted to unicast-renew its lease to its specific DHCP server (at T1 = 50% of lease time). The client retried the renewal at intervals equal to one-half of the remaining time until T2 approached with a minimum of 60 seconds between retries. The DHCP server never responded to any of these unicast requests — perhaps it was offline or the unicast path was broken. At T2 (87.5% of lease time), the client escalates by broadcasting a DHCP Request to any available DHCP server, attempting to get any server to extend its lease.

DHCP Lease Lifecycle

When a DHCP client successfully receives and acknowledges an IP address, it enters the "bound" state. The client receives three time values:

TimerValueAction at Expiry
Lease Time (LT)100% — full lease durationIf expired with no ACK: release IP, return to uninitialized state, broadcast Discover
Renewal Time (T1)50% of LTClient enters renewal state — sends unicast DHCP Request to its specific server
Rebind Time (T2)87.5% of LTIf T1 renewal failed: client sends broadcast DHCP Request to any available server

At T1: client retries unicast renewal at intervals = ½ remaining time until T2 (minimum 60 seconds). At T2: client retries broadcast at intervals = ½ remaining time until LT expires.

Most DHCP clients use a "sticky IP address" — they remember the last assigned IP and explicitly request it again in the Discover or Request packet. This makes dynamic addressing less dynamic than it sounds.

💭THINK FIRST · DHCPv6

DHCPv6 operates over UDP ports 546 (client) and 547 (server). Since IPv6 has no broadcast, clients use the multicast address ff02::1:2 to reach DHCP servers and relay agents. The basic exchange is Solicit-Advertise-Request-Reply (SARR) instead of DORA.

  • DHCPv4 has a BOOTP legacy with message type 1=request, 2=reply. DHCPv6 has 13 message types. What scenarios require more than the basic SARR sequence?

Model Answer: Additional DHCPv6 message types beyond basic SARR are needed for: Confirm (client changed networks, checking if addresses are still valid), Renew (at T1 — unicast to extend lease), Rebind (at T2 — broadcast if Renew failed), Decline (offered address already in use), Release (client voluntarily releases address), Reconfigure (server pushes new parameters to client), and Information-Request (client wants other parameters like DNS but not an IP address — used in stateless DHCPv6 mode with SLAAC). Relay-Forward and Relay-Reply handle the relay agent layer.

An Introduction to DHCPv6

DHCPv6 is defined in RFC 3315. Since IPv6 does not use broadcasts, DHCPv6 clients use the multicast address ff02::1:2 (All DHCP Relay Agents and Servers). DHCPv6 client port = 546, server port = 547.

Basic DHCPv6 exchange (analogous to DORA):

DHCPv4DHCPv6Direction
DiscoverSolicitClient → ff02::1:2 multicast
OfferAdvertiseServer → Client
RequestRequestClient → Server
AcknowledgeReplyServer → Client

DHCPv6 has 13 message types. Key additional types: Confirm (4), Renew (5), Rebind (6), Decline (9), Release (8), Reconfigure (10), Information-Request (11), Relay-Forward (12), Relay-Reply (13).

TIP The BOOTP-DHCP Statistics window (Statistics | BOOTP-DHCP) summarizes DHCPv4 message types in the trace file. As of Wireshark 1.7.2 this feature does not support DHCPv6.

MENTAL NOTE

Case Studies

Case Study 1
Declining Clients
Submitted by: Laura Chappell

A customer hit a problem where suddenly a number of hosts could not communicate on the Internet — a quick look confirmed they had no IP address assigned.

We launched Wireshark with a capture filter for all DHCP traffic (port 67 or port 68). The trace file showed clients booting up, sending a DHCP Discover and receiving an offer. The client then sent the Request and received an ACK — so far so good. Then, approximately one second later, the client sent a Decline to the DHCP server.

We couldn't figure out why — because we had used a capture filter. We had totally missed the problem.

When we took the trace again without a capture filter, we saw the client perform a ping to the offered address (192.168.0.104) immediately after being offered it. The ping was answered by a printer. The printer had been configured with a static IP address of 192.168.0.104, and the DHCP server wasn't checking for duplicate addresses before offering it.

The IT staff reconfigured the DHCP server with static entries for the printers to exclude those addresses from the dynamic pool. The lesson: never use capture filters when troubleshooting the boot-up process.

TL;DR — Chapter Summary

DHCP can be used to provide more configuration settings than just the client IP address. When a client boots up outside of its lease time, we see the four-packet DORA process. When a client is inside its lease time, we see a two-packet Request-Acknowledge process. Clients can request their last used IP address in DHCP Discover or Request packets.

Packets sent from IP address 0.0.0.0 are typically DHCP Discover packets — the sender does not have an IP address. If a DHCP server is not on the local network, a DHCP relay agent is required. DHCPv4 is based on BOOTP (display filter: bootp); DHCPv6 is not (display filter: dhcpv6). DHCP uses ports 67/68; DHCPv6 uses 546/547.

Review Questions

Q22.1 What is the purpose of DHCP?
A22.1 DHCP enables clients to obtain their IP addresses and configuration information in a dynamic manner. Based on BOOTP, DHCP is the standard for address/configuration assignments.
Q22.2 What is the DHCP traffic sequence when a DHCP client boots up outside of its lease time?
A22.2 When a DHCP client is outside of its lease time, the startup traffic sequence is Discover → Offer → Request → Acknowledge (DORA).
Q22.3 What is the purpose of a DHCP Decline packet?
A22.3 This DHCP packet is sent from a DHCP client to the DHCP server to indicate that the offered network address is already in use by another host (detected via a gratuitous ARP or ping test).
Q22.4 Why would a DHCP client enter the rebinding phase?
A22.4 A DHCP client enters the rebinding phase when the renewal process (unicast to the original DHCP server at T1) is unsuccessful. In the rebinding state, the client sends a broadcast DHCP Request to extend its lease with any available server.
Q22.5 What is the syntax for capture and display filters for DHCP traffic?
A22.5 DHCPv4: Capture filter = port 67; Display filter = bootp. DHCPv6: Capture filter = port 546; Display filter = dhcpv6.
Q22.6 What is the IPv6 destination address used for DHCPv6 Solicit messages?
A22.6 DHCPv6 Solicit messages are sent to ff02::1:2 (All DHCP Relay Agents and Servers multicast address).
