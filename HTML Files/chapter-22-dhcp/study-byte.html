Chapter 22 covers DHCP (Dynamic Host Configuration Protocol) — the four-way DORA handshake (Discover, Offer, Request, Acknowledge) that assigns IP addresses. You'll analyze DHCP leases, option fields, and common DHCP problems like address exhaustion and rogue servers.

Guided Analysis — DHCP DORA
Concept — Q1

Describe the four-step DHCP DORA handshake. What is the source and destination IP of the initial Discover packet, and why?

Your Answer
Model Answer
D=Discover: Client broadcasts from 0.0.0.0 to 255.255.255.255 (no IP yet). O=Offer: Server unicasts/broadcasts an offer with a proposed IP. R=Request: Client broadcasts a Request (still no IP confirmed) — broadcasting lets other DHCP servers know which offer was accepted. A=Acknowledge: Server unicasts the final ACK confirming the IP lease. The initial broadcast is necessary because the client has no IP address.
Concept — Q2

What display filter isolates only DHCP traffic in Wireshark? What is the difference between using dhcp and bootp as a filter?

Your Answer
Model Answer
dhcp is the modern Wireshark dissector filter for DHCP. bootp was the older filter name (DHCP is built on top of BOOTP). Both typically match the same traffic in current Wireshark versions. Alternatively, filter by port: udp.port == 67 || udp.port == 68. Port 67 is the server port; port 68 is the client port.
Concept — Q3

What DHCP option indicates the lease time? What DHCP option carries the DNS server address? How would you filter for a specific DHCP message type (e.g., only ACKs)?

Your Answer
Model Answer
Option 51 = IP Address Lease Time. Option 6 = Domain Name Server(s). Option 53 = DHCP Message Type (1=Discover, 2=Offer, 3=Request, 5=ACK, 6=NAK). Filter for only ACKs: dhcp.option.dhcp == 5. Filter for NAKs (address refused): dhcp.option.dhcp == 6 — NAKs indicate the server is rejecting the client's request, often due to stale lease data.

Review Questions
Official review questions from Chapter 22. Write your answer before revealing the model answer.
Review Q22.1

What is the DHCP DORA sequence and what port does each packet use?

Your Answer
Model Answer
Discover (client→broadcast, port 68→67), Offer (server→client, port 67→68), Request (client→broadcast, port 68→67), Acknowledge (server→client, port 67→68). Key point: port 67 is always the server-side port; 68 is always the client side. The Transaction ID (xid) links all four packets of a DORA exchange.
Review Q22.2

How can you identify a rogue DHCP server in a Wireshark trace?

Your Answer
Model Answer
Filter for DHCP Offer packets: dhcp.option.dhcp == 2. If you see Offer packets from more than one source MAC/IP address in response to a single Discover, there is a rogue DHCP server. The legitimate server IP is typically the known gateway IP. Compare the 'Server Identifier' (option 54) across Offer packets to spot the unauthorized server.
Review Q22.3

What does a DHCP NAK indicate, and what filter shows only NAK packets?

Your Answer
Model Answer
A DHCP NAK (Negative Acknowledgment, message type 6) tells the client its requested IP address is invalid — either the lease expired, the client moved to a new subnet, or there is an address conflict. The client must restart the DORA process. Filter: dhcp.option.dhcp == 6. Frequent NAKs can indicate a misconfigured client or a client that moved subnets without releasing its old lease.
