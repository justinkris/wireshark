💭 THINK FIRST · IPv4 HEADER & FRAGMENTATION

IP is connectionless and unreliable — it makes its best effort to deliver packets but provides no acknowledgment. When a packet is too large for a link, IP can fragment it. The Don't Fragment bit controls whether fragmentation is allowed, and all fragments share the same IP ID value for reassembly at the destination.

  • What creates a "black hole" at the network layer, and why does blocking ICMP Type 3 Code 4 packets cause it?
  • You see multiple packets with identical IP ID field values that are NOT fragments (More Fragments = 0, Fragment Offset = 0). What does this suggest about the network?

Model Answer 1: A black hole occurs when a packet with the Don't Fragment (DF) bit set is too large to be forwarded onto the next link. The router should send an ICMP Type 3, Code 4 (Destination Unreachable/Fragmentation Needed but DF bit set) message back to the source, telling it the maximum MTU. If a firewall blocks that ICMP message, the source never learns about the MTU limitation, keeps sending the same oversized packet, and the connection silently hangs — hence "black hole." Proper MTU Path Discovery requires these ICMP messages to reach the sender.

Model Answer 2: If non-fragmented packets share the same IP ID value, the packet may be looping the network — the same packet is cycling through a routing loop and arriving at the capture point multiple times. Each new packet generated by a host gets a unique ID; if the ID is identical, it's the same packet. Contrast this with fragments: all fragments of a single original packet intentionally share one IP ID so the destination can reassemble them.

IPv4 — Purpose, Structure & Problems

IP (IPv4/IPv6) provides the datagram delivery services for networked systems as well as fragmentation and reassembly for low-MTU networks. IP also offers quality of service designation via the Differentiated Services field. IP is connectionless and unreliable — it provides best-effort delivery with no guarantee of arrival. The IPv4 header is typically 20 bytes long.

Fragmentation

As IPv4 packets are forwarded by routers, the MTU size is checked against the next link. If a packet is too large and fragmentation is allowed, the router splits it into smaller fragments, sets the fragment offset, and forwards them. All fragments use the same IP ID value. Fragmentation reassembly occurs at the endpoint.

📷Figure 201 — open trace file to view
Figure 201. IP can fragment packets when a link's MTU doesn't support the datagram size.
CAUTION: Black Hole Detection When the Don't Fragment bit is set and a packet is too large to forward, the router must drop the packet and send an ICMP Type 3, Code 4 message back to the source. If these ICMP messages are blocked by a firewall, the source never learns about the MTU limitation and cannot communicate with the target — a "black hole." Filter: icmp.type==3 && icmp.code==4

Unusual IP Addresses

Invalid source addresses can be detected in Wireshark. The source IP address field cannot contain a loopback address (127.0.0.0/8), a multicast address, or a broadcast address.

Differentiated Services / DSCP

The 6-bit DSCP value determines how a router handles the packet (the per-hop behavior). Expedited Forwarding (EF) provides low loss, low latency, low jitter — a virtual leased line. Assured Forwarding (AF) provides different levels of forwarding assurance.

📷Figure 204 — open trace file to view
Figure 204. This Differentiated Services Codepoint (DSCP) field defines Assured Forwarding for a packet [voip-extension.pcapng].

TTL — Time to Live

Typical starting TTL values are 32, 60, 64, and 128. Each router decrements the TTL by 1. If a router receives a packet with TTL=1, it must discard the packet (cannot decrement to 0 and forward) and may generate an ICMP Type 11, Code 0 (Time Exceeded, TTL Exceeded in Transit) response to the sender. A host that receives TTL=1 processes the packet normally — hosts don't route.

Wireshark has a "TTL low or unexpected" coloring rule: (!ip.dst==224.0.0.0/4 && ip.ttl < 5 && !pim) || (ip.dst==224.0.0.0/24 && ip.ttl != 1)

💭 THINK FIRST · IPv6 ADDRESSING & ADDRESS ASSIGNMENT

IPv6 uses 128-bit addresses (16 bytes), has no broadcast address (multicasts replace it), and uses ICMPv6 instead of ARP for neighbor discovery. IPv6 hosts can acquire addresses via SLAAC, stateful DHCPv6, or stateless DHCPv6 — the choice is driven by the M and O bits in the ICMPv6 Router Advertisement.

  • What happens when two routers on the same segment send conflicting ICMPv6 Router Advertisements — one with M=1 (use DHCPv6) and one with M=0 (use SLAAC)? What symptom would you see on a client?
  • 6to4 tunneling and Teredo both encapsulate IPv6 inside IPv4 to cross IPv4-only networks. What is the key difference in how they achieve this?

Model Answer 1: The client acts on the most recently received Router Advertisement. With conflicting RAs, the client will oscillate: it gets M=1 from Router A, requests an address from DHCPv6, then gets M=0 from Router B, releases the DHCPv6 address and tries SLAAC, then gets M=1 again... This creates repeated DHCPv6 request/release cycles and the client never stabilizes on an address. This is exactly what Jeff Carrell's case study (Chapter 17) describes — the fix is to ensure all routers on the segment agree on M and O flag settings.

Model Answer 2: 6to4 encapsulates IPv6 directly inside IPv4 using Protocol field value 41. It requires a globally-routable IPv4 address because it embeds the IPv4 address inside the IPv6 source address (prefix 2002::). Teredo encapsulates IPv6 inside UDP to cross NAT devices that can't handle Protocol 41 directly. Teredo uses UDP port 3544 and works through NATs. ISATAP is a third option that uses locally-assigned (public or private) IPv4 addresses.

An Introduction to IPv6 Traffic

IPv6 is still just a Layer 3 routed protocol. The Ethernet header Type field value 0x86dd indicates an IPv6 header is next. IPv6 is covered in RFC 2460. IPv6 addresses are covered in RFC 4291. Neighbor Discovery is covered in RFC 4861.

💭 THINK FIRST · IP FILTERS

IPv4 and IPv6 have separate capture and display filter syntax. Knowing these precisely lets you isolate specific traffic and detect anomalies like low-TTL packets, fragmented datagrams, or 6to4 tunneled traffic.

  • Why does ip.addr==192.168.1.103 display more packets than ip.src==192.168.1.103? Could using the wrong filter mask a problem?

Model Answer: ip.addr==x matches any packet where the address appears in either source or destination fields. ip.src==x matches only packets where x is the source. If you're checking for packets sent by 192.168.1.103 to find unusual outbound behavior, using ip.addr would also show inbound traffic from other hosts destined for 192.168.1.103, diluting your results. If you're investigating ARP spoofing or a compromised host sending to unexpected destinations, the source-only filter gives clearer evidence.

Case Studies

Case Study 1
Everyone Blamed the Router
Submitted by: Russ F.

One day we received a report of a router problem — it would periodically not respond to pings. A colleague suggested replacing the router's Ethernet NIC. Before doing that, I suggested we connect Wireshark to the same VLAN and get a network trace using no mirroring — we expected to see a broadcast storm.

The trace showed an IP multicast storm occurring at the same time the router stopped responding. We could see the IP address of one of the servers in the multicast packets. We located the server and disconnected it from the network, resolving the router issue. Further investigation revealed a misconfiguration on the server, which was easily corrected.

Without Wireshark, we would have caused a major network outage while we replaced the router NIC and then probably the router — neither of which would have resolved the problem.

Case Study 2
It's Not the Network's Problem!
Submitted by: Jennifer Keels, Coastal Bend College

Our primary data information system was experiencing connection issues with external resources. The programming department spoke with their technical support, who pointed fingers at our DNS server.

I was still new to Wireshark but knew enough that I could perform some basic troubleshooting. I set a span on the switch port to the system and captured packets.

I instantly saw the system was using an IP address from an old addressing scheme. For some reason, the system would periodically use that old IP address when sending packets.

I was able to inform technical support that they did not remove the old IP address configuration and that was why the system was having network-related issues. I really enjoyed being able to prove, once again, IT WAS NOT THE NETWORK!!

Case Study 3
IPv6 Addressing Mayhem
Submitted by: Jeff Carrell, Network Security Consultant, Network Conversions

I used Wireshark to detect a configuration error plaguing an IPv6 lab setup. A Windows 7 client on VLAN 1 was configured to use DHCP/DHCPv6. At first it was getting IPv4 and IPv6 addresses just fine, but then for some unexplained reason the client would release its IPv6 address and ask for a new one, get it, then release again.

The mystery was solved by looking at the ICMPv6 Router Advertisements. I saw two routers — an HP router and a Cisco router — both sending RAs on the same network. The HP router had M=1 and O=1 (use DHCPv6 for address and other parameters). The Cisco router had M=0 and O=0 (use SLAAC, no DHCPv6).

The client was acting on the HP router RA saying "get your IPv6 address from DHCPv6," but when the client saw a subsequent Cisco router RA saying "don't use DHCPv6," the client released its DHCPv6 address. Then it would see another HP RA, request a new address, and so on in a loop.

The fix: the Cisco router needed to set its M and O flags to 1 to match the HP router. The moral: ANY router on a network segment sending RAs needs to have the M and O bits consistent — otherwise mayhem and confusion will take over.

TL;DR — Chapter Summary

IPv4 offers connectionless routing services for packets traveling through an internetwork. In addition, IP offers the ability to fragment packets and include QoS information in the IP header's Differentiated Services Codepoint area. The Time to Live field in an IP header is decremented each time a router forwards a packet.

Each packet of a fragment set maintains the same IP ID field value. If non-fragmented packets contain the same IP ID value, the packets may be looping the network. When an IP packet does not permit fragmentation but the packet is too large to forward, it is dropped and an ICMP response should be returned indicating the maximum MTU. If the ICMP responses are blocked, a "black hole" is created.

IPv6 uses a 16-byte address. ICMPv6 is used for neighbor discovery, duplicate address detection and address assignment method definition. All routers on a segment sending ICMPv6 Router Advertisements must have consistent M and O flag settings or clients will oscillate between addressing modes.

Review Questions

Q17.1 What is the purpose of IPv4/IPv6?
A17.1 IP provides the datagram delivery services for networked systems, fragmentation and reassembly for low-MTU networks, and quality of service designation to enable certain traffic to be prioritized over other traffic.
Q17.2 Which three IPv4 header fields are used with IP fragmentation?
A17.2 The three fields are the Don't Fragment bit, the More Fragments bit, and the Fragment Offset field.
Q17.3 What should an IPv4 router do when a packet to be forwarded arrives with a TTL value of one?
A17.3 The router must discard the packet because it cannot decrement the TTL to 0 and forward the packet. The router may generate an ICMP Type 11, Code 0 (Time Exceeded, TTL Exceeded in Transit) response to the sender.
Q17.4 What is the purpose of the Differentiated Services field?
A17.4 The 6-bit Differentiated Services field (DiffServ) is used to prioritize traffic and provide a certain level of Quality of Service (QoS). The field contains a DSCP value that determines how to handle the packet — the per-hop behavior (PHB) at each router.
Q17.5 What is the syntax for capture and display filters for IPv4 and IPv6 traffic?
A17.5 IPv4: Capture filter = ip; Display filter = ip. IPv6: Capture filter = ip6; Display filter = ipv6.
Q17.6 What is the format of an IPv6 6to4 packet?
A17.6 A 6to4 packet encapsulates an IPv6 header inside an IPv4 header. The IPv4 Protocol field value is 41 to indicate an IPv6 header follows. The IPv6 source address begins with 0x2002, and the IPv4 address of the encapsulating host is embedded within the IPv6 source address.
