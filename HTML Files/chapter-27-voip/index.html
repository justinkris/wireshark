    Chapter 27: VoIP

    Chapter 27 covers VoIP (Voice over IP) — analyzing SIP signaling and RTP media streams. You'll use Wireshark's VoIP analysis tools (Telephony menu), examine jitter and packet loss impact on call quality, and reconstruct audio streams.

    Guided Analysis — voip-extension.pcapng
    Trace: voip-extension.pcapng — Q1
    Open voip-extension.pcapng. Go to Telephony > VoIP Calls. What information does this view provide? How many VoIP calls are listed?
    The VoIP Calls window shows: start/stop time, caller/callee IDs, protocol (SIP), state (COMPLETED, REJECTED, etc.), and the number of packets. It provides a high-level summary of all calls in the trace. Click 'Flow Sequence' to see the SIP signaling ladder diagram showing INVITE → 100 Trying → 180 Ringing → 200 OK → ACK → BYE → 200 OK.
    Trace: voip-extension.pcapng — Q2
    Apply filter sip. What is the SIP INVITE message, and what does the 200 OK response to an INVITE signify? What information does the SIP SDP body carry?
    SIP INVITE initiates a call — it contains the caller's SIP URI, the callee's SIP URI, and an SDP (Session Description Protocol) body describing media capabilities: codec(s) offered (G.711, G.729, etc.), RTP port, and IP address where media should be sent. The 200 OK to an INVITE means the callee accepted — it also carries an SDP answer with the callee's media parameters.
    Trace: voip-extension.pcapng — Q3
    Apply filter rtp. Select an RTP stream. What fields in the RTP header help detect jitter and packet loss? Go to Telephony > RTP > RTP Streams and examine the statistics.
    The RTP Sequence Number field detects packet loss (gaps) and reordering (out-of-order). The RTP Timestamp tracks audio timing — irregular timestamp gaps indicate jitter. In Telephony > RTP > RTP Streams, Wireshark reports: max delta (max inter-packet delay), max jitter, mean jitter, and lost packets percentage. Jitter > 50ms or loss > 1% typically degrades call quality audibly.
    Optional Traces
    voip-extension.pcapng — audio playback
    In Telephony > VoIP Calls, select a call and click 'Play Streams'. If the codec is supported (G.711/PCMU), Wireshark can decode and play back the audio. Listen for quality issues.
    voip-extension.pcapng — jitter analysis
    Go to Telephony > RTP > RTP Streams. Note the max jitter and mean jitter values. A jitter buffer of 50-150ms is typical. If max jitter exceeds the jitter buffer size, audio artifacts (pops, clicks) occur.
    voip-extension.pcapng — SIP flow
    Go to Telephony > VoIP Calls > Flow Sequence. Screenshot or draw the SIP signaling ladder. Identify: INVITE, Provisional responses (1xx), Final response (200 OK), ACK, and BYE.
    Review Questions
    Review Q27.1
    What is the difference between SIP and RTP in a VoIP call? Which carries the voice data?
    SIP (Session Initiation Protocol, port 5060) is the signaling protocol — it sets up, modifies, and tears down calls (INVITE, RINGING, OK, BYE). SIP is analogous to dialing a phone number. RTP (Real-time Transport Protocol, dynamic ports typically 16384–32767) carries the actual voice/audio payload in real time. SIP says 'let's talk'; RTP delivers the conversation.
    Review Q27.2
    What does jitter mean in the context of VoIP, and what is an acceptable jitter threshold for toll-quality voice?
    Jitter is the variation in packet arrival times — packets should arrive at constant intervals (e.g., every 20ms for G.711) but network delays cause arrival time to vary. A jitter buffer absorbs this variation. ITU G.114 recommends one-way delay under 150ms; jitter above 50ms typically causes audible quality degradation. Packet loss above 1% also produces noticeable audio dropouts.
    Review Q27.3
    How do you use Wireshark to identify the codec used in a VoIP call?
    Look at the SIP INVITE message's SDP body (expand Session Description Protocol in packet details). The 'm=' line shows the media type and port. The 'a=rtpmap:' lines list codec options: payload type 0 = PCMU (G.711 μ-law, 64kbps), payload type 8 = PCMA (G.711 A-law), payload type 18 = G.729. The answering 200 OK's SDP shows which codec was selected for the call.
