    Chapter 28: Baseline Traffic

    Chapter 28 covers the process of capturing and documenting a network baseline — normal traffic patterns that serve as a reference for detecting anomalies. You'll learn what to measure, how to document it, and how to use Wireshark statistics tools to characterize normal network behavior.

    Guided Analysis — Baselining Concepts
    Concept — Q1
    What is a network baseline, and why is it essential for network analysis and troubleshooting? What are four metrics you should capture when baselining?
    A baseline is a documented record of normal network behavior — traffic volume, protocol distribution, top talkers, error rates — captured during typical operating conditions. Without a baseline, you cannot distinguish 'normal busy' from 'abnormal congestion.' Four key metrics: (1) Bandwidth utilization (% of link capacity), (2) Protocol distribution (via Protocol Hierarchy), (3) Top talkers by IP/MAC, (4) TCP error rate (retransmissions, resets per minute).
    Concept — Q2
    Which Wireshark statistics tools are most useful for creating a baseline? Describe what each provides.
    Statistics > Protocol Hierarchy — percentage breakdown of all protocols. Statistics > Conversations — top talker pairs by bytes/packets. Statistics > Endpoints — per-IP/MAC totals. Statistics > I/O Graph — traffic volume over time with peaks and averages. Statistics > Summary — overall capture statistics (total packets, duration, average pps, average Mbps). Together these paint a complete picture of normal network behavior.
    Concept — Q3
    When should you capture a baseline, and how long should the capture run? What time of day and day of week considerations matter?
    Capture baselines during representative normal operation — typically a full business day (8+ hours) including peak hours (morning login storm, lunch traffic surge) and off-peak. Avoid capturing only during off-hours or weekends, as you'll miss authentication storms, backup traffic spikes, and peak application usage. Capture at least 3 different time periods to identify patterns. Also capture baseline for each major traffic category: user workstations, servers, WAN links.
    Optional Traces
    Any trace file
    Open any trace. Go to Statistics > Summary. Record: capture duration, total packets, average packets/sec, average Mbps. This is the starting point for any baseline document.
    Any trace file — protocol hierarchy
    Go to Statistics > Protocol Hierarchy. Record the top 5 protocols by percentage of bytes. This is the protocol distribution baseline. Compare TCP vs UDP split.
    Any trace file — top talkers
    Go to Statistics > Conversations > IPv4 tab. Sort by Bytes descending. What are the top 3 conversation pairs by volume? This identifies bandwidth consumers for baseline documentation.
    Review Questions
    Review Q28.1
    What Wireshark menu provides an overall capture summary including average throughput and total packet count?
    Statistics > Summary (or in newer Wireshark versions, Statistics > Capture File Properties). It shows: file name, packet count, capture duration, average packets per second, average Mbps, and the display filter applied (if any). This is the starting point for any baseline or report — it gives the 'big picture' numbers before diving into details.
    Review Q28.2
    What four pieces of information should be included in a network baseline document?
    (1) Capture metadata — date/time, duration, capture point/interface, network segment. (2) Traffic volume metrics — average and peak Mbps, packets per second. (3) Protocol distribution — Protocol Hierarchy percentages for top protocols. (4) Top talkers — highest-volume IP addresses and conversation pairs. Optionally: error rates (TCP retransmissions/min), broadcast percentage, and multicast traffic volume.
    Review Q28.3
    How would you use Wireshark to detect an anomaly by comparing against a baseline?
    Capture a new trace from the same vantage point and compare: Protocol Hierarchy (new protocol appearing? known protocol percentage doubled?), Conversations (new top talker not seen before?), I/O Graph (traffic spike at unusual time?), Summary (average Mbps 3× the baseline?). Any significant deviation — new protocols, new top talkers, unusual volume patterns — warrants investigation. The baseline makes 'unusual' quantifiable.
