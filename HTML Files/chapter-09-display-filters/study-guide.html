💭 THINK FIRST · DISPLAY FILTER BASICS

Display filters don't change your capture — they only change what you see. Every packet you filtered out is still there, waiting for you to clear the filter. Understanding this non-destructive nature is the foundation for confident filter use.

  • The display filter bar turns yellow while you're typing. What does this mean, and should you apply the filter?
  • You apply a display filter and the packet count drops from 10,000 to 5. You then clear the filter. How many packets are in the file now?
Q1 — YELLOW FILTER BAR
A yellow filter bar means the syntax is valid — Wireshark can parse the expression — but the filter may produce unexpected or unintended results. This often happens when you use a field that exists but in an unusual way, or when a filter is technically correct but might match more broadly than intended. You can apply it, but you should double-check that the results are what you expected. It is not a syntax error (which would show red), so Wireshark will not prevent you from applying it.
Q2 — CLEARING A DISPLAY FILTER
All 10,000 packets are still in the file. Display filters are entirely non-destructive — they hide packets from view without removing them from the capture. Clearing the filter (clicking the X button) simply removes the filter and restores the full view. This is the fundamental difference between display filters and capture filters: display filters hide; capture filters prevent packets from being saved at all.
Section 1

Display Filter Basics

Display filters are different from capture filters. They show and hide packets after they are captured. Packets that don't match the filter remain in the capture file — they're just hidden from view. Display the full capture at any time by clearing the filter.

Display filters use Wireshark's own dissector-aware syntax. You reference protocol fields by their display field names — for example, ip.addr, tcp.port, http.request.method. Wireshark knows the protocol structure and lets you filter on any field it can decode.

Filter bar color feedback: The filter bar changes color as you type to give instant feedback on your expression:

  • Green — filter syntax is valid. Press Enter or click the arrow (→) to apply.
  • Red — syntax error. Wireshark cannot parse the expression as written.
  • Yellow — syntax is valid but the filter may produce unintended matches or unusual results.

Press Enter or click the → (Apply) button to apply a filter. Click the X button to clear it and restore all packets.

Non-destructive filtering Display filters are non-destructive — they hide packets but never delete them. Clear the filter to restore the full view. This is the fundamental difference from capture filters, which prevent packets from being saved in the first place.

💭 THINK FIRST · FILTER SYNTAX AND OPERATORS

Display filter syntax maps directly onto protocol field names. Once you understand the pattern — protocol.field operator value — you can construct filters for any field Wireshark can decode, without memorizing a separate filter language.

  • What is the difference between ip.addr == 10.0.0.1 and ip.src == 10.0.0.1 or ip.dst == 10.0.0.1? Are they equivalent?
  • You want to find all packets where a specific string "login" appears anywhere in the payload. What display filter would you write?
Q1 — ip.addr VS ip.src OR ip.dst
They are effectively equivalent — ip.addr == 10.0.0.1 matches any packet where 10.0.0.1 appears as either the source or the destination IP address. Wireshark's ip.addr field is a pseudo-field that checks both source and destination. The explicit ip.src == 10.0.0.1 or ip.dst == 10.0.0.1 is more verbose but identical in matching behavior. Use ip.addr when you don't care about direction; use ip.src or ip.dst when direction matters.
Q2 — SUBSTRING SEARCH IN PAYLOAD
Use the contains operator: tcp contains "login" or more broadly frame contains "login". The contains operator searches the raw bytes of the specified field for the given string. Using frame searches the entire packet. For case-insensitive or regex matching, use the matches operator with a regex: tcp matches "(?i)login".
Section 2

Filter Syntax and Operators

Display filter syntax follows the pattern: [protocol].[field] [operator] [value]. Wireshark's field names match what you see in the Packet Details pane.

Comparison operators: == (equals), != (not equals), >, <, >=, <=, contains (string in bytes field), matches or ~ (regex match).

Logical operators: and (or &&), or (or ||), not (or !). Membership: in {val1 val2 val3} — e.g., tcp.port in {80 443 8080}.

💭 THINK FIRST · COMMON DISPLAY FILTERS BY PROTOCOL

A small set of display filters covers the vast majority of real-world analysis scenarios. Knowing the right filter for the right protocol means you spend time reading packets, not constructing expressions.

  • You want to see only NEW TCP connection attempts — no data segments, no ACK-only packets. What filter would you use?
  • Write a display filter to find all DNS queries (not responses) for the domain name "example.com".
Q1 — NEW TCP CONNECTION ATTEMPTS ONLY
tcp.flags.syn == 1 and tcp.flags.ack == 0. A TCP SYN without an ACK flag is the first packet of a new connection — the initial SYN from the client. SYN-ACK (the server's response) also has SYN set, but ACK is also set, so excluding ACK isolates only the initiating SYN packets. This filter shows every new connection attempt in the capture.
Q2 — DNS QUERIES FOR A SPECIFIC DOMAIN
dns.flags.response == 0 and dns.qry.name == "example.com". dns.flags.response == 0 filters to queries only (response bit = 0). dns.qry.name matches the queried domain name. You could also use dns.qry.name contains "example.com" to catch subdomains like www.example.com.

💭 THINK FIRST · FILTER BUTTONS AND BOOKMARKS

The fastest display filter you can write is one you don't have to write at all. Wireshark's right-click shortcuts and saved filter buttons let you build precise filters directly from packet data, eliminating typos and field name lookups.

  • What is the difference between "Apply as Filter → Selected" and "Prepare as Filter → Selected" when right-clicking a packet field?
  • You type tcp. in the filter bar and press Tab. What happens, and why is this useful?
Q1 — APPLY AS FILTER VS PREPARE AS FILTER
"Apply as Filter → Selected" immediately applies the filter to the packet list — you see the filtered results right away. "Prepare as Filter → Selected" places the filter expression into the filter bar but does not apply it yet, letting you review and edit the expression before pressing Enter to apply. Prepare is useful when you want to combine multiple right-click operations (e.g., Prepare one field, then "And Selected" on another field) to build a compound filter before applying.
Q2 — TAB AUTOCOMPLETE IN FILTER BAR
Pressing Tab (or just pausing after typing) triggers Wireshark's autocomplete, showing a dropdown list of all field names that start with the typed prefix. Typing tcp. shows every TCP sub-field: tcp.port, tcp.flags, tcp.analysis.retransmission, etc. This is invaluable because you don't need to memorize field names — you can browse the available fields as you type, then select the one you want.
Section 4

Filter Buttons and Bookmarks

Wireshark provides several tools to manage and reuse display filters efficiently:

  1. Filter Bookmarks — click the bookmark icon in the filter bar to save the current filter with a name. Saved filters appear in the dropdown for quick reuse.
  2. Filter Buttons — configurable quick-access buttons below the filter bar (Analyze → Display Filter Macros, or right-click the filter bar area). One-click filter application.
  3. Filter Expressions Dialog — Analyze → Display Filters opens a dialog for creating, naming, and managing all saved display filter expressions.
  4. Right-click shortcut — right-click any field in the Packet Details pane → "Apply as Filter" or "Prepare as Filter" to build filters from actual packet values. The fastest method for precise filtering.
  5. Auto-complete — as you type in the filter bar, Wireshark shows field name suggestions. Press Tab to cycle through completions.
Fastest filter construction method Right-click a field in Packet Details → "Apply as Filter → Selected" to instantly filter to all packets containing that exact field value. This is the fastest way to build complex, accurate filters without memorizing field names.

Save filters: bookmark icon → name it. Right-click Details field → Apply as Filter (fastest method). Autocomplete in filter bar for field names. Analyze → Display Filters = manage saved filters. Filter bar turns green=valid, red=error, yellow=unusual match.
