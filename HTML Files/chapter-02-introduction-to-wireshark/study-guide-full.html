    Wireshark Creation and Maintenance

    💡THINK FIRST · WIRESHARK CREATION & HISTORY▾

    Gerald Combs created Wireshark because commercial analyzers cost $5,000–$20,000. If an open-source capture tool (tcpdump) already existed, why build an entirely new GUI application — and what does that choice reveal about how Wireshark defines its value beyond simply capturing packets?

    HINT

    Think about the difference between capturing packets and interpreting them. A CLI tool and a GUI tool serve different audiences and answer different questions.

    MODEL ANSWER

    Wireshark adds a graphical interface and automatic dissection that makes packet contents human-readable without deep protocol knowledge. tcpdump captures and displays raw data; Wireshark dissects each layer and presents field-by-field detail. The real value is accessibility — allowing network analysts, not just developers, to inspect traffic. The community-maintained open-source model also separates tool longevity from any single company: when CACE Technologies was acquired by Riverbed in 2010, Wireshark continued unchanged.

    Wireshark is the world's most popular network analyzer. Available free as an open-source tool, it runs on a variety of platforms and offers the ideal "first responder" tool for IT professionals.

    In 1997, commercial network analyzers cost $5,000–$20,000. Gerald Combs, a technologist at a small Internet service provider, decided to create his own. Prior to writing Ethereal, Combs was using a Sniffer portable at the University of Missouri. He originally released his network analyzer as Ethereal (version 0.2.0) on July 14, 1998.

    When Gerald began working with CACE Technologies in June 2006, trademark ownership issues forced the move to the new name Wireshark. CACE Technologies was purchased by Riverbed Technology in 2010. Wireshark is maintained by an active community of ~700 credited developers worldwide, with 10–20 active at any given time.

    Obtain & License

    Download from www.wireshark.org/download.html. Wireshark is released under the GNU GPL. Available for Windows, Apple Mac OS X, Debian GNU/Linux, FreeBSD, Gentoo Linux, HP-UX, Mandriva, NetBSD, Red Hat Enterprise Linux, Ubuntu, and more.

    Wireshark contains 2,272,715 lines of code — estimated development cost of $90,367,829. Bug tracking at bugs.wireshark.org/bugzilla. Use Help | About Wireshark | Authors to see the current developer list.

    Capture Packets on Wired or Wireless Networks

    💡THINK FIRST · CAPTURE INTERFACES▾

    WinPcap, libpcap, and AirPcap are all described as link-layer interfaces — yet they are not interchangeable. What determines which one is used, and why does Wireshark need a completely separate library (the Wiretap Library) just to open saved trace files when these capture drivers already handle raw packets?

    HINT

    Capture drivers are OS-specific and hardware-specific. Opening a saved file is a fundamentally different operation from live capture — no traffic is flowing; you are reading bytes from disk.

    MODEL ANSWER

    The capture library used depends on the host OS and adapter type: libpcap for Unix/Linux/macOS, WinPcap for Windows, and AirPcap for 802.11 wireless on Windows. These drivers bypass the OS network stack to receive raw frames at the link layer. Opening a saved trace file is different — the capture driver is not involved at all. The Wiretap Library handles file format translation, allowing Wireshark to read pcap, pcap-ng, NetMon, Sniffer, and many other formats regardless of which OS originally captured the file.

    📷Figure 11 — open trace file in Wireshark to view this screen
    Figure 11. Traffic capture process showing WinPcap, AirPcap, and libpcap as link-layer interfaces

    When Wireshark is connected to a wired or wireless network, traffic is processed by either the WinPcap, AirPcap or libpcap link-layer interface.

    Libpcap

    The libpcap library is the industry standard link-layer interface for capturing traffic on *NIX hosts. Information regarding patches can be found at www.tcpdump.org.

    WinPcap

    WinPcap is the Windows port of the libpcap link-layer interface. WinPcap consists of a driver that provides low-level network access and the Windows version of the libpcap API. Visit www.winpcap.org for more information.

    AirPcap

    AirPcap is a link-layer interface and network adapter for capturing 802.11 traffic on Windows. AirPcap adapters operate in passive mode to capture WLAN data, management, and control frames. More at www.riverbed.com/us/products/cascade/airpcap.php.

    WinPcap, AirPcap, and libpcap are NOT used when opening saved trace files. Those are handled by the Wiretap Library. The capture drivers only activate during live capture.

    Open Various Trace File Types

    💡THINK FIRST · TRACE FILE TYPES▾

    The Wiretap Library lets Wireshark open dozens of trace file formats. What happens if you try to open a format it does not recognize — and more importantly, why would you ever need to open a trace file from a competing product rather than just recapturing the traffic?

    HINT

    Network analysis is often forensic work. You may inherit files from any tool your organization has ever used — and recapturing is not always possible.

    MODEL ANSWER

    If Wireshark cannot parse the format, it displays an error and fails to open the file. The Wiretap Library is critical because it abstracts format differences, enabling Wireshark to read NetMon, Sniffer, ERF, and others without format-specific code throughout the UI. Opening competitor formats matters because organizations change tools over time — a legacy Sniffer capture from five years ago may be the only trace file of a past security incident. The Wiretap Library preserves access to that forensic history even after the original software is gone.

    WinPcap, AirPcap and libpcap interfaces are not used when opening trace files. Opened trace files are processed through the Wireshark Wiretap Library.

    Understand How Wireshark Processes Packets

    💡THINK FIRST · PACKET PROCESSING▾

    Wireshark dissectors chain together — each one hands off to the next based on a type field value. If a dissector for a lower-layer protocol is disabled, what happens to all higher-layer protocols that depend on it, and what does this reveal about the nature of real protocol layering?

    HINT

    Think about what enables the HTTP dissector to activate at all. What does Wireshark need to know before it can even look at an HTTP header?

    MODEL ANSWER

    Disabling a lower-layer dissector blinds Wireshark to everything above it. For example, disabling UDP also disables DNS and DHCP because those applications run over UDP — Wireshark never reaches the application layer. Dissectors chain via protocol type indicators: the Ethernet dissector reads EtherType 0x0800 (IPv4), hands off to IP, which reads Protocol 17 (UDP), hands to UDP, which reads destination port 53 (DNS), then hands to the DNS dissector. Break any link and the chain stops. This mirrors real network layering: each layer genuinely depends on the one below.

    Trace files processed by libpcap/WinPcap/AirPcap or opened via the Wiretap Library are processed through the core engine.

    Core Engine

    The core engine is described as the "glue code that holds the other blocks together." It coordinates dissectors, plugins, display filters, and the graphical toolkit.

    Dissectors and Plugins

    Dissectors (also called decodes) decode packets to display field contents and interpreted values. When a packet arrives, Wireshark detects the frame type first, then chains through dissectors:

    Dissector Chain Example
    Ethernet (EtherType 0x0800) → IP dissector (Protocol 6) → TCP dissector (Port 80) → HTTP dissector

    There are over 105,000 possible display filters — one for virtually every protocol field Wireshark can dissect. Disabling UDP also disables DHCP and DNS because those applications depend on UDP being decoded first.

    GIMP Toolkit (GTK+)

    GTK+ is the graphical toolkit used to create the Wireshark GUI, offering cross-platform compatibility across Windows, macOS, and Linux.

    Use the Start Page & Identify the Nine GUI Elements

    💡THINK FIRST · THE GUI▾

    The Wireshark Start Page has four areas (Capture, Files, Online, Capture Help) and the main window has nine distinct GUI elements. If you were designing a training exercise for a new analyst, which single element reveals the most diagnostic information about a trace file at a glance — before selecting any packet?

    HINT

    Consider what information is visible regardless of which packet is selected. Something that gives you a health summary of the entire trace file immediately on open.

    MODEL ANSWER

    The Status Bar reveals the most at a glance: it shows the Expert Info severity level (the colored button), the current trace file path and size, total packet count, displayed packet count (when a filter is applied), marked packets, and the active profile — all without selecting a single packet. A new analyst can immediately see the highest alert level, whether a display filter is active (and how many packets it matches), and which analysis profile is loaded. The nine elements work together, but the Status Bar is the fastest single diagnostic readout.

    Navigate Wireshark's Main Menu

    💡THINK FIRST · MAIN MENU SYSTEM▾

    The Analyze menu has a Decode As feature that forces a specific dissector on traffic Wireshark would not otherwise recognize — for example, applying the IRC dissector to traffic on port 18067. When is this necessary, and what risk does it introduce if you select the wrong dissector?

    HINT

    Non-standard ports are common in security incidents and custom enterprise applications. Think about what happens to the displayed fields if the protocol assumption is wrong.

    MODEL ANSWER

    Decode As is essential when applications use non-standard ports — malware commonly avoids well-known ports to evade detection, and custom apps often run on unusual ports. Applying the correct dissector makes the traffic readable and analyzable. The risk is misidentification: if you apply the wrong dissector, Wireshark displays fields that look valid but correspond to the wrong protocol interpretation, leading to false conclusions. The setting is temporary unless saved via User Specified Decodes. The Statistics | IO Graph is one of the most powerful tools, enabling comparison of total traffic against specific display-filtered traffic (e.g., all traffic vs. TCP Duplicate ACKs).

    The Main Menu has eleven sections (cannot be hidden). Key items worth knowing:

    File Menu

    • File | File Set: work with a series of split trace files linked by Wireshark
    • File | Export: export selected packets, dissections, or objects (HTTP, SMB, DICOM, SSL)
    • File | Merge: combine trace files — use Mergecap for chronological ordering

    Edit Menu

    • Mark Packets (Ctrl+M): temporary black/white highlight — cleared when file is reopened
    • Time Reference (Ctrl+T): measure elapsed time from a specific packet
    • Time Shift (since v1.8): alter timestamps in the trace
    • Edit | Preferences: User Interface, Capture, Name Resolution, Filter Expressions, Statistics, Protocols

    View Menu

    • View | Time Display Format: most important for troubleshooting — use "Seconds Since Previous Displayed Packet" to identify large gaps
    • View | Coloring Rules: persistent per-profile; "Bad TCP" rule excludes Window Updates since v1.8

    Analyze Menu

    • Decode As: force a specific dissector on traffic using non-standard ports (temporary unless saved)
    • User Specified Decodes: save Decode As settings persistently
    • Follow TCP/UDP/SSL Stream: reassemble streams for faster interpretation
    • Expert Info: identifies unusual traffic with categorization and colorization

    Statistics Menu

    • Protocol Hierarchy: detect protocol anomalies by packet/byte percentage
    • IO Graphs: most powerful feature — compare traffic patterns with display filters
    • Conversations / Endpoints: identify most active hosts and conversations
    📷Figure 38 — open trace file in Wireshark to view this screen

    The Internals menu lists 1,100+ supported protocols. Tools | Firewall ACL Rules builds Cisco IOS, IPFirewall, Netfilter, or Windows Firewall rules directly from a selected packet source IP. Tools | Lua enables scripting to extend Wireshark functionality.

    Use the Main Toolbar for Efficiency

    💡THINK FIRST · MAIN TOOLBAR▾

    The Main Toolbar is divided into seven sections. Capture icons start/stop capture; Navigation icons include Go to Corresponding Packet. This feature links related packets — like ACKs to their data. Why is this specifically valuable for TCP analysis, and what does it save the analyst from doing manually?

    HINT

    Consider how TCP acknowledgments relate to the data packets they acknowledge, and how large a trace file can be when manually searching for a specific packet.

    MODEL ANSWER

    Go to Corresponding Packet links ACKs to their data packets and Duplicate ACKs to the original ACK. In TCP analysis, a Duplicate ACK in packet 415 that corresponds to data in packet 23 takes you instantly to the relevant context without manually searching thousands of packets. Wireshark auto-generates these links from TCP SEQ/ACK Analysis in the Packet Details pane. The Reload button (Trace and Print section) is also critical — it clears all temporary ignored packets, time references, and conversation colorizations without reopening the file from scratch.

    The Main Toolbar is separated into seven sections:

    1. Capture: List Interfaces, Capture Options, Start Capture, Stop Capture, Restart Capture
    2. Trace and Print: Open File, Save File, Close File, Reload File (clears ignored/time references), Print
    3. Navigation: Find, Go Back, Go Forward, Jump To, First Packet, Last Packet, Go to Corresponding Packet
    4. Color and Scroll: Packet Coloring (toggle), Auto Scroll (toggle — disable when dropping packets)
    5. Viewer: Zoom In, Zoom Out, Zoom 100%, Resize All Columns
    6. Filter, Color and Configuration: Capture Filter Editor, Display Filter Editor, Coloring Rules Editor, Global Preferences
    7. Help: Help Window

    Filter Toolbar

    Contains the Display Filter button, filter area with auto-complete (105,000+ possible filters), Expression button, Clear, Apply, and Save. Filter Expressions (since v1.8) save favorite filters as buttons.

    Wireless Toolbar

    For 802.11 analysis. The 802.11 Channel, Channel Offset, FCS Filter, Wireless Settings, and Decryption Keys fields require an AirPcap adapter. The toolbar is hidden by default — View | Wireless Toolbar to show it.

    Help | About Wireshark

    Use the Wireshark tab to see your version and capabilities (SMI, GeoIP, etc.). The Folders tab shows where your Personal Configuration folder, profile files, and GeoIP database live — essential for locating configuration files.

    Work Faster Using RightClick Functionality

    💡THINK FIRST · RIGHTCLICK FUNCTIONALITY▾

    Right-clicking in the Packet Details pane offers both Apply as Filter and Prepare a Filter. These sound similar but behave very differently. What is the difference, and when would you deliberately choose Prepare a Filter over the faster Apply as Filter option?

    HINT

    One immediately narrows your packet list; the other populates the filter bar without applying it. Think about when you need to modify the generated filter before running it.

    MODEL ANSWER

    Apply as Filter immediately applies the generated display filter to the trace, reducing the Packet List to matching packets. Prepare a Filter generates the syntax and places it in the filter bar without applying it — giving you the chance to modify it before running. You would use Prepare a Filter when the exact field value is just a component of a larger filter (for example, combining a source IP with a port condition using &&). Apply as Filter is faster when you are confident the single field is the exact filter you need. Apply as Column is a third option — it adds the selected field as a persistent column in the Packet List pane, useful for custom TCP analysis columns like Calculated Window Size.

    Rightclick options are available in all three main panes, with different options in each.

    Packet List Pane (right-click on a packet)

    • Apply as Filter, Prepare a Filter, Conversation Filter
    • Follow TCP/UDP/SSL Stream
    • Colorize Conversation
    • Mark Packet (toggle), Ignore Packet (toggle)
    • Set Time Reference, Time Shift
    • Edit or Add Packet Comment (requires pcap-ng format; saved in pkt_comment field)
    • Copy: Summary Text, Summary CSV, As Filter, Bytes, Printable Text Only, Hex Stream, Binary Stream

    Packet Details Pane (right-click on a field)

    • Expand All, Collapse All
    • Apply as Column: add the selected field as a persistent Packet List column
    • Apply as Filter, Prepare a Filter
    • Copy: Description, Fieldname, Value, As Filter, Bytes, Hex Stream, Binary Stream
    • Wiki Protocol Page: opens the Wireshark Wiki page for the protocol
    • Filter Field Reference: opens the display filter reference list in your browser
    • Resolve Name: temporary single-IP DNS PTR lookup (lost on file reload)
    • Protocol Preferences: quick access to per-protocol settings
    Resolve Name lets you resolve a single IP address without enabling global name resolution and flooding your DNS server with PTR queries for every IP in the trace file.

    Column Heading Right-Click

    Right-click any column heading to align, rename, hide/show, or remove it. Right-click and select Edit Column Details to change the field, occurrence, and display type.

    Know Your Key Resources

    💡THINK FIRST · KEY RESOURCES▾

    Wireshark maintains five mailing lists, a Q&A site (ask.wireshark.org), and multiple trace file repositories. If you encounter packet behavior you cannot explain, what is the most efficient path from confusion to an answer — and why does the type of question determine where you look?

    HINT

    Not every Wireshark question is actually a Wireshark question. Some are protocol questions, some are configuration questions, and some require real trace files to practice with.

    MODEL ANSWER

    The fastest path depends on the nature of the confusion. If the question is about Wireshark behavior (why is this field not decoded?), ask.wireshark.org is authoritative. If it is about protocol semantics (why does this TCP flag combination appear?), the IETF RFC (www.ietf.org) is the primary source. For trace files to practice with, wiresharkbook.com (book companion) and pcapr.net (60M+ packets from 6,500+ users) are the main repositories. The Wireshark-users mailing list is high volume — ask.wireshark.org is now preferred for community questions. Bugzilla (bugs.wireshark.org) is specifically for reporting Wireshark bugs or requesting enhancements, not protocol analysis questions.

    Wireshark Mailing Lists

    • Wireshark-users: community support (high volume) — prefer ask.wireshark.org

    Case Study 1
    Detecting Database Death
    Submitted by: Bill Bach, Goldstar Software, Inc.
    🖼️
    C2-CS1.png
    Generate this illustration and save to
    all-casestudy-pictures/C2-CS1.png
    A network analyst at a workstation peers at two trace files side by side: one from the client, one from the server. On both screens, a -1 value travels along a network cable, but the database vendor log nearby shows 0 instead. Minimal text. Flat simple cartoon style, bold outlines, bright colours.

    I was troubleshooting an application problem for a client — a simple "Database Version 6 or Higher Required" message. The database files were already in version 6 format, and the error only appeared about 1/10 of the time, sometimes on a different database file.

    After quadruple-checking all the usual suspects and enabling the database vendor's trace feature, we captured a series of events with the error. Upon digging through an 80MB trace file, we located the database request where the version number was requested. The application had provided a 0 value for one of the parameters instead of -1 (which tells the database to return the current file version). With 0 in there, no file version was returned, so the program complained.

    We complained to the vendor, who dug through their code and could find NO instances of ever passing a 0. Back to the trace file — we confirmed that 19/20 times the parameter was -1, but periodically it was 0.

    We captured traffic from the same startup process simultaneously: one trace working, one not. We watched the -1 leave the workstation in both the client trace and the server trace, but the database vendor's trace file showed 0. Indisputable proof! The vendor found a case where parameters could be overwritten with 0 in the communications module. A new communications module arrived the following week.

    What we learned:

    • You may need the application developer, backend developer, AND a networking professional for some issues
    • You may need multiple network traces (at the client AND at the server)
    • Just because a vendor provides a trace log does not mean you can rely on it
    TL;DR — Chapter 2 Summary

    Introduction to Wireshark

    From its humble beginnings as Ethereal, Wireshark has matured to a feature rich tool for analyzing wired and wireless network traffic. As long as you stay within the laws and corporate policies that regulate use of Wireshark, you can troubleshoot and secure your network more efficiently with an inside look at network communications.

    All versions of Wireshark use packet capture drivers to capture traffic on wired and wireless networks and the Wiretap Library to open various types of trace files. Wireshark supports a common interface across multiple platforms with menu-based, icon-based or rightclick functionality for trace file manipulation and interpretation.

    Review Questions

    Q2.1
    What is the purpose of WinPcap?
    HINT

    WinPcap is platform-specific. Consider what a link-layer interface does and which operating system it targets.

    ANSWER

    WinPcap is the Windows port of the libpcap link-layer interface. WinPcap consists of a driver that provides low-level network access and the Windows version of the libpcap API. It enables packet capture on Windows hosts by bypassing the Windows networking stack to access raw frames at the link layer.

    Q2.2
    What is the purpose of Wireshark's dissectors?
    HINT

    Consider what information a raw packet byte stream contains versus what Wireshark shows you in the Packet Details pane — and what has to happen in between.

    ANSWER

    Wireshark dissectors decode packets to display field contents and interpreted values. Each dissector handles one protocol and chains to the next based on type field values found in headers. An HTTP packet uses multiple dissectors chained together: Ethernet, IP, TCP, and HTTP — each handing off to the next based on a type field value in its header.

    Q2.3
    What is the purpose of the Wiretap library?
    HINT

    The Wiretap Library is not the capture driver — it activates when you open a saved file, not during live capture. Think about what problem it solves.

    ANSWER

    The Wireshark Wiretap Library enables Wireshark to read a variety of trace file formats — including formats used by Microsoft Network Monitor, Network General Sniffer, WildPackets OmniPeek, and many others. It abstracts format differences so that Wireshark can open any supported trace file regardless of which tool or OS originally captured it.
