    Chapter 31: Network Scanning

    Chapter 31 covers identifying and analyzing network scanning traffic — port scans, OS fingerprinting, vulnerability scans, and their signatures in packet traces. You'll use traces like sec-strangescan.pcapng to identify scanner behavior and apply appropriate detection filters.

    Guided Analysis — sec-strangescan.pcapng
    Trace: sec-strangescan.pcapng — Q1
    Open sec-strangescan.pcapng. Apply filter tcp.flags.syn == 1 && tcp.flags.ack == 0 to isolate SYN packets. What does a large number of SYN packets to sequential ports from a single source indicate?
    A sequential sweep of SYN packets to many ports from one source is a TCP SYN scan (half-open scan) — the classic Nmap -sS signature. The scanner sends SYN to each port: if the port is open, the target responds SYN-ACK (scanner records open); if closed, RST/ACK (closed); if no response, filtered by firewall. The scanner never completes the three-way handshake, leaving half-open connections.
    Trace: sec-strangescan.pcapng — Q2
    Apply filter tcp.flags.reset == 1 && tcp.flags.ack == 1 (RST-ACK). What do these packets indicate in the context of a port scan?
    RST-ACK from the target means the port is closed — the scanner's SYN hit an inactive port, so the target OS responded with RST to reject the connection. The ratio of SYN-ACK (open ports) to RST-ACK (closed ports) responses tells the scanner which ports are worth attacking. A high RST-ACK count relative to SYN-ACK count means most ports are closed.
    Concept — Q3
    What is an XMAS scan, and what TCP flags does it set? How does it differ from a SYN scan in terms of stealth?
    An XMAS scan sets FIN, PSH, and URG flags simultaneously (all flags 'lit up like a Christmas tree'). It's used for OS fingerprinting: RFC-compliant TCP stacks respond with RST to closed ports and with no response to open ports (open ports silently drop the malformed packet). It's stealthier than SYN scans because many older IDS signatures only look for SYN-based scans. Filter: tcp.flags == 0x029 (FIN+PSH+URG).
    Optional Traces
    sec-strangescan.pcapng
    Apply Statistics > Conversations > TCP. Sort by packet count descending. What destination port appears most frequently? What does the source IP/port pattern look like for the scanner vs. a normal client?
    sec-strangescan.pcapng — Nmap detection
    Apply the Nmap Detection coloring profile (from ch11) if available. Alternatively, filter tcp.flags.syn==1 && tcp.window_size==1024 — this specific window size is an Nmap signature. Does the scanner use window size 1024?
    Any trace — UDP scan detection
    UDP scans look different from TCP scans. Filter icmp.type==3 && icmp.code==3 (Port Unreachable). Many Port Unreachable responses to a single source indicate UDP scanning — each ICMP response means a closed UDP port.
    Review Questions
    Review Q31.1
    What is the difference between a TCP SYN scan and a TCP Connect scan? Which is stealthier?
    SYN scan (half-open): sends SYN, reads response, never completes the handshake. Stealthier because no full connection is established — many firewalls and older IDS systems only log completed connections. Connect scan: completes the full three-way handshake (SYN → SYN-ACK → ACK) then immediately closes with RST or FIN. More detectable because the OS logs a completed connection, but requires no special privileges to execute.
    Review Q31.2
    What Wireshark filter identifies an Nmap SYN scan, and what specific TCP window size does Nmap use by default?
    tcp.flags.syn==1 && tcp.flags.ack==0 && tcp.window_size==1024 — Nmap uses a window size of 1024 in its default SYN scan probes. More broadly, tcp.flags.syn==1 && tcp.flags.ack==0 finds all SYN probes; the 1024 window size narrows it to Nmap specifically. Many IDS signatures use this window size as an Nmap indicator.
    Review Q31.3
    How can you determine how many unique ports were scanned from a port scan trace?
    Go to Statistics > Conversations > TCP. Sort by destination port. Count the number of unique destination ports targeted at the scan victim's IP. Alternatively, use the filter tcp.flags.syn==1 && ip.dst==[victim-ip] and then go to Statistics > Endpoints to see the port distribution. Each unique destination port in the victim's column represents one scanned port.

    Quick Reference

    SYN Scan
    Half-open scan: SYN sent, SYN-ACK=open, RST=closed, no-reply=filtered.
    XMAS Scan
    FIN+PSH+URG flags. RST=closed port; silence=open. tcp.flags==0x029.
    Nmap Window Size
    Default SYN probe window=1024. Filter: tcp.window_size==1024.
    icmp.type==3 code==3
    Port Unreachable — closed UDP port; many = UDP scan in progress.
