Questions

Q1

Open arp-recon.pcapng. What would explain the non-sequential target IP addresses? Can you determine the subnet mask of the transmitter by the ARP target addresses?

Your Answer
Model Answer
The non-sequential target IP addresses in an ARP reconnaissance trace indicate that the scanner is not simply sweeping sequentially through the subnet. Instead, the scanner may be randomizing the scan order to evade simple detection heuristics, or it may be using a list of specific targets rather than scanning the entire subnet. From the ARP target addresses, you can infer the subnet mask the transmitter is operating under — for example, if all targets share the same first three octets, a /24 mask is likely in use.
Q2

Open icmp-routersolicitation.pcapng. How can ICMP Router Solicitation be used to alter the default gateway setting of 10.1.22.2?

Your Answer
Model Answer
ICMP Router Solicitation packets (Type 10 in ICMPv4) request that routers on the local network announce themselves with Router Advertisement packets. A malicious actor can send forged Router Advertisements in response to these solicitations, advertising a false default gateway IP address. Hosts that accept these advertisements will update their routing tables and begin sending traffic through the attacker's machine, enabling a man-in-the-middle attack.
Q3

Open icmp-traceroute-normal.pcapng. How many routers were not discovered during this traceroute operation? How would you block a router from being discovered?

Your Answer
Model Answer
Routers that do not generate ICMP Time Exceeded (Type 11, Code 0) responses — either because they are configured to suppress them or are rate-limiting ICMP — will appear as undiscovered hops (typically shown as asterisks). You can block a router from being discovered by configuring it to not generate or rate-limit ICMP Time Exceeded responses.

Q5

Open sec-nmap-ackscan.pcapng. How many different discovery processes can you detect?

Your Answer
Model Answer
The trace file depicts multiple discovery processes simultaneously: Nmap's default scan includes an ARP scan (since the target is on a local network), an ICMP ping sweep, and a TCP half-open (SYN) port scan against a predefined set of common ports. All three can be identified by their distinct packet patterns appearing in sequence.
Q6

Open sec-nmap-ipscan.pcapng. Someone is doing an IP scan. Sort the Info column to see all protocols queried.

Your Answer
Model Answer
The IP scan sends packets with unusual protocol numbers in the IP Protocol field — including values for ICMP, IGMP, TCP, UDP, EGP, IGP, and others — to determine which protocols the target supports. Closed/unsupported protocols trigger ICMP Destination Unreachable/Protocol Unreachable (Type 3, Code 2) responses. Sorting the Info column makes it easy to see all the different IP protocol numbers tested.

Q8

Open sec-nmap-robotsplus.pcapng. Apply a filter for http.request.method. What else is Nmap doing?

Your Answer
Model Answer
The Nmap Scripting Engine (NSE) is performing HTTP requests looking for a robots.txt file, which often lists directories the website owner wants to keep private from web crawlers. Attackers are interested in robots.txt because its disallowed entries often reveal sensitive paths like admin panels or internal APIs. In addition, Nmap may also be performing a version detection scan (-sV) against discovered HTTP services.

Q10

Open sec-nmap-udpscan.pcapng. What is the interesting signature in the destination MAC address field?

Your Answer
Model Answer
The interesting signature in a UDP scan's destination MAC address is that Nmap may send UDP probe packets to the broadcast MAC address (ff:ff:ff:ff:ff:ff) rather than the target's unicast MAC address. This is unusual behavior compared to normal unicast UDP traffic and can serve as a detection signature for UDP scanning activity.
Q11

Open sec-nst-osfingerprint.pcapng. Create a coloring rule for ICMP Echo packets with a non-zero code value. What is NetScanTools Pro's signature?

Your Answer
Model Answer
NetScanTools Pro uses an ICMP Echo Request with a non-zero code value (Code 1) as part of its OS fingerprinting probe. Standard ICMP Echo Requests always have Code 0 — any non-zero code is a deviation from the RFC standard and is used by certain tools as a probe to fingerprint how the target OS handles malformed ICMP packets.

Q13

Open sec-strangescan.pcapng. What is the scanner doing? What is triggering the 'TCP ACKed lost segment' expert notification?

Your Answer
Model Answer
The 'TCP ACKed lost segment' expert notification is triggered when Wireshark sees an ACK acknowledging a sequence number that it never saw transmitted — meaning the original segment was sent before Wireshark started capturing, or the segment was never sent and the ACK is based on a crafted packet structure. In a scan context using unusual flag combinations, the scanner is deliberately crafting packets with flags that don't correspond to a real ongoing connection.
