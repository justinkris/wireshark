    Chapter 25: Email

    Chapter 25 covers email protocols — SMTP for sending, POP3 and IMAP for retrieval. Like FTP, traditional email protocols transmit in clear text. You'll analyze SMTP transactions, email headers, and use Follow TCP Stream to reconstruct email messages.

    Guided Analysis — SMTP
    Concept — Q1
    SMTP uses a command-response dialogue. What port does SMTP use, and what is the sequence of SMTP commands for sending an email (from connection to message delivery)?
    SMTP uses TCP port 25 (server-to-server), port 587 (submission with STARTTLS), or port 465 (SMTPS). Command sequence: EHLO/HELO (identify sender) → MAIL FROM → RCPT TO → DATA (begin message body) → . (period on its own line = end of message) → QUIT. Each command receives a 3-digit response code: 250=OK, 354=start input, 221=closing.
    Concept — Q2
    What is the difference between POP3 and IMAP for email retrieval? Which protocol leaves email on the server?
    POP3 (port 110) downloads email to the client and typically deletes it from the server — designed for single-device access. IMAP (port 143) keeps email on the server and synchronizes state across multiple clients — perfect for accessing email from phone, laptop, and web. IMAP supports server-side folders and search; POP3 is simpler but less flexible.
    Concept — Q3
    How would you use Wireshark to extract the body of an email sent via SMTP? What would you look for in the Follow TCP Stream output?
    Apply filter smtp or tcp.port == 25, then right-click an SMTP packet > Follow > TCP Stream. In the stream, after the DATA command you'll see the raw email: headers (From, To, Subject, Date, Content-Type) followed by a blank line, then the message body. Base64-encoded attachments appear as long strings of alphanumeric characters after the MIME boundary marker.
    Optional Traces
    Any SMTP trace
    Apply smtp. Find the DATA command and the end-of-message marker (period on its own line). Use Follow TCP Stream to read the full email. Can you identify the subject line and sender from the headers?
    Any POP3 trace
    Apply pop. Follow the TCP Stream. You should see the LIST command (showing message IDs), RETR (retrieve message), and DELE (delete) commands. The +OK and -ERR responses indicate success/failure.
    Email trace — credential exposure
    SMTP authentication (AUTH LOGIN or AUTH PLAIN) sends credentials Base64-encoded. Apply smtp.auth. The credentials are trivially decodable — run the Base64 string through any decoder to reveal username and password. This is why SMTPS/STARTTLS is essential.
    Review Questions
    Review Q25.1
    What SMTP response code indicates a successful mail delivery acceptance, and what code means the server is ready to receive data?
    250 = Requested mail action okay, completed (used after EHLO, MAIL FROM, RCPT TO — each step confirmed). 354 = Start mail input; end with . (server is ready to receive the email body after DATA command). 221 = Service closing transmission channel (after QUIT). 550 = Mailbox unavailable/user unknown.
    Review Q25.2
    What Wireshark filter isolates SMTP traffic, and what filter would you use for POP3?
    SMTP: smtp or tcp.port == 25 (also check port 587 for submission: tcp.port == 587). POP3: pop or tcp.port == 110. IMAP: imap or tcp.port == 143. For all email protocols together: tcp.port == 25 || tcp.port == 110 || tcp.port == 143 || tcp.port == 587.
    Review Q25.3
    Why are traditional SMTP, POP3, and IMAP considered insecure, and what are their secure equivalents?
    All three transmit in clear text — credentials and email content are visible to anyone capturing traffic. Secure equivalents: SMTPS (port 465) or SMTP+STARTTLS (port 587) for sending; POP3S (port 995) for secure POP3; IMAPS (port 993) for secure IMAP. All use TLS to encrypt the session. In Wireshark, encrypted sessions appear as TLS handshake packets rather than readable commands.
