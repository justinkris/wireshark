💭 THINK FIRST · PACKET COMMENTS

Packet comments turn a nameless capture into documented evidence. Before sharing a trace with a colleague, annotating the key packets means they don't have to find what you already found.

  • You found the exact packet that shows a TCP RST caused by a firewall timeout. Before sharing the capture file with your team, how do you highlight that specific packet?
  • After adding packet-level comments to 15 packets, you save the file as .pcap. What happens to those comments?
Q1 — HIGHLIGHTING A SPECIFIC PACKET
Right-click the packet → Packet Comment (or Ctrl+Alt+C), then type your explanation. The comment appears in the Packet Details pane and a small annotation icon appears in the packet row. Anyone opening the file and filtering on pkt_comment will jump directly to all commented packets — no hunting required.
Q2 — SAVING AS .PCAP DISCARDS COMMENTS
Packet comments are stored in pcapng format only. Saving as legacy .pcap silently discards all packet and file comments — they are permanently lost. Always save annotated captures as .pcapng to preserve the annotations.
Section 1

Packet and Capture Comments

Wireshark supports two types of annotations that transform a raw capture into documented evidence.

  • Packet comments — attach a note to a specific packet. Right-click the packet → Packet Comment, or use Ctrl+Alt+C. The comment appears in the Packet Details pane and adds a small annotation icon to the packet row. Filter: pkt_comment
  • Capture file comment — a single global note for the whole file. Access via Statistics → Capture File Properties → File Comment, or Edit → Set/Unset Capture Comment.

Both types require pcapng format to persist. Saving as .pcap will silently discard all packet and file comments.

Collaborative analysis tip Packet comments are critical for collaborative analysis. Annotate the "smoking gun" packets before sharing a trace. Filter pkt_comment to jump directly to all annotated packets without reading every frame.
Format warning — .pcap discards comments Comments are only saved in .pcapng format. If you save as .pcap, all packet and file comments are permanently lost. Always use .pcapng for annotated captures.
🧠
MENTAL NOTE
Packet comment: right-click → Packet Comment or Ctrl+Alt+C. File comment: Statistics → Capture File Properties → File Comment. Filter: pkt_comment. Comments only saved in .pcapng (NOT .pcap). Great for collaborative analysis — annotate before sharing.

💭 THINK FIRST · SAVING CAPTURE FILES

Not all capture file formats are equal. Choosing the wrong format when saving can silently discard comments, statistics, or name resolution blocks — exactly the data you need for forensic analysis.

  • What is the primary advantage of .pcapng over .pcap format?
  • A colleague needs to open your capture in an older tool that only supports .pcap. How do you save a compatible copy while preserving the original .pcapng?
Q1 — PCAPNG VS PCAP
pcapng supports packet comments, file comments, interface statistics, name resolution blocks, and can store multiple interfaces in one file. Legacy .pcap supports none of these extras and stores only raw frames. For any modern analysis workflow, .pcapng is the correct choice.
Q2 — SAVING A LEGACY-COMPATIBLE COPY
Use File → Save As → select .pcap format for the copy sent to the colleague. Keep the original .pcapng with comments intact on your own system. Note that any packet and file comments will not appear in the .pcap copy — they exist only in your original .pcapng.
Section 2

Saving Capture Files

File → Save As allows saving the full capture or a subset. The format you choose determines what metadata is preserved.

Format options:

  • .pcapng — recommended default. Supports comments, statistics, name resolution blocks, multiple interfaces.
  • .pcap — legacy format. Compatible with most tools, but no comments, no statistics blocks.
  • .csv — spreadsheet export (decoded packet summaries).
  • .json — programmatic processing.
  • .pdml — XML detailed decode (verbose).
  • .psml — XML packet summary.

Tips: always use .pcapng for new captures. Save as .pcap only for legacy tool compatibility. Auto-save during capture: Capture Options → Output → ring buffer.

💭 THINK FIRST · EXPORTING PACKET DATA

Exporting isn't just saving — Wireshark can extract specific packet subsets, protocol-decoded fields as CSV/JSON, or even reassembled files transferred over the network. Each export type serves a different analysis or reporting need.

  • You have a 50,000-packet capture but only need to share the 200 packets matching your current display filter. What is the fastest way to create a new capture file containing only those 200 packets?
  • During a forensic investigation, you believe a file was transferred over HTTP. What Wireshark feature extracts that file?
Q1 — EXPORT SPECIFIED PACKETS WORKFLOW
Apply the display filter to show those 200 packets, then File → Export Specified Packets → check "Displayed packets only" → Save. This creates a new capture file containing only the visible packets — the original is unchanged. It's the fastest way to share a focused subset without modifying the source file.
Q2 — EXTRACTING FILES FROM HTTP
File → Export Objects → HTTP. Wireshark reassembles HTTP objects (images, HTML files, executables, documents) from the TCP stream and presents them in a dialog where you can save them individually. This is the primary technique for recovering files from HTTP captures and is a core forensic workflow.
Section 3

Export Packet Data

Wireshark offers four distinct export mechanisms, each suited to a different purpose:

  1. Export Specified Packets — File → Export Specified Packets → choose Displayed, Marked, or Range. Creates a filtered subset as a new capture file.
  2. Export Packet Dissections — File → Export Packet Dissections → As CSV / JSON / PDML / PSML / plain text. Exports decoded packet fields (what you see in the Packet List) to a structured format for reporting or scripting.
  3. Export Objects — File → Export Objects → HTTP / SMB / TFTP / IMF. Extracts and reassembles files transferred within protocol streams.
  4. Export Selected Packet Bytes — File → Export Selected Packet Bytes. Raw bytes of the currently selected packet range.
Most common export workflow File → Export Specified Packets with "Displayed packets only" is the most common export workflow — apply a display filter first, then export just those matching packets to a new capture file. The original file is always unchanged.
🧠
MENTAL NOTE
Export Specified Packets: File → Export Specified Packets → Displayed/Marked/Range. Export Dissections: CSV/JSON/XML (decoded fields). Export Objects: File → Export Objects → HTTP (file extraction). Export Bytes: raw bytes. All exports are non-destructive — original file unchanged.

💭 THINK FIRST · MARKING AND PRINTING

Marking and printing are documentation tools — they let you select the most relevant packets from a large capture and produce a focused record of what you found. In security investigations, this documented record may be required evidence.

  • You've marked 8 packets that clearly demonstrate a TCP RST storm. How do you create a PDF document showing just those 8 packets with their full protocol decodes?
  • If you close Wireshark without saving after marking packets, are the marks preserved?
Q1 — PRINT MARKED PACKETS TO PDF
File → Print → select "Marked packets only" → select "Packet details" for full protocol decodes → choose print to PDF. This produces a concise technical document containing only the 8 relevant packets with their complete decode trees — ideal for incident reports or evidence packages.
Q2 — MARKS ARE EPHEMERAL
No. Packet marks (and time references) are ephemeral — they exist only in the current session's memory and are not written to the capture file. Unlike packet comments, marks are lost when Wireshark closes. To persist markers across sessions, use packet comments (Ctrl+Alt+C) instead — those are saved in the .pcapng file.
Section 4

Marking and Printing Packets

Marking: Right-click a packet → Mark/Unmark Packet, or Ctrl+M. Marked packets appear with reversed colors (black text on white background by default). To filter to marked packets only: frame.marked == 1

Printing: File → Print → choose scope: All packets / Displayed packets / Marked packets. Format: packet summary (one line per packet) or packet details (full decode tree). Use "Print to PDF" for documentation — not necessarily a physical printer.

Recommended workflow for evidence: Mark the key packets demonstrating the problem → File → Print → Marked Packets → Packet Details → Print to PDF → submit as evidence or include in incident report.

Mark and print — instant technical document Combine marking and printing: mark the key packets demonstrating the problem → File → Print → Marked Packets → Print Details → Print to PDF. Instant concise technical document without exporting a separate capture file.
🧠
MENTAL NOTE
Mark: right-click → Mark or Ctrl+M. Filter marked: frame.marked==1. Marks are NOT saved to file (ephemeral). Print: File → Print → All/Displayed/Marked. For persistent annotations use packet comments (Ctrl+Alt+C) not marks. Print to PDF for reports and evidence documentation.
