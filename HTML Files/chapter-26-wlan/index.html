    Chapter 26: WLAN

    Chapter 26 covers 802.11 WLAN — wireless LAN traffic analysis. You'll examine management frames (Beacon, Probe, Association, Authentication), data frames, and 802.11 header fields. Wireless capture requires monitor mode and appropriate hardware.

    Guided Analysis — wlan-airplane.pcapng
    Trace: wlan-airplane.pcapng — Q1
    Open wlan-airplane.pcapng. Apply filter wlan.fc.type_subtype == 8 (Beacon frames). What information do Beacon frames carry, and how often does an AP typically transmit them?
    Beacon frames are broadcast by APs approximately every 100ms (10 per second) and carry: SSID (network name), supported rates, BSSID (AP MAC), channel, capability information (WPA/WPA2/WMM support), and timing synchronization (TSF timer). They allow clients to discover available networks without active probing.
    Trace: wlan-airplane.pcapng — Q2
    Apply filter wlan.fc.type == 0 (all management frames). What management frame subtypes do you see? Identify at least three and describe their purpose.
    Common management frame subtypes: Subtype 0 = Association Request (client requests to join AP). Subtype 1 = Association Response (AP accepts/rejects). Subtype 4 = Probe Request (client looking for APs). Subtype 5 = Probe Response (AP answering probe). Subtype 8 = Beacon (AP advertising itself). Subtype 11 = Authentication. Subtype 12 = Deauthentication.
    Trace: wlan-airplane.pcapng — Q3
    Apply filter wlan.fc.type == 2 (data frames). Are the data frames encrypted? How can you tell? What filter shows only unencrypted (clear-text) data frames?
    Encrypted data frames have the Protected Frame bit set in the Frame Control field — the payload appears as random bytes and Wireshark cannot dissect the upper-layer protocols. Filter for unencrypted data: wlan.fc.type == 2 && wlan.fc.protected == 0. If you see HTTP or other clear-text protocols in data frames, the wireless network is open (no encryption).
    Optional Traces
    wlan-airplane.pcapng
    Apply Statistics > WLAN Traffic to see a summary of all BSSIDs, SSIDs, and associated clients. Count unique APs and clients.
    wlan-airplane.pcapng — signal strength
    Check if your capture has RSSI/signal strength information in the 802.11 RadioTap header (shown before the 802.11 header in the packet details). Note the signal strength in dBm and noise floor if available.
    Any WLAN trace — 802.11 header dissection
    Select any data frame and expand the 802.11 header tree. Identify: Frame Control, Duration, Address 1 (receiver/RA), Address 2 (transmitter/TA), Address 3 (BSSID or destination), Sequence Control. Note how addresses map to source/destination/AP depending on the To-DS and From-DS bits.
    Review Questions
    Review Q26.1
    What is the difference between WLAN management frames, control frames, and data frames? Give an example of each.
    Management frames (type 0) set up and maintain connections — Beacon, Probe Request/Response, Association Request/Response, Authentication, Deauthentication. Control frames (type 1) assist in delivery — ACK, RTS, CTS, Block ACK. Data frames (type 2) carry the actual payload — data, QoS data, Null function. Filter: management=wlan.fc.type==0, control=wlan.fc.type==1, data=wlan.fc.type==2.
    Review Q26.2
    What Wireshark filter shows all Beacon frames, and what information do Beacons contain that helps with network discovery?
    wlan.fc.type_subtype == 8 or wlan.fc.type_subtype == 0x08. Beacons contain: SSID, BSSID (AP MAC), supported data rates, current channel, capability flags (privacy bit indicates WPA/WEP), and the Beacon Interval (typically 100ms TUs = 102.4ms). The SSID field is empty (null) for hidden networks — the SSID length will be 0.
    Review Q26.3
    What is a Deauthentication attack in the context of 802.11, and how would it appear in a Wireshark trace?
    A Deauthentication attack (deauth flood) sends forged Deauthentication frames (subtype 12) with the AP's MAC as the spoofed source, forcing clients to disconnect. In Wireshark: filter wlan.fc.type_subtype == 12 and look for a rapid stream of Deauth frames. If the source MAC matches the legitimate AP BSSID but the volume is far higher than normal, it's likely a spoofed deauth attack.
