Questions

Q1

Download the Chanalyzer Pro recordings from www.wiresharkbook.com (80211n 40 MHz file transfer.wsx, Lotsa Interference.wsx, Pocket Jammer.wsx, Soundalier.wsx) and open them in Chanalyzer Pro.

Your Answer
Model Answer
Chanalyzer Pro is a dedicated RF spectrum analysis application that works with Metageek Wi-Spy USB spectrum analysers. Unlike Wireshark (which captures 802.11 frames), Chanalyzer shows the raw RF energy across the 2.4 GHz or 5 GHz band over time, revealing non-802.11 interference sources. Opening the provided .wsx recordings in Chanalyzer reveals patterns like constant interference (jammers), intermittent bursts (microwave ovens, cordless phones), and normal 802.11 utilization. Spectrum analysis is an essential complement to packet analysis for diagnosing WLAN performance problems caused by RF interference.
Q2

Open wlan-ap-problem.pcapng. Create an IO Graph for the beacon traffic. Why are users having problems connecting to the WLAN at times?

Your Answer
Model Answer
Beacon frames are transmitted by the AP every 100ms (the default Beacon Interval) to announce the network's presence. Create an IO Graph filtered on wlan.fc.type_subtype==8 (Beacon frames) — a healthy AP produces a steady, regular line. Gaps in the beacon graph (periods with no beacons) indicate the AP was unreachable, overloaded, or crashed during those intervals. Clients attempting to connect during a beacon gap cannot discover or associate with the AP, explaining the intermittent connection failures users experience.
Q3

Open wlan-beacon-problem.pcapng. How does this trace file look when you graph the IO rate? What capture filter was used to capture only Beacon frames?

Your Answer
Model Answer
Apply an IO Graph filtered on Beacon frames to see whether the beacon transmission rate is steady or erratic. An irregular or bursty beacon rate indicates AP timing problems — the AP is not transmitting beacons at consistent 100ms intervals, which disrupts client power-save scheduling and association timing. The BPF (Berkeley Packet Filter) capture filter for beacon frames only: wlan[0] == 0x80 — this matches the first byte of the 802.11 Frame Control field where the type=00 (management) and subtype=1000 (beacon) bits combine to 0x80.
Q4

Open wlan-ppi.pcapng. Expand the PPI header completely. On what channel were these packets received? What was the data rate? What was the dBm antenna signal strength?

Your Answer
Model Answer
PPI (Per-Packet Information) is a pseudoheader prepended to each 802.11 frame by the capture driver, containing radio layer metadata. Expand the "PPI" section in Wireshark's Packet Details pane: the "802.11-Common" sub-section contains the Channel field (showing both frequency in MHz and channel number), the data rate (in 500 Kbps units — divide by 2 to get Mbps), and the dBm Antenna Signal (a negative number where values closer to 0 indicate stronger signal). A signal of -60 dBm or better is excellent; -80 dBm and below degrades reliability.
Q5

Open wlan-radiotap.pcapng. Expand the Radiotap header completely. On what channel were these packets received? What was the data rate? What was the dBm antenna signal strength?

Your Answer
Model Answer
Radiotap is the more widely supported alternative to PPI for radio metadata. Expand the "Radiotap Header" section in Packet Details: the "Channel frequency" field shows the channel in MHz, "Data rate" shows the link rate in Mbps, and "dBm antenna signal" shows the received signal strength as a negative dBm value. Both PPI and Radiotap carry the same types of radio metadata but use different encoding formats — Radiotap is the modern standard supported by most Linux wireless drivers, while PPI was originally developed for Solaris and some BSD systems.
Q6

Open wlan-videodownload.pcapng. Build an IO Graph. Select Statistics | WLAN to see the SSID. How many WLAN retries are in the trace file?

Your Answer
Model Answer
Build an IO Graph (Statistics > I/O Graphs) to visualize the video download throughput over time. Use Statistics > WLAN Traffic to see a table of SSIDs, BSSIDs, and packet counts — this identifies the network name (SSID) without decryption. WLAN retry frames (retransmissions at the 802.11 layer, distinct from TCP retransmissions) are frames with the Retry bit set in the Frame Control header. Filter: wlan.fc.retry == 1 and note the count — high retry rates indicate RF problems that degrade effective throughput below what the IO Graph shows as raw packet rate.
Q7

Open wlan-signalissue.pcapng. Create and apply a display filter for the PPI antenna signal value. What is the range of the antenna signals? Add this value as a custom column. Filter for traffic from 192.168.0.106—what is the range of signals? Filter for traffic from 192.168.0.1—what is the range? Can you find points where signal strength was too weak?

Your Answer
Model Answer
Filter on the PPI antenna signal field using ppi.80211-common.dbm-antsignal to see signal values — right-click the field in Packet Details and choose "Apply as Column" to add it to the Packet List. The overall signal range spans from the weakest to strongest dBm value visible across all packets. Filter for each host IP to compare their signal profiles: ip.src==192.168.0.106 vs ip.src==192.168.0.1. The host further from the AP will show weaker (more negative) and more variable signal readings. Points where signal drops below -80 dBm correlate with retries and errors.
Q8

Open wlan-wpa-Induction.pcap. Decrypt the traffic using password 'Induction' and SSID 'Coherer'. After decryption, what does this trace file contain? How could you filter on only the data packets?

Your Answer
Model Answer
Add the WPA decryption key in Edit > Preferences > Protocols > IEEE 802.11 > Decryption Keys — click Add, set Key Type to wpa-pwd, and enter Induction:Coherer (password:SSID format). Close preferences; Wireshark will re-dissect the trace. After decryption, the 802.11 data frames reveal standard TCP/IP traffic — DNS queries, HTTP connections, and other application-layer protocols become readable. To filter only 802.11 data frames (excluding management and control overhead): wlan.fc.type == 2.
