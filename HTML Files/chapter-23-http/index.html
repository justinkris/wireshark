    Chapter 23: HTTP

    Chapter 23 covers HTTP — the application-layer protocol powering web traffic. You'll analyze HTTP request/response cycles, status codes, headers, and use Follow TCP Stream to reconstruct web sessions. Key focus areas include performance analysis, HTTP/1.1 vs HTTP/2, and identifying slow web servers.

    Guided Analysis — HTTP Request/Response
    Trace: http-espn2011.pcapng — Q1
    Open http-espn2011.pcapng. Apply filter http.request to see only HTTP GET requests. What is the first URL requested? What HTTP method is used?
    The first request should be an HTTP GET to the ESPN homepage (or a specific ESPN URL). GET is the standard method for retrieving web content. Look at the 'Request URI' field in the HTTP layer to see the full URL path. The Host header tells you the target domain even when the packet capture shows only the IP.
    Trace: http-espn2011.pcapng — Q2
    Apply filter http.response.code >= 400. Do you see any error responses? What is the difference between a 404 and a 503 status code?
    404 = Not Found — the requested resource doesn't exist on the server (client error). 503 = Service Unavailable — the server is temporarily overloaded or down (server error). 4xx errors are client-side problems; 5xx errors are server-side. A 301/302 is a redirect — the server tells the client to go to a different URL.
    Concept — Q3
    Use Statistics > HTTP > Request Sequences (or Follow TCP Stream) to reconstruct a full HTTP session. What does the full HTTP response look like in the stream view? How can you identify the Content-Type?
    The Follow TCP Stream view shows the raw HTTP headers and body. The Content-Type response header (e.g., text/html, image/jpeg, application/json) identifies what type of content was returned. In the stream view, the HTTP request appears first (in one color), then the server's response headers and body follow.

    Review Questions
    Review Q23.1
    What Wireshark filter shows only HTTP GET requests? What filter shows only HTTP responses with error codes (4xx and 5xx)?
    http.request.method == "GET" or simply http.request for all requests. For error responses: http.response.code >= 400. For only server errors: http.response.code >= 500. For redirects: http.response.code >= 300 && http.response.code < 400.
    Review Q23.2
    What does 'HTTP Keep-Alive' mean, and how does it affect the number of TCP connections you see in a trace?
    HTTP/1.1 Keep-Alive (persistent connections) reuses the same TCP connection for multiple HTTP request/response pairs, reducing the overhead of repeated TCP handshakes. Without Keep-Alive (HTTP/1.0), a new TCP connection would be opened for every single HTTP request — you'd see many more SYN/FIN pairs. In a Keep-Alive trace, one TCP stream carries many sequential HTTP exchanges.
    Review Q23.3
    How do you use Wireshark to find the web server's response time (time from client request to first byte of server response)?
    Enable the 'Time' column and look for the time delta between the HTTP GET request and the subsequent HTTP 200 OK (or first response packet). Alternatively, use Statistics > HTTP > Request Sequences which shows individual request/response timing. The 'tcp.time_delta' or frame timestamp difference between request and response frames reveals server response latency.

    HTTP error responses. 4xx=client error, 5xx=server error.
