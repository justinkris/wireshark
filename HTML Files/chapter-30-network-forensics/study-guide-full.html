Network Forensics Overview

Gathering network evidence, avoiding detection, and spotting unusual traffic patterns

"If you have performed your baselines, you are more likely to be able to spot unusual traffic patterns."

MY NOTES
💭THINK FIRST · NETWORK FORENSICS▾

Network forensics is the process of examining network traffic for evidence of unusual or malicious traffic. Host forensics examines storage media; network forensics examines data communications.

  • Where should you place a Wireshark capture point if you suspect numerous hosts are communicating with a command and control (C&C) server?
  • Why is it recommended to avoid using capture filters during a network forensics investigation?
Q1: Place Wireshark close to the network egress point and filter on the IP addresses of the suspect hosts or the protocol in use. This lets you observe all outbound communications without being physically close to every compromised host.
Q2: Once traffic is filtered out using a capture filter, you cannot get access to that traffic again. A display filter can be removed to reveal all captured traffic, while a capture filter permanently excludes packets. During forensics, you cannot know in advance what evidence will be relevant.

Compare Host vs. Network Forensics

Host forensics is the process of investigating media storage elements such as internal and external hard drives. Evidence may include data files, locally-stored emails, registry settings, browsing history and more. Network forensics is the process of examining network traffic for evidence of unusual or malicious traffic. This traffic may include reconnaissance (discovery) processes, phone-home behavior, denial of service attacks, man-in-the-middle poisoning, botnet commands, etc.

Gather Evidence

Network forensic evidence may be gathered for proactive or reactive analysis. Proactive analysis techniques may require placing network capture devices at various key locations on the network and saving large volumes of traffic. An Intrusion Detection System (IDS) offers complementary capability for examining network traffic and alerting IT staff to unusual traffic patterns.

The placement of Wireshark depends on the issue being investigated. Using Wireshark to capture traffic to and from a suspect host is an example of reactive analysis. If you suspect numerous compromised hosts are communicating with command and control (C&C) servers, you may prefer to place Wireshark close to the network egress point and filter on the IP addresses of the suspect hosts or the protocol in use.

The purpose of network forensics analysis is to reduce traffic data to useful information. Capturing high quantities of traffic and distilling it into separate conversations, protocols, or time sets helps locate possible breaches.

💭THINK FIRST · AVOIDING DETECTION▾

By default, Wireshark does not transmit data on the network. However, if network name resolution is enabled, Wireshark generates DNS PTR queries for each IP address captured — making it visible.

  • How can you make Wireshark completely silent on the network during a forensics investigation?
  • What testing tool could an attacker use to detect Wireshark or other packet capture tools running on a network, and how does it work?
Q1: Disable the TCP/IP stack on the capture interface. Wireshark can still capture traffic even with the TCP/IP stack disabled — this ensures the Wireshark system is not sending any traffic on the network, making it undetectable.
Q2: Products such as NetScanTools Pro contain a Promiscuous Mode Scanner that sends ARP variations with modified MAC address fields (broadcast, multicast variants). If a host is in promiscuous mode, it may respond to ARP packets not addressed to its hardware address, revealing its presence as a capture device.

Avoid Detection

By default, Wireshark does not transmit data on the network. Other applications running on the same host as Wireshark may be communicating, however. Wireshark may be detectable if you enable network name resolution. For example, the host running Wireshark may be capturing traffic and sending DNS PTR queries for each IP address captured — besides making Wireshark visible, this traffic may overwhelm the DNS server if the capture contains a high number of IP addresses.

Some products, such as NetScanTools Pro, can perform discovery processes to identify hosts in promiscuous mode. Handle Evidence Properly

Handling of evidence should not alter or cause concern regarding its integrity. Trace files should always be stored in a secure location and chain of custody documentation should define the capture process and location, trace file control, transfer and analysis process details. IT staff should own a fireproof safe for securing magnetic media that contains evidence and follow all recommended evidence handling procedures. Local laws and regulations should be considered to preserve the integrity and admissibility of digital evidence.

💭THINK FIRST · UNUSUAL TRAFFIC PATTERNS▾

Recognizing unusual traffic requires first recognizing normal traffic — baselines are essential. Creating coloring rules for unusual patterns makes them immediately visible in the Packet List pane.

  • How would you create coloring rules to detect Nmap traffic without knowing which specific ports Nmap is scanning?
  • What does a DNS response with more than 5 answers suggest might be happening?
Q1: Nmap has unique signatures regardless of target ports: TCP SYN with window size less than 1025, ICMP Echo with 0x00 payload, TCP packets with unusual flag combinations (SYN+FIN+PSH+URG = 0x2b), TCP SYN with MSS value of 256, and Window Scale set to 10. Color these patterns to make Nmap traffic immediately visible.
Q2: DNS responses with more than 5 answers (dns.count.answers > 5) may indicate a botnet C&C server is listed — bots often receive a list of multiple IP addresses where their C&C server might be reached. This is not always a problem, but warrants closer examination.

Recognize Unusual Traffic Patterns

In order to recognize unusual traffic patterns, you must first recognize normal traffic patterns. Baselines are essential in differentiating traffic types. Using penetration testing, reconnaissance and mapping tools to generate unusual traffic enables you to correlate this type of traffic with these tools. For example, capturing an OS fingerprinting operation performed with Nmap reveals that some ICMP Echo Request packets have the code field set at 9 — the specification indicates the code field of an ICMP Echo Request packet should be 0.

Color Unusual Traffic Patterns

In order to spot unusual traffic more efficiently, consider creating coloring rules to highlight this traffic. The following table illustrates additional coloring rules that highlight unusual traffic.

FilterWhat it Detects
tcp.window_size < 65535 && tcp.flags.syn==1Small Window Size SYN (suboptimal or discovery packet)
tcp.port==6666 || tcp.port==6667 || tcp.port==6668 || tcp.port==6669Default IRC TCP ports 6666-6669 (possible bot issue)

Complementary Forensic Tools

Numerous other security tools complement the packet capture abilities of Wireshark. Fyodor (creator of Nmap) maintains a list of Top 100 Security Tools at SecTools.org. Key tools include: Nessus, Snort, Netcat, NetScanTools, Metasploit Framework, Hping2, Kismet, Tcpdump, Cain and Abel, John the Ripper, Ettercap, and Nikto.

Case Study

Case Study 1
SSL/TLS Vulnerability Studied
Submitted by: Steve Dispensa, CTO at PhoneFactor

On November 5, 2009, word spread through the IT community that the globally-deployed SSL/TLS was susceptible to man-in-the-middle attack. The vulnerability was discovered by Marsh Ray and Steve Dispensa from PhoneFactor in August of 2009.

Dispensa describes how Wireshark was used throughout the research: identifying the problem in TLS after a developer got suspicious about the way Apache handled certificate authentication, performing packet captures coupled with source code analysis, developing a working implementation of the attack, and proving the vulnerability was real by capturing the exploit code in action.

When proving the issue to vendors, packet captures proved far more effective than protocol diagrams alone. Wireshark is a great reference tool since it generally is well adapted to the actual implementations in the field, rather than the idealized behavior described in standards documents.

TL;DR — Chapter 30 Summary

Host forensics is the process of investigating the contents of electronic media such as hard drives. Network forensics is the process of investigating data communications evidence. Knowing where to capture the network traffic and how to capture the network traffic is the most important element of network forensics. Avoid using capture filters if possible — once traffic is filtered out using capture filters you cannot get access to that traffic again.

Ensure you have not enabled Wireshark network name resolution process to avoid detection. Handle your evidence with the assumption that it may be used in a legal process someday. Use proper chain of custody procedures and ensure the network traffic evidence is kept in a secure location (such as a safe).

If you have performed your baselines processes, you are more likely to be able to spot unusual traffic patterns. When you spot these unusual patterns, consider creating coloring rules to make them even more highly visible. There are numerous forensics tools that complement Wireshark — Fyodor maintains a list of Top Security Tools at SecTools.org.

Review Questions

Q30.1. What is the purpose of network forensics?
A: Network forensics is the process of examining network traffic for evidence of unusual or unacceptable traffic. This traffic may include reconnaissance (discovery) processes, phone-home behavior, denial of service attacks, man-in-the-middle poisoning, bot commands, etc.
Q30.2. What is one of the traffic patterns that can make a Wireshark system visible to others?
A: If network name resolution is enabled, Wireshark may generate a large number of DNS PTR queries to resolve IP addresses to host names.
Q30.3. Why should you capture your own traffic when doing research with reconnaissance and attack tools?
A: Capture your own traffic when doing research with these tools to identify the signatures in their traffic and create defense mechanisms to block these tools from being used successfully on your network.
Q30.4. How can you make unusual traffic easier to locate in Wireshark?
A: Consider creating coloring rules for unusual packets so you can identify them faster in the Packet List pane.
