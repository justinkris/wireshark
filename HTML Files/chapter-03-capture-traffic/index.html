Live Capture Practice Self-directed tasks

Download the practice trace files available from the Download section of the book website, www.wiresharkbook.com. Use these trace files to practice the tasks and tricks contained in this chapter.

The tasks below require your own Wireshark installation and a live network connection. Work through each task and record your observations.

Task 1

Capture web browsing traffic on your local system — learn what you can capture without port spanning or using a full-duplex tap. Select Capture | Interfaces and wait a few moments to see which interface(s) are seeing traffic. Click Start to begin capturing on one of these interfaces.

Launch your web browser and browse to www.wiresharkbook.com. After the page has loaded, select Capture | Stop or click the Stop Capture button on the Main Toolbar. Select File | Save and call your trace file wiresharkbook1.pcapng.

Task 3

If you have a wireless adapter on your system, start a capture using that WLAN interface. If you receive an error message indicating that the "capture session could not be initiated (failed to set hardware filter to promiscuous mode)", close the alert window and select Capture | Options, choose your WLAN adapter, disable (uncheck) Capture packets in promiscuous mode and click Start. Browse to www.wiresharkbook.com and then stop your capture session. Examine the traffic to see what data link header was placed on your traffic.

Task 4

If you have a switch, practice spanning a port that connects to a system configured as a testing host. To ensure your spanning works properly, use that testing system to browse to www.wiresharkbook.com. If your spanning process worked correctly you should be able to see all traffic to or from your testing host.

Task 5

Perform a remote capture test by installing WinPcap on another network host and running rpcapd -n on that host. On your local Wireshark system, open Capture | Options and select Remote in the Interfaces option. Define the IP address of the host running rpcap. Select the remote interface to capture from and begin capturing. Analyze the traffic you have captured from the remote host to verify the process worked.

My Notes
Task 6

Practice capturing your own traffic to file sets. Name your capture files testset1.pcapng and use multiple files — create the next file every 30 seconds. Use a ring buffer of 5 files and stop capturing after 10 files. Start your capture and begin browsing a number of web sites for the next 7 minutes or so. Check to determine if Wireshark automatically stopped capturing and identify your five files of the file set. Their names should begin with testset1_00006, testset1_00007, testset1_00008, testset1_00009, and testset1_00010.

Optional Traces
Practice navigating Wireshark's interface with the following trace file from www.wiresharkbook.com.
vlan-general.pcapng

This trace shows an X11 communication on a VLAN. You can see the VLAN tag directly after the Ethernet header and before the IP header. Open the trace and expand the Ethernet header fields to see the 802.1Q VLAN tag embedded in the frame. Note the VLAN ID and how Wireshark identifies and labels this encapsulation.

Review Questions
Official WCNA exam-style review questions from the end of Chapter 3. Write your answer before revealing the model answer.
Q3.1

If you connect a Wireshark host directly into a switch, what traffic can you expect to see by default?

Your Answer
Model Answer
By default, switches forward all broadcast packets, multicast packets (unless configured to block multicast forwarding), packets destined to the Wireshark host's hardware address, and packets destined to unknown hardware addresses. You will not see unicast traffic intended for other hosts unless the switch is configured for port spanning/mirroring.
Q3.2

What is the difference between monitor mode and promiscuous mode?

Your Answer
Model Answer
In monitor mode, the driver doesn't make the adapter a member of any service set. In this mode, an adapter and driver pass all packets of all SSIDs from the currently selected channel up to Wireshark — including management and control frames. Promiscuous mode enables a network card and driver to capture traffic addressed to other devices on the network, not just the local hardware address, but the adapter remains a member of the network (and is still associated with one SSID in WLAN).
Q3.3

What is the purpose of file sets?

Your Answer
Model Answer
File sets are used to create a contiguous set of trace files during a capture process. Instead of opening and navigating through one large trace file (which may be a slow process), you can create file sets and move faster among the smaller trace files. File sets also enable ring buffers, which limit the number of files saved to avoid filling up a hard drive during an unattended capture session.
