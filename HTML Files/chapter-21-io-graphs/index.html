    Chapter 21: I/O Graphs

    Chapter 21 covers Wireshark's I/O Graph tool — a graphical way to visualize traffic volume, protocol activity, and anomalies over time. You'll learn to build multi-line graphs, apply display filters per-line, and use advanced graph types (SUM, MAX, AVG) to surface performance issues.

    Guided Practice — I/O Graph Techniques
    Concept — Q1
    Open any trace file with varied traffic (e.g., http-download-good.pcapng). Open Statistics > I/O Graph. What does the Y-axis represent by default, and how do you change it to show bytes per interval instead of packets?
    By default the Y-axis shows packets per interval. To switch to bytes, change the Y-axis unit dropdown from 'Packets' to 'Bytes' (or 'Bits'). This is useful for comparing bandwidth consumption rather than just packet counts — a single large HTTP response may show as a spike in bytes but moderate in packet count.
    Concept — Q2
    How do you add a second graph line filtered to only TCP retransmissions? What does a spike in retransmissions coinciding with a dip in throughput indicate?
    Click '+ Add' to add a second line. Enter the display filter tcp.analysis.retransmission for that line and assign it a different color. A spike in retransmissions coinciding with a dip in overall throughput (line 1) indicates packet loss causing TCP to back off its congestion window — the classic signature of a congestion or link quality problem.
    Concept — Q3
    What is the purpose of the 'SUM' and 'MAX' graph types in I/O Graph's advanced settings? Give a use-case for MAX(tcp.analysis.bytes_in_flight).
    SUM adds up the values of the specified field per interval (e.g., total bytes in flight). MAX shows the peak value within each interval. MAX(tcp.analysis.bytes_in_flight) reveals the maximum number of unacknowledged bytes in a TCP stream per time bucket — a high MAX suggests the pipe is full and throughput is limited by the receiver window or congestion window, not available bandwidth.

    Graph RTP traffic (rtp) over time. You should see a very steady, constant stream of equally-spaced packets. Any gaps or bursts indicate jitter — a major VoIP quality problem.
    Review Questions
    Review Q21.1
    What is the default Y-axis metric in Wireshark's I/O Graph, and what are the other options?
    The default is Packets (packets per interval). Other options include Bytes, Bits, and SUM/MIN/MAX/AVG of a specific field value. Bits per second is useful for comparing to link capacity. Field-based aggregation (SUM, MAX, etc.) requires entering a numeric display filter field like tcp.len or tcp.analysis.bytes_in_flight.
    Review Q21.2
    How would you use I/O Graph to identify the exact second when a network problem began?
    Plot a line for all traffic and a second line for error packets (e.g., tcp.analysis.flags or icmp.type==3). Zoom in on the graph's time axis. The moment when error packets first appear and throughput drops marks the onset of the problem. Click on a point in the graph to jump to that packet in the packet list for detailed inspection.
    Review Q21.3
    What interval setting in I/O Graph is most useful for catching short-lived bursts vs. long-term trends?
    Short intervals (0.01–0.1 seconds) reveal burst behavior and micro-congestion events. Longer intervals (1–10 seconds) smooth out noise and show long-term trends. Start with 0.1 seconds to catch sub-second events; use 1 second for trend analysis over minutes. Very short intervals (1ms) can show individual frame timing but produce noisy graphs.

    Quick Reference

    I/O Graph
    Statistics > I/O Graph — visualize traffic over time with per-line filters.
    SUM / MAX graph type
    Aggregate field values per interval. MAX(tcp.analysis.bytes_in_flight) shows window pressure.
    tcp.analysis.retransmission
    Filter for a second graph line to correlate retransmissions with throughput dips.
    Interval
    Time bucket size — 0.1s for burst detection, 1s for trend analysis.
