Analyze Suspect Traffic

Identifying malformed packets, dark addresses, floods, ARP poisoning, and TCP evasion

"A strong knowledge of TCP/IP communications can help you spot protocol and application traffic that is used for breaches."

MY NOTES
💭THINK FIRST · SUSPECT TRAFFIC▾

Suspect traffic does not match network baselines — it is either out of place because of protocol type, port usage, packet frequency, requests, responses, etc. Baselines are essential for identification.

  • How does a bot-infected host commonly communicate with its command and control (C&C) server, and what network evidence would you look for?
  • Why would a malicious FTP program choose to use port 80 rather than its standard port 21?
Q1: Bot-infected hosts typically connect to C&C servers via IRC (ports 6666-6669 or nonstandard ports) or HTTP. Look for: IRC traffic on nonstandard ports (Decode As may be needed to identify it), DNS responses with many IP addresses (possible C&C list), and periodic low-volume outbound connections during idle time.
Q2: Port 80 (HTTP) is widely allowed through outbound firewalls since it carries normal web browsing traffic. A malicious FTP client using port 80 can bypass firewalls that block port 21, evading detection while still exfiltrating data.

What is "Suspect" Traffic?

Suspect traffic does not match network baselines — it is either out of place because of protocol type, port usage, packet frequency, requests, responses, etc. Suspect traffic may be normal network communications that we are not familiar with or traffic that has unusual patterns. Alternately, suspect traffic may simply be caused by poorly behaving applications, misconfigurations, innocent mistakes or faulty devices.

In order to rule out the innocent causes of suspect traffic, you need to know what is normal. This is where your baseline becomes a precious resource.

The following traffic may be considered unacceptable:

  • Maliciously malformed packets — intentionally malicious packets
  • Traffic to invalid or "dark" addresses — packets addressed to unassigned IP or MAC addresses
  • Flooding or denial of service traffic — traffic sent at a high packet per second rate
  • Clear text passwords — passwords that are visible and therefore unsecure
  • Clear text data — data that is visible or able to be reconstructed
  • Phone home traffic — periodic connections to a remote host (updates, commands)
  • Unusual protocols and applications — not commonly seen or allowed on the network
  • Route redirections — ICMP-based route redirections for man-in-the-middle attacks
  • ARP poisoning — altering target ARP tables for man-in-the-middle attacks
  • IP fragmentation and overwriting — using fragment offset to overwrite previous data
  • TCP splicing — obscuring the actual TCP data processed at the peer
  • Password cracking attempts — repeated attempts to guess account passwords

💭THINK FIRST · RESOLUTION VULNERABILITIES▾

The TCP/IP resolution process has multiple steps, each of which can be compromised: port resolution (services file), DNS resolution (cache poisoning), MAC resolution (ARP poisoning), and route resolution (route table poisoning).

  • How can a malicious application exploit the port resolution step even without modifying any system files?
  • What is the significance of a DNS response that contains a CNAME record followed by many IP addresses?
Q1: A malicious application can simply choose to communicate on a port that is allowed through the firewall (e.g., port 80 for HTTP) rather than its standard port. Applications define which ports they will use — modifying the services file only affects how Wireshark displays the port, not how the application uses it.
Q2: A CNAME record followed by many diverse IP addresses is a common technique used by botnet C&C servers to distribute their command infrastructure. The bot-infected host receives a list of IP addresses where the C&C server might be reached, making it resilient to takedowns. Filter: (dns.flags.response==1) && (dns.count.answers > 5).

Port Resolution Vulnerabilities

Port resolution relies on the integrity of the services file and the application requesting to use a particular port number. If a malicious user or program has altered the content of the services file, the port resolution process may be affected. A malicious FTP program might use port 80 knowing that many companies do not block outbound traffic to this port.

Bot-infected hosts often use Internet Relay Chat (IRC) to communicate with Command and Control (C&C) servers. In this case, the bot-infected host connects to the IRC server on port 18067 and Wireshark defines the IRC communications as simply "Data." Using the right-click | Decode As function, we can force Wireshark to temporarily dissect traffic to and from port 18067 as IRC traffic.

Name Resolution Process Vulnerabilities

If a malicious application has altered the client hosts file, the client system will use the information in that file before generating a DNS query. Unless a secure form of DNS is used to validate responses, clients accept any DNS responses as long as the transaction ID number and the restated query match the original request. If the DNS information supplied leads to an alternate host, the client continues the resolution processes to connect to the incorrect host.

In the case of bot-infected hosts, it is not uncommon to see a DNS query generate CNAME responses with many IP addresses. Creating a coloring rule to identify DNS responses that contain more than 5 IP addresses may help you spot these packets: (dns.flags.response==1) && (dns.count.answers > 5).

MAC Address and Route Resolution Vulnerabilities

When resolving the hardware address of a local target or a router, the client depends on the validity of the ARP response or entries in the local ARP cache. MAC address redirection can be used by some attackers to perpetrate a man-in-the-middle attack. When a client needs to send data to a target on a remote network, the client consults its routing tables. If the local route table has been poisoned, the client sends packets in the wrong direction — this is route redirection, used for man-in-the-middle attacks.

Route resolution: route table poisoning or ICMP redirects. Services file edit only renames port in Wireshark, does not apply dissector.

💭THINK FIRST · UNACCEPTABLE TRAFFIC PATTERNS▾

Flooding, dark address traffic, clear text passwords, phone home traffic, ARP poisoning, and IP fragmentation each have distinct signatures in Wireshark. Coloring rules make them immediately visible.

  • How can you determine whether a flood of packets is caused by a layer 2 loop versus a deliberate denial of service attack?
  • What is TCP splicing and why is it used as an evasion technique against firewalls and IDS?
Q1: If all flooding packets have the same IP ID field value, it is the same packet circulating in a layer 2 loop (Spanning Tree failure). If each packet has a different IP ID field value, each packet is separately generated — suggesting a deliberate flood attack (e.g., Macof MAC table flooding).
Q2: TCP splicing sends each byte of TCP payload in a separate packet. Because the firewall or IDS must reassemble the TCP segments to inspect the payload, splitting data across many tiny packets can confuse security devices that do not fully reassemble TCP streams before applying signatures.

Identify Unacceptable Traffic

Find Maliciously Malformed Packets

Malicious packets take advantage of vulnerabilities in protocols and/or applications. CVE-2009-3103 (SMBv2 Negotiate Protocol Request Vulnerability) pointed to packets that contained the value "&" in the Process ID High field in the SMB header. The following filter can be used alone or as a coloring rule to detect these malformed packets:

(smb.cmd==0x72) && (smb.flags.response==0) && !(smb.pid.high==0)

This filter identifies: SMB Negotiate Protocol Request (0x72) that is a request (not response) and has a non-zero value in the Process ID High field. When vulnerabilities are announced with packet details, consider creating coloring rules to highlight these packets in any trace file you open.

Identify Invalid or Dark Destination Addresses

Traffic sent to addresses that are not assigned is considered unusual. Unassigned MAC addresses are referred to as "dark MAC addresses." Unassigned IP addresses are referred to as "dark IP addresses." Traffic sent to or referencing unassigned addresses may be indications of blind discovery processes.

📷Figure 383 — open trace file to view
Figure 383. This ARP scan hits numerous dark IP addresses — not normally seen from monitoring devices, should be flagged for investigation.

Flooding and Denial of Service Traffic

Flooding can be used to saturate a network link, a TCP connection table, the buffer on a network interface card, switch tables, routing tables or other elements of a network. Macof is a tool that purposefully floods a network to overload a switch MAC address table, hoping to cause the switch to stop making forwarding decisions and forward all packets out all ports (becoming, in essence, a hub). Macof signature: TCP SYN packets with Window Size = 512 (illogical value — prefer 65535). Coloring rule: tcp.window_size==512 && tcp.flags.syn==1.

📷Figure 384 — open trace file to view
Figure 384. Macof sends packets to random MAC and IP addresses — signature: TCP SYN with Window Size 512.

Find Clear Text Passwords and Data

Some applications use clear text passwords and Wireshark can easily capture and display those passwords. These visible passwords are a security concern. To identify clear text passwords crossing the network, begin packet capture then access the host using a password. Use the Find feature to look for the string anywhere in the trace file or Follow the TCP Stream to look for the password in readable format.

📷Figure 385 — open trace file to view
Figure 385. Wireshark displays a password setting process visible in clear text in an HTTP POST operation.

Identify Phone Home Traffic

"Phone home" traffic is seen when an application periodically connects to a remote host for the purpose of updating the application, obtaining commands, etc. The most commonly seen phone home behavior is generated by virus detection programs. It is important to differentiate between acceptable phone home behavior (virus detection updates) and malicious behavior (bot-infected host processes). One method of detecting phone home traffic is to capture the traffic to and from a host that is idle.

Figure 386. Virus detection services phone home to obtain signature updates — know your normal baseline to distinguish this from malicious activity.

Catch Unusual Protocols and Applications

The Protocol Hierarchy Statistics window helps identify unusual protocols and applications in the traffic. A breached Windows host showing IRC and Trivial File Transfer Protocol (TFTP) traffic in the Protocol Hierarchy window is highly suspicious — these are not normal for a typical Windows workstation.

💭THINK FIRST · ATTACK PATTERNS▾

ARP poisoning, ICMP redirection, IP fragmentation overwriting, and TCP splicing are sophisticated attack techniques. Wireshark can detect each of them through specific field values and expert info warnings.

  • How does ARP poisoning work to enable a man-in-the-middle attack, and what Wireshark indicator reveals it?
  • What is the signature of an IP fragment override attack, and how can you detect it using a Wireshark column?
Q1: ARP poisoning sends gratuitous ARP replies to victim hosts, associating the attacker MAC address with victim IP addresses. Both hosts update their ARP caches to send traffic to the attacker. Wireshark detects this by generating a "Duplicate IP address configured" Expert Info warning when it sees conflicting ARP entries for the same IP address.
Q2: Add an ip.frag_offset column to the Packet List pane. In a normal fragmented set, the fragment offset values should increase monotonically (0, 1480, 2960, 4440...). If a later fragment has a lower offset value than a previous fragment, it is overwriting already-received data — this is IP fragmentation overwriting, a technique to bypass firewalls and IDS.

Attack Patterns: Routing, Fragmentation, and TCP Evasion

Locate Route Redirection Using ICMP

ICMP Redirect (Type 5) is sent by a gateway that knows of a better router to use. An attacker can use this redirection to intercept and forward traffic that normally would not be directed to the attacker IP address. Consider creating a special coloring rule for ICMP redirections: icmp.type==5.

📷Figure 389 — open trace file to view
Figure 389. ICMP Redirect packets indicate a better router to use to reach a host — can be used for man-in-the-middle attacks.

Catch ARP Poisoning

ARP poisoning is typically used for man-in-the-middle attacks. The attacker generates ARP packets with false information that alters the ARP tables of victim hosts. Ettercap and Cain and Abel are two tools that can be used to perform ARP poisoning. In an ARP poisoning attack, both victim hosts believe the other is at the attacker MAC address — the attacker intercepts and forwards all traffic between them.

Wireshark detects ARP poisoning by generating a "Duplicate IP address configured" Expert Info warning when it sees conflicting ARP entries for the same IP address.

Figure 390. Wireshark detects duplicate use of an IP address during ARP poisoning.

Catch IP Fragmentation and Overwriting

The IP header contains three fields that define fragmentation: May Fragment (0=may, 1=don't), More Fragments (0=last, 1=more coming), and Fragment Offset (13 bits — used to reassemble data in correct order). Fragmentation overwriting occurs when data occurring later in a fragmented set overrides previous data based on its Fragment Offset field value.

To spot fragmentation override, add an ip.frag_offset column to the Packet List pane. If the fragmentation offset value does not increment with each new fragment, the communication is suspect.

📷Figure 392 — open trace file to view
Figure 392. Wireshark lists the offset of IP fragments in the Info column — check for non-monotonic offset values.

Spot TCP Splicing

TCP splicing splits TCP segments over multiple packets — each packet may contain only one byte of data. This is easy to detect in Wireshark. An indication of splicing would be a continuous stream of small packets traveling in both directions on a TCP connection. Consider adding a tcp.len column in Wireshark to help spot these unusual packets. Right-click to reassemble these spliced packets into a single stream.

📷Figure 393 — open trace file to view
Figure 393. An FTP login sequence is sent one byte at a time — TCP splicing to evade IDS inspection.

Identify Password Cracking Attempts

Password cracking attempts can be obvious on the wire — even if the connection is encrypted. Unsuccessful attempts generate error responses which may trigger another TCP connection to be established. An unencrypted FTP password crack consists of multiple login attempts in clear text. A higher-than-normal number of error responses would be seen on the network. Coloring rule to highlight FTP password errors: ftp.response.code==530.

📷Figure 394 — open trace file to view
Figure 394. This dictionary password cracking attempt is unsuccessful so far — FTP response code 530 indicates login failure.

Build Filters and Coloring Rules from IDS Rules

In many cases you can correlate your firewall or IDS rules with Wireshark display filters or coloring rules. When vulnerabilities are openly announced, consider creating coloring rules based on the packet details released with the vulnerability to highlight these packets in any trace file you open. Visit emergingthreats.net for open source Suricata and Snort rules that can be translated into Wireshark filters.

Case Study 1
The Flooding Host
Submitted by: Martin B., Network Administrator

Martin B. (Network Administrator) fired up Wireshark after users complained about performance and found a ton of broadcasts being sent from one network host to nearly every machine on the network, all hitting port 135 — a port previously used for exploits.

Moving to the switch upstream from the flooding host, Martin found that no one was even sitting at that machine. He then found the server it was communicating with on the Internet and reassembled the TCP streams to find that it was using port 18067 to set up an IRC channel. Using the basic information found in the trace file, he did some research and found the host was bot-infected — he could identify the exact bot.

The team immediately shut down that host and began checking every system on the network. Wireshark took out all the guesswork.

Case Study 2
Catching Keylogging Traffic
Submitted by: Jim McMahon, Founder, Our Security Guy Strategic Consultants

Jim McMahon (security consultant) was scanning the network for administrative traffic flows using a product demonstration tool. While scanning ports for various traffic types, the team noticed a periodic small packet departing the network every 10 minutes AND a larger packet once every hour going to an unrelated private domain from a financial analyst account.

Investigation revealed that the stored data (poorly set up — it did not clean up after itself after sending) showed that screen shots were going out periodically and the larger packet was keystroke monitoring collection dispatched hourly. The machine was taken offline immediately.

EnCase forensic examination determined that a commercially available keylogger had been installed via a "pretty picture" Trojan horse downloaded from the jealous fiancé of the employee. The boyfriend confessed and faced legal consequences.

Case Study 3
Passively Finding Malware
Submitted by: Labnuke99

Labnuke99 used Wireshark as a malware infected host detector on a Windows network. Running on a Linux computer that was not in Active Directory or DNS, the only way any connections should be made to it would be by scanning the network or connecting directly to its IP address. The Linux host listened on ports 139 and 445.

An 11-hour time difference made real-time capture during buffer overflow events on Windows machines impractical. The next morning, the logs revealed that a culprit had tried to gain access to the Linux host on both ports 139 and 445 — revealing the infected Windows machine that was actively scanning and attempting to exploit other hosts.

The site administrator was notified about the infected computer, which was rebuilt from clean media. Wireshark is a great tool for detecting malware infected hosts.

TL;DR — Chapter 32 Summary

Suspect traffic may include unusual protocols or applications, unusually formed packets, traffic to unused addresses or suspicious targets, high traffic rates or other traffic that does not match your baselines. A strong knowledge of TCP/IP communications can help you spot protocol and application traffic that is used for breaches.

Key attack patterns: maliciously malformed packets (use protocol vulnerability details to create coloring rules), dark address traffic (unassigned IP/MAC addresses receiving traffic), flooding (check IP ID for loop vs. deliberate attack), clear text passwords (Follow TCP Stream to extract), phone home traffic (capture during idle time), ARP poisoning (Wireshark "Duplicate IP address" Expert Warning), IP fragmentation overwriting (non-monotonic frag_offset values), TCP splicing (1-byte-at-a-time data packets), and password cracking (high error response count).

Review Questions

Q32.1. What is "suspect traffic?"
A: Suspect traffic is traffic that is considered unusual on the network. For example, if a network does not typically support large numbers of connections to sites in China or TFTP communications, you might consider this suspect traffic.
Q32.2. How can name resolution vulnerabilities affect network security?
A: If the name resolution process is breached, an attacker can redirect hosts to communicate with systems other than the intended ones. For example, if an attacker has added malicious entries to a DNS server's cache, that server will provide this information to querying hosts — from the host's perspective, the redirection is transparent.
Q32.3. What is a maliciously malformed packet?
A: A maliciously malformed packet is a packet that is intentionally created to take advantage of protocol or application vulnerabilities. The 2009 SMBv2 Negotiate Protocol Request packet containing an ampersand character in the Process ID High field is an example.
Q32.4. What is a "dark" destination address?
A: A "dark" destination address is an address that falls within the network address range in use but is not currently assigned to a host.
Q32.5. What is a key signature of a packet that is looping a switched network?
A: A packet that is looping on a switched network will contain the same IP ID value. If you capture a flood of packets and all of the packets have the same IP ID value, it may be a looping packet.
Q32.6. Which Wireshark feature can help you spot unusual protocols and applications on the network?
A: Wireshark Protocol Hierarchy window helps identify unusual protocols and applications. It is imperative that you have a baseline and know what is considered "normal" network communications so you can spot these unusual protocols and applications.
Q32.7. What are two redirection processes that can facilitate man-in-the-middle attacks?
A: ARP poisoning and ICMP redirection are two redirection processes that can facilitate man-in-the-middle attacks.
Q32.8. How can you determine the complete payload of TCP splicing traffic?
A: Use TCP reassembly to view the reconstructed TCP payload when the traffic has been spliced.
