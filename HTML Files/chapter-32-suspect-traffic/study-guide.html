💭 THINK FIRST · MALWARE TRAFFIC INDICATORS

Malware traffic differs from legitimate traffic in regularity, destination diversity, and timing patterns. Legitimate user traffic is irregular (driven by human behavior); malware beaconing is mechanically regular (driven by a timer). This distinction is visible in IO Graphs and Conversations statistics.

  • You graph a specific host's outbound connections in IO Graphs and see a perfectly regular spike every exactly 30 seconds. What does this suggest and how would you investigate?
  • A host makes 200 DNS queries in one minute with 190 returning NXDOMAIN. What malware behavior is this?
Q1 — REGULAR 30-SECOND OUTBOUND SPIKES
Regular periodic outbound connections at exact intervals are the signature of malware beaconing — software on the host is "calling home" to a C2 (command and control) server on a fixed schedule. Legitimate user behavior is irregular; machines don't browse the web exactly every 30 seconds. Investigate: filter for that host's outbound TCP/UDP connections at the 30-second intervals to find the destination IP and port. Check whether it's HTTP(S), DNS, or another protocol. Look up the destination IP in threat intelligence databases. Examine the payload size — small, fixed-size payloads are consistent with C2 check-in, not user activity.
Q2 — 190/200 NXDOMAIN IN ONE MINUTE
This is DGA (Domain Generation Algorithm) malware. DGA malware generates pseudo-random domain names algorithmically and sends DNS queries for each one. The vast majority return NXDOMAIN because most generated domains don't exist — the attacker only registers a small number of them as active C2 servers at any given time. The infected host keeps querying until it finds one that resolves. 190/200 NXDOMAIN rate in one minute from one host is the textbook DGA signature. Filter: dns.flags.rcode == 3 and ip.src == [host IP] to see all NXDOMAINs from that host.
Section 1

Malware Traffic Indicators

Malware traffic has consistent behavioral signatures that appear in Wireshark regardless of the malware family or payload. The key differentiator from legitimate traffic is mechanical regularity — malware operates on timers, not human impulses.

Malware traffic patterns:

  1. Beaconing — regular periodic outbound connections to C2. Signature: exact interval timing, connections outside business hours, connections to unusual IPs or foreign geolocations.
  2. Unusual outbound ports — malware may use port 443 to blend with HTTPS but connect to non-enterprise IPs with no legitimate business purpose.
  3. Large outbound transfers at unusual hours — data exfiltration often happens overnight when traffic is lower and less monitored.
  4. DGA domains — hundreds of NXDOMAIN DNS responses from one host in rapid succession as the bot cycles through generated names.
  5. Multiple failed DNS queries — malware cycling through generated domain names to find the currently active C2 registration.
Beaconing — top malware indicator Regular periodic connections at fixed intervals (beaconing) are a top malware indicator. Legitimate user traffic is irregular. IO Graph a suspicious host's outbound traffic — if you see mechanical regularity (spikes at exact intervals), investigate immediately.
🧠
MENTAL NOTE
Malware signatures: Beaconing (regular intervals, IO Graph visible), unusual outbound ports, large off-hours transfers, DGA (many NXDOMAIN from one host), high-frequency DNS queries. Detect beaconing: IO Graph of specific host's outbound. DGA filter: dns.flags.rcode==3 and ip.src==[suspect]. Regular = malware; irregular = human.

💭 THINK FIRST · BOTNET COMMUNICATION

Botnet C2 channels are designed to blend with legitimate traffic. HTTP-based C2 mimics web browsing; DNS-based C2 hides in normal DNS traffic; HTTPS C2 uses encryption to conceal commands. Detecting these channels requires looking at behavioral anomalies rather than content.

  • You see regular HTTP GET requests from a host to a legitimate-looking URL, but the User-Agent is "Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)". Why is this suspicious in 2025?
  • What is domain fronting and why does it make C2 traffic difficult to block?
Q1 — OUTDATED USER-AGENT IN 2025
Internet Explorer 6.0 running on Windows XP (Windows NT 5.1) has been end-of-life since 2014 — no legitimate user is running this browser on a modern system. Malware often uses hardcoded User-Agent strings that were common years ago, failing to update them as time passes. This outdated User-Agent string in 2025 is a strong indicator of a non-human client (malware or bot) making the HTTP request. Legitimate browsers update their User-Agent strings with every browser version. Combine this with the regularity of the requests and the destination IP to build the case.
Q2 — DOMAIN FRONTING
Domain fronting is a technique where the TLS SNI (Server Name Indication — visible in the unencrypted TLS ClientHello) shows a legitimate, trusted CDN domain (e.g., a major cloud provider's domain), while the actual HTTP Host header inside the encrypted TLS session requests a different, malicious domain. The firewall sees the TLS SNI pointing to a trusted CDN and allows the traffic; the CDN routes the request based on the inner Host header to the actual C2 server. Because the actual destination is encrypted inside TLS, it's invisible to the firewall. Block the CDN domain to stop it, and you'd block all traffic to that CDN (collateral damage). CDN providers have been closing domain fronting loopholes, but it remains an active technique.
Section 2

Botnet Communication Patterns

Botnets use a range of C2 communication channels, each designed to blend into legitimate traffic and evade detection. Identification requires behavioral analysis — looking at regularity, User-Agent anomalies, and protocol misuse rather than payload content.

Botnet C2 channels:

  1. HTTP-based C2 — bot polls server via GET/POST at regular intervals. Blends with web traffic. Indicators: regular interval, unusual User-Agent string, small fixed-size responses with commands encoded in body.
  2. HTTPS C2 — encrypted channel; requires TLS session key log to inspect payload. Detectable by behavioral anomalies (timing, destination IP reputation).
  3. DNS-based C2 — commands encoded in DNS query/response fields (subdomain labels, TXT records). High query frequency to one base domain.
  4. IRC-based C2 (older botnets) — TCP port 6667, IRC protocol visible in stream. Now uncommon but still encountered in legacy infections.
  5. P2P C2 — no single server; distributed control. Harder to take down; produces many peer-to-peer connections rather than traffic to one C2 IP.
  6. Domain Fronting — TLS SNI shows trusted domain; HTTP Host header inside TLS points to actual C2 server.
HTTP C2 detection signals HTTP C2 often mimics web traffic. Look for: User-Agent anomalies (outdated or fake browser strings), mechanically regular request intervals, C2 responses with HTTP 200 but no meaningful HTML content (small payloads disguised as web responses, not actual web pages).
🧠
MENTAL NOTE
C2 channels: HTTP (regular GET/POST, odd User-Agent, small fixed payloads), HTTPS (encrypted, needs key log), DNS (encoded in subdomain queries), IRC (port 6667), P2P (distributed). Domain fronting: TLS SNI does not match HTTP Host header. HTTP C2 detection: User-Agent anomaly + regular timing + small unusual payload.

💭 THINK FIRST · DATA EXFILTRATION

Data exfiltration uses both obvious and covert channels. HTTP POST and FTP uploads are obvious but easily detected. DNS tunneling and ICMP tunneling hide data in protocol fields not normally inspected. Recognizing the signatures of each technique is essential for security analysis.

  • You see DNS queries with names like "dGhpcyBpcyBkYXRh.evil-domain.com" repeated many times. What is happening and what encoding is likely being used?
  • What fields in ICMP would you examine to detect ICMP tunneling?
Q1 — BASE64 SUBDOMAIN DNS QUERIES
This is DNS tunneling for data exfiltration. The subdomain portion ("dGhpcyBpcyBkYXRh") is base64-encoded data being covertly transmitted in the DNS query name. The malware encodes small chunks of stolen data as base64 strings, uses them as subdomains of a controlled domain (evil-domain.com), and sends DNS queries — which most firewalls allow outbound. The attacker's authoritative DNS server for evil-domain.com receives these queries, decodes the subdomains, and reassembles the exfiltrated data. Base64 characters (A–Z, a–z, 0–9, +, /, =) are the typical encoding. DNS tunneling signatures: long subdomain names (>30–50 chars), high query frequency to the same base domain, many unique subdomains for one base domain, TXT or NULL record queries.
Q2 — ICMP TUNNELING DETECTION FIELDS
ICMP tunneling encodes data in the ICMP Echo Request/Reply payload field (the data portion after the ICMP header). Normal ping requests have small, fixed payloads (typically 32 bytes on Windows, 56 bytes on Linux). Check: (1) icmp.data_len — normal pings are small; tunneling uses large payloads (hundreds to thousands of bytes). (2) Payload content — normal ping payloads contain repeated ASCII characters (abcdef...); tunneling payloads have variable, high-entropy content. (3) Frequency — normal ping is manual or one-time; tunneling is continuous high-frequency stream. (4) Bidirectionality — normal ping is request+reply; tunneling shows meaningful data in both directions.
Section 3

Data Exfiltration Signatures

Attackers use a spectrum of channels to move data out of a network — from obvious HTTP uploads to covert DNS and ICMP tunnels. Each channel has a distinct packet signature that Wireshark can expose.

FilterWhat It Shows
http.request.method=="POST"HTTP uploads (data sent to server)
ftp.request.command=="STOR"FTP file uploads
dns.qry.name matches ".*[a-z0-9]{30,}.*"Long DNS names (possible tunnel)
icmp.data_len > 64Large ICMP payloads (possible tunnel)
smtp.req.command=="RCPT"SMTP recipients (email exfiltration)

Exfiltration channels and their signatures:

  1. HTTP/HTTPS POST — large request bodies to external servers, especially non-enterprise IPs.
  2. FTP STOR — file uploads to external FTP servers. Visible in plain text in Wireshark stream.
  3. DNS tunneling — data encoded in DNS subdomain queries (long names, high TXT/NULL query rate, many unique subdomains per base domain).
  4. ICMP tunneling — data in ICMP Echo payload (large payload size, high frequency, variable/high-entropy content).
  5. SMTP attachments — email with large attachments to external addresses, especially outside business hours.
🧠
MENTAL NOTE
Exfil channels: HTTP POST (large body), FTP STOR, DNS tunnel (long subdomain names, high freq, TXT queries), ICMP tunnel (large payload, icmp.data_len > 64, variable content), SMTP attachments. DNS tunnel: base64 in subdomain labels. ICMP tunnel: icmp.data_len large + high entropy + continuous bidirectional stream.

💭 THINK FIRST · DNS ANOMALIES

DNS is the most abused protocol in malware and exfiltration because it's almost universally allowed outbound by firewalls. Anomalies in DNS traffic — high NXDOMAIN rates, unusual query types, long domain names, or DNS on non-standard ports — are among the highest-value security indicators in network traffic.

  • Host 10.0.0.55 generates 300 NXDOMAIN responses in 5 minutes for random-looking domains. What is this behavior?
  • How would you write a filter to find DNS traffic NOT on port 53?
Q1 — 300 NXDOMAIN IN 5 MINUTES
This is DGA (Domain Generation Algorithm) malware. The host is infected with malware that generates random-looking domain names algorithmically (the "300 NXDOMAIN in 5 minutes" is the bot cycling through generated names looking for the one currently registered by the attacker as the active C2 server). Most generated names return NXDOMAIN because they don't exist — the attacker registers only a few of the thousands of generated names, rotating them to evade blocklists. The algorithm is seeded with a date, so both the malware and attacker can independently calculate the same set of candidate domains for any given day.
Q2 — DNS ON NON-STANDARD PORT FILTER
dns and not (udp.port == 53 or tcp.port == 53). This filter shows packets that Wireshark decodes as DNS protocol but that are NOT on the standard port 53. Malware sometimes runs DNS-like communication on unusual ports to evade DNS-specific firewall rules and DNS monitoring tools. Alternatively: dns and not udp.port==53 and not tcp.port==53. Any result from this filter warrants immediate investigation.
Section 4

DNS Anomalies and Analysis

DNS anomalies are high-value security indicators precisely because DNS is universally trusted by firewalls. Normal DNS traffic has a predictable profile — a few queries per minute for varied, recognizable domains. Any significant deviation from this baseline warrants investigation.

DNS anomaly patterns:

  1. High NXDOMAIN rate — filter dns.flags.rcode==3. Many NXDOMAINs from one host = DGA malware cycling through generated names.
  2. Long domain names — DGA and DNS tunnel queries have unusually long subdomains (>30–50 characters). Look for base64 or random-looking strings in the subdomain.
  3. High query rate to one base domain — C2 beaconing via DNS; may encode commands in subdomains of a single controlled base domain.
  4. Unusual record types — TXT, NULL, MX queries for unusual domains may carry tunneled data.
  5. DNS on non-standard ports — filter dns and not (udp.port==53 or tcp.port==53). Any DNS-decoded traffic on a non-standard port = evasion attempt.
  6. PTR lookup storms — many reverse DNS queries from one host in rapid succession = network scanning activity (host discovery via reverse lookup).

Baseline comparison: Normal DNS — fewer than 10 queries per minute from one host for varied domains. Suspicious — more than 100 queries per minute, or high rate to one base domain, or many NXDOMAINs from one source.

NXDOMAIN storm = DGA indicator High NXDOMAIN rate from one host (dns.flags.rcode == 3) is the top indicator of DGA malware. Filter: dns.flags.rcode == 3 and ip.src == [suspect host]. 50+ NXDOMAINs per minute from one host is highly suspicious and warrants immediate endpoint investigation.
🧠
MENTAL NOTE
DNS anomalies: NXDOMAIN storm (dns.flags.rcode==3) = DGA. Long subdomain names = DNS tunnel. High TXT/NULL queries = tunnel exfil. DNS on non-port-53 = evasion. PTR storm = network scan. Normal: few DNS queries/min for varied domains. Suspicious: 100+/min, many NXDOMAINs, or queries all to same base domain.
