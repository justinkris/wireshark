    Chapter 32: Suspect Traffic

    Chapter 32 covers analyzing suspect and malicious traffic — malware beaconing, data exfiltration, ARP poisoning, and botnet C2 communications. You'll apply forensic techniques to identify anomalous traffic patterns that deviate from known-good baseline behavior.

    Guided Analysis — Suspect Traffic Patterns
    Concept — Q1
    Malware often communicates with C2 servers in a regular 'beaconing' pattern. How would you detect beaconing in Wireshark? What statistical characteristics distinguish beaconing from normal traffic?
    Use Statistics > Conversations to find IP pairs with very regular communication intervals. Then use I/O Graph filtered to that IP pair — regular spikes at fixed intervals (e.g., every 60 seconds exactly) indicate beaconing. Normal user traffic is irregular and bursty. Beaconing exhibits: consistent inter-packet timing, fixed packet sizes, same destination port, and traffic even when the user is away from the computer.
    Trace: arp-poison.pcapng — Q2
    Open arp-poison.pcapng. Apply filter arp. What is ARP poisoning, and what pattern in the ARP traffic indicates it is occurring?
    ARP poisoning sends gratuitous ARP replies to update other hosts' ARP caches with the attacker's MAC address mapped to a legitimate IP (e.g., the gateway IP). This redirects traffic through the attacker (man-in-the-middle). Signs: (1) ARP replies without preceding ARP requests (gratuitous ARPs). (2) Multiple MAC addresses claiming the same IP. (3) An IP that suddenly maps to a different MAC than the baseline. Filter for gratuitous ARPs: arp.isgratuitous == 1.
    Concept — Q3
    How would you detect data exfiltration over DNS in a packet capture? What specific filters and statistics would you examine?
    (1) Apply dns and check Statistics > Conversations — excessive DNS to a single unusual authoritative server. (2) Filter dns.qry.name and look for long subdomain strings (>30 chars before the domain root). (3) Apply dns && frame.len > 200 — abnormally large DNS packets. (4) Filter dns.qry.type == 16 for TXT queries. (5) Look for consistent intervals in I/O Graph filtered to DNS — beaconing via DNS is common in tunneling tools.
    Optional Traces
    arp-poison.pcapng
    Apply arp. Look for arp.isgratuitous==1. Identify which IP is being 'hijacked' and what MAC is the poisoner. Then look at traffic after the poison — do you see the victim's traffic now appearing to route through the attacker?
    sec-strangescan.pcapng
    Beyond port scanning, look for payload content in any established connections. Apply tcp contains "cmd" or tcp contains "shell" to search for command execution strings in TCP payloads.
    Any trace — exfiltration detection
    Go to Statistics > Conversations. Sort by bytes sent from internal IPs to external IPs. Any internal host sending unusually large volumes outbound (compared to baseline) may be exfiltrating data. Note: inbound-heavy = normal web browsing; outbound-heavy = potential exfiltration.
    Review Questions
    Review Q32.1
    What is ARP cache poisoning and what Wireshark filter identifies gratuitous ARP packets used in an attack?
    ARP cache poisoning (ARP spoofing) involves sending unsolicited ARP replies that associate the attacker's MAC with a legitimate IP address, redirecting traffic through the attacker for man-in-the-middle interception. Filter: arp.isgratuitous == 1 finds gratuitous ARP replies. Also look for arp.duplicate-address-detected which Wireshark flags when two ARP entries for the same IP have different MACs.
    Review Q32.2
    What behavioral pattern distinguishes malware C2 beaconing from normal user web traffic in an I/O Graph?
    C2 beaconing: regular, periodic spikes at fixed intervals regardless of time of day; traffic continues even outside business hours; consistent packet sizes and destination IP. Normal web traffic: irregular, bursty, correlates with user activity (stops at night/weekends), highly variable packet sizes and many different destination IPs. I/O Graph interval: use 1-second buckets over several hours to visualize the regularity.
    Review Q32.3
    What Wireshark filter searches for a specific string in packet payloads, and how might you use this during a malware investigation?
    frame contains "string" searches all packet bytes for the literal string. Protocol-specific: tcp contains "password", http contains "malware.exe", dns.qry.name contains "evil.com". During malware investigation: search for known IOCs (Indicators of Compromise) — C2 domain names, URL paths from threat intel feeds, specific user-agent strings, or unique strings from the malware binary (if known).
