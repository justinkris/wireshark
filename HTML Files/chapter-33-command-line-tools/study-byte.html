    Chapter 33: Command-Line Tools

    Chapter 33 covers Wireshark's command-line companions — TShark (CLI packet analyzer), dumpcap (high-performance capture engine), Capinfos (trace file info), and Editcap/Mergecap (trace file manipulation). These tools enable scripting, automation, and large-scale trace analysis.

    Guided Practice — TShark Commands
    Concept — Q1
    What is TShark, and how does it relate to Wireshark? Write a TShark command that captures 100 packets on interface eth0 and saves them to a file called output.pcap.
    TShark is Wireshark's command-line counterpart — it uses the same dissectors and display filters as the GUI but runs without a graphical interface, making it ideal for remote servers, scripts, and automation. Command: tshark -i eth0 -c 100 -w output.pcap. Flags: -i = interface, -c = count (stop after N packets), -w = write to file.
    Concept — Q2
    Write a TShark command that reads an existing trace file and prints only the source IP, destination IP, and protocol for each packet. Then write one that counts HTTP GET requests.
    Print fields: tshark -r input.pcap -T fields -e ip.src -e ip.dst -e _ws.col.Protocol. Count HTTP GETs: tshark -r input.pcap -Y 'http.request.method=="GET"' | wc -l. The -Y flag applies a display filter (same syntax as Wireshark GUI). -T fields -e extracts specific fields in tab-delimited format, ideal for piping to grep, awk, or Python.
    Concept — Q3
    What is the purpose of editcap and mergecap? Give a use-case for each.
    editcap modifies existing trace files: split a large capture into time-based segments (editcap -i 60 big.pcap chunk_.pcap = one file per 60 seconds), remove duplicate packets (-d), or convert between capture formats. mergecap combines multiple pcap files into one (mergecap -w combined.pcap file1.pcap file2.pcap), useful when you have captures from multiple interfaces or time periods that need to be analyzed together.
    Optional Traces
    TShark — live analysis
    Open a terminal and run: tshark -i [your-interface] -Y 'dns' -T fields -e dns.qry.name. Watch DNS queries scroll in real time. Replace 'dns' with 'http.request' to watch HTTP requests live.
    Capinfos — trace metadata
    Run capinfos [any-trace.pcapng] on one of the book's trace files. Record: file format, number of packets, duration, average packet rate, data byte rate. This is faster than opening Wireshark's Statistics > Summary.
    TShark — statistics mode
    Run tshark -r [trace.pcap] -q -z io,stat,1 to get a per-second I/O statistics report from the command line. Compare to Wireshark's I/O Graph.
    Review Questions
    Review Q33.1
    What TShark flag applies a display filter when reading a trace file, and what flag applies a capture filter during live capture?
    Display filter (reading files or live): -Y 'filter-expression' (same syntax as Wireshark display filters). Capture filter (live capture only): -f 'bpf-expression' (BPF syntax). Example: tshark -i eth0 -f 'port 80' -Y 'http.request.method=="GET"' captures only port 80 traffic (-f) then applies display filter to show only GETs (-Y).
    Review Q33.2
    What is dumpcap, and when would you use it instead of TShark or Wireshark?
    Dumpcap is Wireshark's dedicated capture engine — it runs with minimal overhead and can capture at very high packet rates without dropping packets, even on busy links. Use it when you need long-running captures on production systems where you can't afford the overhead of the full TShark dissection engine. It only captures (no analysis); you analyze the resulting pcap files later with TShark or Wireshark. It also supports ring buffer mode (-b filesize:100 -b files:10) for continuous capture with automatic file rotation.
    Review Q33.3
    How would you use editcap to extract only the first 10 minutes of traffic from a 2-hour capture file?
    editcap -A [start-time] -B [end-time] input.pcap output.pcap where times are in YYYY-MM-DD HH:MM:SS format. Alternatively, to extract by packet count: editcap -r input.pcap output.pcap 1-N where N is the packet number corresponding to 10 minutes in. Or split by time intervals: editcap -i 600 input.pcap chunk_.pcap splits into 600-second (10-minute) files automatically.

    Quick Reference

    tshark -Y 'filter'
    Apply display filter when reading/capturing. Same syntax as GUI.
    tshark -T fields -e
    Extract specific fields in tab-delimited output for scripting.
    dumpcap
    High-performance capture-only engine. Use for long captures on busy links.
    editcap / mergecap
    Split/modify or merge pcap files. editcap -i 60 = 60-second splits.
