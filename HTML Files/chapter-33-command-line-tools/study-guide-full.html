Effective Use of Command-Line Tools

Tshark, Editcap, Mergecap, Capinfos, Dumpcap, and Text2pcap

"Tshark's primary purpose is to offer command-line packet capture — it requires fewer resources than the GUI Wireshark and handles large trace files efficiently."

💭THINK FIRST · COMMAND-LINE LAUNCH▾

Wireshark includes a set of command-line tools for capturing, manipulating and analyzing network traffic. Wireshark.exe can be launched with parameters to automatically begin capturing on a specific interface with specific filters.

  • What is the advantage of launching Wireshark with a specific configuration profile (-C) from the command line?
  • How would you use Wireshark command-line parameters to create a ring buffer that captures traffic in a rolling set of files?
Q1: Launching with a profile (-C "WLAN" for example) automatically applies all the custom columns, coloring rules, and preferences defined in that profile — no manual selection needed. This is especially useful when you need to respond quickly to an incident and want the right analysis environment immediately.
Q2: Use the -b (ring buffer) parameter: -b duration:7 -b files:2 -a files:4 to create a ring buffer that captures in 7-second file chunks, keeps only the 2 most recent files, and automatically stops after 4 files total. Replace the files count with duration to run until manually stopped.

Use Wireshark.exe (Command-Line Launch)

Wireshark.exe launches the graphical view of Wireshark. There are numerous parameters that can be used to automatically begin capturing traffic from a specific interface, apply a capture filter, and set various capture parameters. Consider adding the Wireshark program file directory to your path so you can run these tools from any directory.

Key Wireshark Launch Parameters

ParameterDescription
-i <interface>Name or ID of interface (default: first non-loopback)
-f <filter>Packet filter in libpcap filter syntax (capture filter)
-kStart capturing immediately
-c <count>Stop after n packets
-a duration:NAutostop: stop after N seconds
-b duration:N -b files:NRing buffer: switch to next file after N seconds, keep N files
-C <profile>Start with specified configuration profile
-r <infile>Read from an existing trace file
-nDisable all name resolutions
-R <display filter>Packet filter in Wireshark display filter syntax

Customize Wireshark Launch

You can create shortcuts to launch separate instances of Wireshark with specific properties. For example:

wireshark -k -C "WLAN" -i airpcap_any   (WLAN profile, AirPcap multi-channel)
wireshark -k -i 7 -c 1000                      (Capture 1000 packets on interface 7)
wireshark -k -i 7 -a duration:200              (Capture for 200 seconds)
wireshark -r noarp.pcapng                      (Open existing trace file)

💭THINK FIRST · TSHARK CAPTURE AND STATS▾

Tshark can capture live traffic or display a saved trace file. It uses fewer resources than the GUI Wireshark. The -z option provides statistics on protocols, conversations, IO rates, and service response times without displaying packets.

  • When would you prefer to use Tshark over the GUI Wireshark for packet capture, and when would you prefer Dumpcap?
  • What is Bug 2234 in Tshark, and what is the workaround?
Q1: Use Tshark when you need to capture to file on a remote system or a low-memory system, or when you want to extract specific fields programmatically (using -T fields -e field.name). Use Dumpcap when you only need raw packet capture without any dissection — Dumpcap is the capture engine for Tshark and uses fewer resources than Tshark itself.
Q2: Bug 2234: display filters (-R) do not work when simultaneously running a live capture and saving packets to a file. Workaround: capture without a display filter first using Dumpcap or Tshark, then run Tshark again against the saved file with the display filter and -w to write filtered output to a new file.

Capture Traffic with Tshark

Tshark can be used to capture live traffic or display a saved trace file. Packets can be displayed to the standard output (screen) or saved to a trace file. The resource overhead is much lower than the GUI version of Wireshark, but higher than Dumpcap.

ParameterDescription
-i <interface>Name or ID of interface (default: first non-loopback)
-f <filter>Packet filter in libpcap filter syntax
-R <read filter>Packet filter in Wireshark display filter syntax (read from file)
-w <outfile>Set the output filename
-T fields -e <field>Output specific field values only (e.g., -T fields -e http.host)
-qBe more quiet — show only statistics, not packets
-z <statistics>Show various statistics (io,phs / conv,eth / conv,ip / conv,tcp)
-VAdd output of packet tree (Packet Details)
-O <protocols>Only show packet details for these protocols

Tshark can be used to quickly gather statistics on live traffic or trace files. Use the -q option if you only want the statistics and do not want to see the packets while running Tshark.

Service Response Times with Tshark

Tshark can obtain Service Response Time (SRT) values for numerous protocols using the syntax: tshark -i <adapter> -qz <protocol>,srt. Supported protocols include: afp, camel, dcerpc, h225, icmp, icmpv6, rpc, scsi, smb.

💭THINK FIRST · EDITCAP AND MERGECAP▾

Editcap is used to edit trace files: split large files into file sets, remove duplicate packets, adjust timestamps, and truncate packets. Mergecap combines multiple trace files into one.

  • When would you need to adjust timestamps in a trace file using Editcap, and what would happen if you merged two unsynchronized trace files without doing so?
  • What is the difference between using File | Merge in Wireshark and using Mergecap from the command line?
Q1: If two trace files were captured on hosts with unsynchronized clocks (e.g., 0.5 seconds apart), merging them directly would interleave packets incorrectly. The packet from file B timestamped at T=0.5 would appear after file A's packet at T=0.6 even if they were actually simultaneous. Use editcap -t to shift timestamps before merging.
Q2: File | Merge in Wireshark orders files based on the most recent trace file merged (not timestamp-based). Mergecap by default merges based on packet timestamps (chronological order across all files). Use Mergecap -a for concatenation order regardless of timestamps.

Edit Trace Files with Editcap

Use Editcap to split a trace file, alter the trace file timestamp, remove duplicates and perform other trace file editing tasks. You must specify both an input and output file.

ParameterDescription
-c <packets per file>Split into files of a maximum of N packets each
-i <seconds per file>Split into files based on time intervals
-dRemove duplicate packets (5-packet window)
-D <window>Remove duplicate packets with configurable window size
-t <time adjustment>Adjust the timestamp of each packet (in seconds, e.g., -0.5)
-s <snaplen>Truncate each packet to max N bytes
-A <start time>Only output packets after this time (YYYY-MM-DD hh:mm:ss)
-B <stop time>Only output packets before this time (YYYY-MM-DD hh:mm:ss)
editcap -d dupes.pcapng nodupes.pcapng          (Remove duplicates within 5-packet window)
editcap -c 2000 dbad.pcapng dbadsplit.pcapng    (Split into 2000-packet files)
editcap -t -0.2 oldtime.pcapng newtime.pcapng  (Subtract 0.2 seconds from all timestamps)

Merge Trace Files with Mergecap

Use Mergecap to merge two or more capture files into one. By default, Mergecap merges files based on packet timestamps (chronological order). Use -a to concatenate in the order listed regardless of timestamps.

mergecap -w allinone.pcapng file1.pcapng file2.pcapng  (Merge by timestamp)
mergecap -a -w neworder.pcapng trace1.pcapng trace2.pcapng  (Concatenate in order)

MENTAL NOTE
Editcap tasks: split large files (-c packets or -i seconds), remove duplicates (-d), adjust timestamps (-t), time-filter packets (-A/-B). Mergecap: default merges by packet timestamp; -a concatenates in order. Workflow for time-shift merge: (1) use capinfos -aeS to get timestamps, (2) editcap -t to adjust, (3) mergecap to combine. File sets can be accessed via File | File Set in Wireshark after splitting.

💭THINK FIRST · CAPINFOS, DUMPCAP, AND TEXT2PCAP▾

Capinfos displays details about trace files (packet count, duration, data rates). Dumpcap is the underlying capture engine — lower resource usage than Tshark. Text2pcap converts ASCII hex dumps to pcap trace files.

  • What type of information does Capinfos provide that Tshark -z statistics does NOT provide, and vice versa?
  • When would you prefer Dumpcap over Tshark for packet capture?
Q1: Capinfos provides file-level metadata: capture file type, number of packets, capture duration, file size in bytes, average data rate, average packet rate, SHA1/MD5 hashes. Tshark -z statistics provides protocol and conversation statistics from within the packets themselves (protocol hierarchy, IP/TCP conversations). They are complementary — Capinfos tells you ABOUT the file; Tshark -z tells you what is IN the file.
Q2: Use Dumpcap when you only need raw capture to a file with no dissection. Dumpcap uses fewer resources than Tshark because it does not perform protocol dissection. On a flooded network or resource-constrained system where you need to capture as many packets as possible without dropping them, Dumpcap is the better choice.

Capinfos, Dumpcap, and Text2pcap

List Trace File Details with Capinfos

Capinfos prints information about trace files — useful for quickly auditing trace files before analysis.

ParameterDescription
-tDisplay the capture file type
-cDisplay the number of packets
-sDisplay the size of the file (in bytes)
-uDisplay the capture duration (in seconds)
-a, -eDisplay the capture start and end time
-y, -iDisplay average data rate (in bytes/sec and bits/sec)
-zDisplay average packet size (in bytes)
-xDisplay average packet rate (in packets/sec)
-HDisplay the SHA1, RIPEMD160, and MD5 hashes of the file
capinfos -csd 100pkts.pcapng             (Packet count, file size, total length)
capinfos -uae 100pkts.pcapng            (Duration, start and end time)
capinfos -yizx 100pkts.pcapng          (Average rates and packet size)
capinfos -H tcp*.pcapng                 (MD5/SHA1 hashes for all tcp*.pcapng files)
capinfos -aeS before.pcapng after.pcapng  (Compare start/end times for merging)

Capture Traffic with Dumpcap

Dumpcap is used to capture network packets and save them into a libpcap format file. Dumpcap is used as the capture engine for Tshark but uses fewer resources than Tshark — an advantage when capturing on a flooded network or resource-constrained system.

dumpcap -i 7 -b files:25 -b filesize:25000 -w capset.pcapng  (Ring buffer: 25 files of 25MB)
dumpcap -a duration:3000 -w 5mins.pcapng                    (Capture for 50 minutes)

Convert Text with Text2pcap

Text2pcap generates a trace file from an ASCII hex dump of packets. If the original text does not include certain headers (Ethernet, IP, UDP or TCP), use the Text2pcap options to prepend dummy headers on the data to create properly formatted trace files.

📷Figure 407 — open trace file to view
Figure 407. Use Text2pcap to convert traffic from text format to pcap format.
text2pcap plainfile.txt newtrace.pcapng                   (Basic text to pcap conversion)
text2pcap -e 0x0800 iptext.txt iptrace.pcapng              (Prepend Ethernet header for IP packets)
text2pcap -u 1000,69 udptext.txt udptrace.pcapng           (Prepend Ethernet/IP/UDP headers)

Understand Rawshark

Rawshark expects raw libpcap packet headers followed by packet data. Unlike Tshark, Rawshark makes no assumptions about the encapsulation or input format. You must use the -d (encapsulation) and -r (input file) flags. Most likely, you will use Tshark and Dumpcap for command-line packet capture — Rawshark is the third, rarely used, command-line capture tool included with Wireshark.

🧠
MENTAL NOTE
Capinfos = file metadata (packet count, duration, data rates, hashes). Tshark -z = protocol/conversation statistics from packet contents. Dumpcap = lowest resource capture engine (no dissection). Text2pcap = convert ASCII hex dump to pcap. Tool resource usage: Dumpcap < Tshark < Wireshark GUI. Use Dumpcap on flooded networks. Use Editcap -c to split large files before opening in Wireshark.

Case Study

Case Study 1
Getting GETS and a Suspect
Submitted by: Anonymous

An anonymous security team ran Wireshark for a week to watch all the traffic to and from an employee's PC, suspecting the employee was connected to a competitor's site that had obtained corporate price sheets. They ended up with trace files 100MB in size — too big to open directly in Wireshark.

After researching Tshark, they found they could easily pull out packets that referenced the file name in an HTTP GET request. They used the following Tshark command:

tshark -r capcorp1.pcap -R http.request.method=="GET" && frame contains "pricex"

They added -w project.pcap to save those packets to a separate file. After just three days, they found the suspect not only viewing the competitor site but also uploading a newer price sheet that had been released just days before. They had clear evidence that the employee was sending all the company pricing data to a competitor.

TL;DR — Chapter 33 Summary

Wireshark includes a number of command-line tools that offer added functionality for capturing, manipulating and analyzing network traffic. Wireshark.exe launches the GUI version of Wireshark and can be set to launch with specific parameters in place for a specific interface, filter or other loading sequence.

Tshark provides a command-line tool for capturing traffic and loading a trace file with specific parameters in place. The resource overhead is much lower than the GUI version of Wireshark, but higher than Dumpcap. Rawshark is the third, but rarely used, command-line capture tool. Capinfos can give you a quick view of trace file details such as the number of packets, the average data rate and average packet size. Mergecap can be used to merge multiple trace files. Editcap is a great tool for altering trace file timestamps, splitting up a large trace file into file sets, removing duplicate packets or changing the trace file type. Text2pcap can be used to convert a text file to a trace file.

Review Questions

Q33.1. What is the primary purpose of Tshark?
A: Tshark's primary purpose is to offer command-line packet capture. Tshark is preferred over the GUI capture because it requires fewer resources than the GUI Wireshark.exe.
Q33.2. Which command-line tool can be used to change the packet timestamps on a trace file?
A: Editcap can be used to change packet timestamps using the -t parameter.
Q33.3. Which command-line tool can be used to display the capture file type, the number of packets and the capture duration of a trace file?
A: Capinfos can be used to display numerous statistics about a trace file. For information about the protocols and applications in a trace file, use Tshark with the -z parameter.
Q33.4. You are working on a system that is low on memory and a network that is saturated with packets. Would you rather use tcpdump or Tshark to capture traffic?
A: Between tcpdump and Tshark, tcpdump uses fewer system resources but does not offer as many capture configuration options. However, Dumpcap (included with Wireshark) uses even fewer resources than Tshark.
