💭 THINK FIRST · TSHARK BASICS

tshark is the command-line equivalent of Wireshark — it can do almost everything Wireshark's GUI can, but without a display. This makes it essential for headless servers, SSH analysis sessions, CI/CD pipelines, and scripted automation. The fundamental commands map directly to Wireshark GUI actions.

  • You need to capture traffic on a Linux server with no GUI, writing to a file for exactly 5 minutes. What tshark command would you run?
  • How do you find the names of network interfaces available for capture on a system using tshark?
Q1 — TSHARK CAPTURE TO FILE FOR 5 MINUTES
tshark -i eth0 -w /tmp/capture.pcapng -a duration:300 — this captures on interface eth0, writes to a file, and automatically stops after 300 seconds (5 minutes). If you don't know the interface name, first run tshark -D to list all available interfaces. To capture on all interfaces simultaneously, use -i any (on Linux).
Q2 — LISTING INTERFACES WITH TSHARK
tshark -D lists all available capture interfaces with their index numbers and names, the same list shown on Wireshark's welcome screen. Output example: 1. eth0 / 2. any / 3. lo. Use the index number or the name with the -i flag. This is the first command to run on an unfamiliar system before attempting any capture.

💭 THINK FIRST · TSHARK OUTPUT MODES

tshark's -T fields mode combined with -e field selectors is one of the most powerful analysis tools available — it extracts exactly the protocol fields you care about as tab-separated output that can be piped to standard Unix tools (grep, sort, uniq, awk, cut) for immediate analysis without opening Wireshark.

  • Write a tshark command to extract all DNS query names from a capture file, outputting only the domain names.
  • What tshark command gives you TCP conversation statistics from a capture file without printing individual packets?
Q1 — EXTRACT DNS QUERY NAMES
tshark -r capture.pcapng -Y "dns.flags.response == 0" -T fields -e dns.qry.name — this reads the file, filters to DNS queries only (not responses, to avoid duplicates), and outputs only the dns.qry.name field. Each line of output is one queried domain name. Pipe through sort | uniq -c | sort -rn to get a frequency-ranked list of queried domains.
Q2 — TCP CONVERSATION STATISTICS
tshark -r capture.pcapng -z conv,tcp -q — the -z conv,tcp option generates TCP conversation statistics (source IP, destination IP, source port, destination port, frames, bytes per direction), and -q suppresses individual packet output. The result is a conversation summary table printed at the end of processing. Other useful -z options: io,stat,1 (IO statistics per second), expert (expert information summary), http,stat (HTTP method/code breakdown).

💭 THINK FIRST · EDITCAP AND MERGECAP

editcap and mergecap are the command-line tools for manipulating capture files — splitting, slicing, converting formats, removing duplicates, adjusting timestamps, and merging multiple captures. They operate efficiently without opening a GUI and are essential for preparing captures for analysis or sharing.

  • You have two simultaneous captures from two different servers. How do you merge them into one time-ordered file?
  • A capture was taken with the capture machine's clock wrong by exactly +1 hour (1 hour fast). How do you fix the timestamps?
Q1 — MERGING TWO CAPTURE FILES
mergecap -w combined.pcapng server1.pcapng server2.pcapng — mergecap reads both files, sorts all packets chronologically by timestamp, and writes them to a single output file. If both capture machines had synchronized clocks (NTP), the merged file will have correct relative ordering. If clocks were unsynchronized, you may need to adjust one file's timestamps first with editcap -t before merging.
Q2 — FIXING TIMESTAMP CLOCK SKEW
editcap -t -3600 input.pcapng output.pcapng — the -t option shifts timestamps. Since the clock was 1 hour fast (3600 seconds too high), subtract 3600 seconds by using -t -3600. The output file will have all timestamps shifted back by 1 hour. If the clock was slow (1 hour behind), use -t 3600 to add 3600 seconds. Always document any timestamp adjustments in your forensic report.

💭 THINK FIRST · CAPINFOS AND DUMPCAP

capinfos and dumpcap serve distinct purposes. capinfos provides file metadata without opening Wireshark — useful for forensic hashing, file validation, and quick stats. dumpcap is a capture-only tool with lower overhead than tshark, making it the right choice for high-speed captures where protocol dissection during capture would cause packet drops.

  • As part of forensic evidence handling, you need the SHA-256 hash of a capture file without opening Wireshark. What command do you use?
  • For maximum capture performance on a busy 10Gbps interface, which Wireshark CLI tool should you use and why?
Q1 — FORENSIC FILE HASH WITH CAPINFOS
capinfos -M file.pcapng — the -M flag outputs the MD5, SHA1, and SHA256 hashes of the file. The SHA256 hash can be recorded as the evidence integrity hash. Alternatively, use the operating system's built-in hash tool (sha256sum on Linux, Get-FileHash on Windows PowerShell, shasum -a 256 on macOS) for independent verification.
Q2 — HIGH-SPEED CAPTURE WITH DUMPCAP
dumpcap — it has the lowest overhead of all Wireshark CLI tools because it only captures raw packets and writes them to disk without performing any protocol dissection. tshark and Wireshark dissect each packet as it arrives, which uses significantly more CPU. On a high-speed link, this CPU overhead can cause the capture buffer to fill faster than packets can be written, resulting in drops. dumpcap avoids this by being a pure capture engine. Capture with dumpcap to file, then analyze offline with tshark or Wireshark at full speed. dumpcap also supports ring buffers natively (-b files:N filesize:KB).
