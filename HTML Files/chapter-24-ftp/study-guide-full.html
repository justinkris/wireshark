Analyze File Transfer Protocol (FTP) Traffic

💡THINK FIRST · PURPOSE OF FTP

FTP uses TWO separate TCP connections — a command channel and a data channel. The command channel stays open for the entire session on port 21. But the data channel is opened on demand for each file transfer and directory listing. Why are two channels needed? What would be the problem with sending data on the same connection as commands?

HINT

Think about what happens during a directory listing — the client needs to receive a list of files while also potentially sending more commands. How does having a separate data channel help?

MODEL ANSWER

Two channels allow the command channel to remain open and responsive (sending directory navigation commands, checking status) while the data channel handles bulk file transfer. Without separation, the client couldn't send new FTP commands while a large file is downloading — the entire session would freeze. The spec defines port 20 for the data channel (active mode), but in practice dynamic ephemeral port numbers are used (passive mode). FTP is defined in RFC 959.

The Purpose of FTP

FTP (File Transfer Protocol) is used to transfer files over TCP. FTP is covered in RFC 959. TFTP (Trivial File Transfer Protocol) uses connectionless transport (UDP) — this chapter focuses on FTP only.

In a typical FTP communication, a command channel is established to port 21 on the FTP server. To transfer data (such as directory contents or files), a secondary data channel is established using dynamic port numbers. The specification defines that port 20 is to be used for the data channel in active mode, but in reality you will notice dynamic port numbers in use for this channel (passive mode is the default for most clients).

FTP IS NOT SECURE

FTP sends the username and password in clear text on the command channel. Anyone who can capture network traffic between the FTP client and server can read the credentials. Use SFTP (SSH File Transfer Protocol) or FTPS (FTP over TLS) for secure file transfers. When analyzing FTP traces, you can often see credentials in plain text by following the TCP stream of the command channel.

🧠
MENTAL NOTE
FTP = RFC 959. Two channels: command (port 21, stays open) + data (dynamic port, opened per transfer). FTP is NOT secure — credentials in clear text. Commands are in UPPER CASE in packets even if typed in lower case. Use ftp filter for command channel; ftp-data for data channel.

💡THINK FIRST · NORMAL FTP COMMUNICATIONS

FTP clients type 'get' and 'put' at the command line — but what commands actually appear in the packets? And FTP servers respond with numerical codes similar to HTTP. What do response codes in the 100-299 range indicate vs codes in the 400-599 range?

HINT

Think about command translation: 'get' becomes RETR (retrieve), 'put' becomes STOR (store). And consider what the numerical response code ranges mean.

MODEL ANSWER

FTP command translation: get → RETR, put → STOR, dir/ls → NLST or LIST, cd → CWD. Commands are always in uppercase in the packets. FTP response code ranges: 1xx = Positive Preliminary (transfer starting), 2xx = Positive Completion (command succeeded), 3xx = Positive Intermediate (more info needed), 4xx = Transient Negative Completion (temporary failure, retry), 5xx = Permanent Negative Completion (fatal error, don't retry). Key codes: 220=service ready, 230=login successful, 227=entering passive mode, 226=transfer complete, 550=file not found.

Analyze Normal FTP Communications

FTP connections begin with a TCP handshake followed by the client waiting for the server banner.

Clients issue commands and servers respond with numerical codes. You can create a filter looking for all hosts attempting to login to an FTP server using the display filter ftp.request.command=="USER".

Standard FTP client commands:

  • USER: Identifies the user accessing the FTP server
  • PASS: Indicates the user's password
  • CWD: Change working directory
  • QUIT: Terminates the connection
  • PORT: Sets up a data connection IP address and port number at the client (active mode FTP)
  • PASV: Requests the server to listen on a non-default data port for the client to establish (passive mode FTP)
  • TYPE: Indicates the type of data to be transferred (A=ASCII, I=Image/binary)
  • RETR: Retrieve a file from the FTP server (what 'get' translates to)
  • STOR: Send a file to the FTP server (what 'put' translates to)
  • DELE: Delete a file | RMD: Remove a directory | MKD: Make a directory
  • PWD: Print (display) working directory | NLST: Name list | HELP: Show commands

FTP Response Codes

Key response codes:

  • 125/150: Data connection open/about to open; transfer starting
  • 200/202: Command okay / not implemented
  • 220/221: Service ready for new user / Closing control connection
  • 226: Closing data connection — file transfer successful
  • 227: Entering Passive Mode (h1,h2,h3,h4,p1,p2) — contains server IP + port
  • 230: User logged in, proceed
  • 331/332: Username okay, need password / Need account for login
  • 421: Service not available, closing control connection
  • 425/426: Can't open data connection / Connection closed, transfer aborted
  • 450/550: File action not taken (file unavailable)
  • 500/501/502: Syntax error / Syntax error in parameters / Command not implemented
  • 530: Not logged in | 553: File name not allowed
🧠
MENTAL NOTE
FTP commands: USER, PASS, CWD, RETR (get), STOR (put), PASV, PORT, TYPE I/A. Response codes: 2xx=success, 3xx=need more info, 4xx=temp failure, 5xx=permanent failure. 227=passive mode with IP+port. 230=logged in. 550=file not found. Filter: ftp.response.code==230 for successful logins.

💡THINK FIRST · PASSIVE MODE FTP

In passive mode, the CLIENT establishes the data connection. The PASV command tells the server to listen on a port and report back the IP:port. What problem does passive mode solve that active mode has? And what does response 227 contain?

HINT

Think about firewalls — if a company has a firewall in front of the FTP client, what happens when the FTP server tries to initiate an INBOUND connection to the client (active mode)?

MODEL ANSWER

Active mode requires the server to initiate an inbound TCP connection to the client (on the PORT the client specified). Corporate firewalls block unsolicited inbound connections — so active mode FTP fails through NAT and firewalls. Passive mode solves this: the server opens a listening port and the CLIENT initiates all connections. Response 227 contains: IP address in dotted decimal (as comma-separated octets) and port encoded as two numbers (p1, p2) where port = p1×256 + p2. Example: 227 Entering Passive Mode (128,121,136,217,117,237) → IP=128.121.136.217, port=117×256+237=30189.

Analyze Passive Mode FTP Connections

The PASV command is issued by the client to request that the server listen for a separate data connection to be established by the FTP client. When the server responds to the PASV command, it includes its IP address and the port number that it will be listening on for the PASV connection.

The response 227 (Entering Passive Mode) contains the server's IP address and port in the format: (h1,h2,h3,h4,p1,p2) where h1-h4 are the four octets of the IP address and p1,p2 encode the port number: port = p1 × 256 + p2.

Example FTP passive mode sequence:

  1. Client sends PASV command
  2. Server responds: 227 Entering Passive Mode (128,121,136,217,117,237) → port 30189
  3. Client establishes TCP connection to server port 30189 (data channel)
  4. Client sends RETR command on command channel
  5. Server responds 150 (data connection open, starting transfer)
  6. Data flows on the data channel
  7. Server sends 226 (transfer complete) on command channel
FILTER: FTP || FTP-DATA

Use ftp || ftp-data to view both the FTP command channel and the FTP data channel simultaneously. Wireshark is smart — since FTP data channel traffic can run over a dynamically defined port number, Wireshark parses the IP address and port information contained in packets that contain the PORT command or in response packets to the PASV command to identify traffic that should match the ftp-data filter.

🧠
MENTAL NOTE
Passive mode: client initiates data connection. Server opens port + reports it in response 227. Port calculation: p1×256+p2. Solves firewall problem — no inbound connections to client needed. Wireshark auto-detects ftp-data channel using PASV response port info. Most modern FTP clients use passive mode by default.

💡THINK FIRST · ACTIVE MODE FTP

In active mode FTP, the CLIENT sends a PORT command to tell the server where to connect for the data channel. Then the SERVER initiates the data connection. What security concern does active mode raise? And what is the PORT command format?

HINT

Think about what 'active' means from the server's perspective — the server actively connects back to the client. How does this interact with client-side firewalls?

MODEL ANSWER

Active mode: client sends PORT command with its IP and chosen port. Server initiates inbound TCP connection to that port. Security concern: (1) The server connects BACK to the client — many client-side firewalls block this inbound connection. (2) FTP bounce attack: a malicious client can specify any IP:port in the PORT command, causing the server to connect to a third-party host on that port — effectively using the FTP server as a TCP proxy. Servers can block this by rejecting PORT commands where the IP doesn't match the client's connection IP. PORT format: same as PASV response — PORT h1,h2,h3,h4,p1,p2.

Analyze Active Mode FTP Connections

In an active mode data transfer, the client issues the PORT command and indicates the IP address and port number that it will listen on for a data channel connection that will be established by the server. This is the opposite of passive mode — in active mode, the SERVER initiates the data connection.

The PORT command packet includes the client's IP address and port on which it will listen to the server's connection request:

Example: PORT 192,168,0,101,206,177 → Client IP=192.168.0.101, port=206×256+177=52913

ACTIVE MODE AND FIREWALLS

Active mode FTP fails through most corporate firewalls because the server must initiate an INBOUND TCP connection to the client. Client-side firewalls and NAT devices typically block unsolicited inbound connections. This is why passive mode is the default for most FTP clients. If your FTP client is failing through a firewall, try switching to passive mode.

FTP BOUNCE ATTACK

The FTP bounce attack exploits active mode: a malicious client sends a PORT command with a third-party host's IP address and port. The FTP server then connects to that third-party host — effectively being used as a TCP proxy. Modern FTP servers reject PORT commands where the IP address doesn't match the client's connection address. FTP server response 425 with 'Possible bounce attack' message indicates this protection is active.

🧠
MENTAL NOTE
Active mode: CLIENT sends PORT command with its IP+port, SERVER initiates data connection. Problem: inbound connection to client = blocked by firewalls. FTP bounce: PORT with third-party IP = server connects to innocent third party. Server response 425 = bounce attack detected. Passive mode preferred for firewalled environments.

💡THINK FIRST · FTP PROBLEMS

FTP communication problems start with the TCP handshake. If the server doesn't have the FTP daemon running, what happens to the SYN packet? If passive mode is blocked by a firewall, what sequence of events would you see in Wireshark? How many connection attempts does the client make before giving up?

HINT

Think about what happens at the TCP level when FTP fails, and then what happens at the FTP application level when passive mode doesn't work.

MODEL ANSWER

FTP daemon not running: server sends TCP RST in response to SYN — connection refused, FTP never starts. Firewall blocking port 21: SYN gets no response — TCP retransmits (usually 3-5 times) then gives up. Passive mode blocked by firewall: server sends 227 (entering passive mode) with port info. Client tries to establish TCP connection to that port — firewall blocks it. After 5 failed connection attempts, client gives up. Server sends message 'You could at least say goodbye.' Then client shuts down the command channel. You see: PASV → 227 → SYN (data channel) → no response → retransmits → client quits.

Analyze FTP Problems

FTP communication problems begin with the TCP handshake. If a server does not have the FTP daemon running, it responds to TCP SYN packets on the FTP port with a TCP RST response. If the FTP server is configured to use a different port than the client uses, the FTP connection cannot be established properly.

In addition, if a firewall blocks passive mode support, the passive mode connection attempt will fail:

  1. Client sends PASV command
  2. Server responds with 227 Entering Passive Mode (including IP and port)
  3. This indicates the server supports passive mode connections
  4. Client attempts to make a connection on the port provided
  5. The port is open on the server, but the server does not respond to the connection attempts
  6. If the port is open: server should respond with SYN/ACK. If port is closed: server should respond with TCP RST. If no response: a firewall along the path or on the server may be blocking this port.
  7. After five attempts to make a connection, the client gives up and shuts down the command channel
  8. The server responds with the message — 'You could at least say goodbye.' What attitude!
FTP PROBLEMS CHECKLIST
  • RST in response to SYN on port 21: FTP daemon not running
  • No response to SYN on port 21: firewall blocking port 21
  • 227 received but data channel SYN gets no response: firewall blocking passive mode data port
  • 530 Not Logged In: wrong credentials
  • 425 Can't open data connection: active mode data connection failed
  • 425 Possible bounce attack: client used PORT with foreign IP
🧠
MENTAL NOTE
FTP failure sequence: RST to SYN=daemon not running. No response to SYN=firewall. 227 received but data channel fails=firewall blocking passive port. Client retries data connection 5 times then quits. Server's 'goodbye' message = server-side humor about ungraceful disconnects. Check firewall rules for both port 21 AND the passive port range.

Dissect the FTP Packet Structure & Filters

The FTP packet structure is very simple. FTP commands follow immediately after the TCP header. Some commands include an argument as in the case of the RETR command.

Responses contain a numerical code and text as plain text in the response packet. The response code and the response argument are in plain text in the response packet.

Data packets have an even simpler format — the data follows the TCP header directly. No extra commands are required or allowed on the data channel.

Reassemble FTP Traffic

Reassembling FTP traffic is very easy because the data channel contains just the data being transferred. No extra commands are embedded in the data stream. To reassemble FTP traffic: Follow TCP Stream on the data channel, define the format as raw and choose Save As. If you captured the command sequence preceding the data transfer in your trace file, you should have the name of the original file being transferred. This is useful in case you are unsure of the format of the file and do not recognize the file identifier.

FTP FILTER REFERENCE
ftp.request.command=="USER" — FTP USER packets (login attempts)
ftp.request.command=="USER" || ftp.request.command=="PASS" — USER or PASS
ftp.request.command=="USER" && ftp.request.arg=="Fred" — Login as Fred
ftp.request.command=="PASS" && ftp.request.arg matches "(?i)krueger" — Password (case insensitive)
ftp.response.code==230 — Successful FTP logins
ftp.request.command=="PASV" — FTP passive mode requests
ftp.response.code==227 — Entering Passive Mode responses
ftp.request.command=="MKD" && ftp.request.arg=="dir01" — Make directory dir01
ftp.response.code==257 — Successful directory creation

Case Study 1
Secret FTP Communications
FTP Idle Traffic Analysis

When a new computer comes into the office we typically perform an idle analysis of the system.

One day a new Windows XP Home Edition laptop arrived. It would eventually be updated to Windows Vista for testing. We started it up, installed the operating system, and then just let it sit alone, untouched, while we captured traffic to and from the idle system.

After returning to the machine later in the day and reviewing the traffic to and from the unattended system, we spotted an interesting traffic pattern — an FTP connection.

Considering that we had not done anything other than install the operating system, we did not expect to see any interesting traffic. Instead, we saw a successful FTP connection to a server called rockford.discoverconsole.com. We could see the username 'discover' and the password 'qu1ck41cry' in clear text.

We also saw a CWD request for DISCoverFTP/SystemUpdates/HP_DEC. Why would a new system try to make an FTP connection to a remote FTP server? Surely a vendor wouldn't release a system that performed such a lame operation transparent to the user?

A bit of research uncovered information about discoverconsole.com (which is now CompuExpert). It turned out that HP shipped their Windows XP Media Center edition with this 'value added' set of games pre-installed and automatically updated on the system.

It is now mandatory that all new laptops are analyzed the moment they start up.

🧠
MENTAL NOTE
FTP = clear text credentials. Always capture command channel for credential harvesting analysis. Reassemble data channel: Follow TCP Stream → raw → Save As. FTP idle traffic analysis: start capture BEFORE connecting anything. Secret/unexpected FTP = possible software phoning home or malware. Filter ftp.request.command=="USER" to find all login attempts.

CHAPTER SUMMARY

TL;DR — Chapter 24

FTP is a TCP-based file transfer application. FTP communications use a separate connection for commands and data transfer. The most common port number used for the FTP command channel is port 21, but FTP can be configured to run over any other port number if desired. The data channel may use port 20 or use a port number established through the PORT or PASV command channel process.

There are two types of FTP transfer processes — active mode and passive mode. Active mode FTP data transfers use the PORT command; the data transfer connection is established by the FTP server to the FTP client. Passive mode data transfers use the PASV command; the data transfer connection is established by the FTP client to the FTP server.

Interestingly, the commands that many FTP users are familiar with — get and put — are not the actual commands that FTP communications use on the network. When the user types a get command, FTP sends a RETR request. When the user types put, FTP issues an STOR command.

FTP servers respond with a numerical code indicating the status of the request. Response codes in the 400 and 500 range indicate that a problem has occurred.

FTP traffic is not secure — username and password are transmitted in clear text.

Review Questions

Q24.1
What is the purpose of FTP?
HINT

Think about what FTP provides and where it runs.

ANSWER

FTP is a basic file transfer protocol. Any type of file can be transferred using FTP. FTP uses TCP for reliable transport, and is defined in RFC 959. FTP supports commands for file upload (STOR), download (RETR), directory navigation (CWD, PWD, NLST), file deletion (DELE), and directory management (MKD, RMD). FTP is NOT secure — credentials and data are transmitted in clear text.

Q24.2
What are the two connections used for in FTP communications?
HINT

Think about what each channel carries and which port each uses.

ANSWER

FTP communications use one connection as a command channel and a second connection as a data channel. The command channel (port 21) carries all FTP commands and responses in plain text and remains open for the entire FTP session. The data channel (dynamic port) carries the actual file data and directory listings and is opened on demand for each transfer and closed when the transfer completes.

Q24.3
What is the purpose of the FTP PORT command?
HINT

Think about active mode FTP — who initiates what connection?

ANSWER

The PORT command is used by the client to establish an active mode FTP connection. PORT is used by the client to tell the server the IP address and port number the client will listen on for a data channel connection to be established by the FTP server. The format is PORT h1,h2,h3,h4,p1,p2 where the port number = p1×256 + p2. In active mode, the server initiates the data connection to the client.

Q24.4
What is the purpose of the FTP PASV command?
HINT

Think about passive mode — who initiates what connection and what does the server respond with?

ANSWER

The PASV command is used by the client to establish a passive mode FTP connection. If the FTP server supports passive mode connections, the server responds to PASV packets with the IP address and port number that the server will listen on for a data channel connection that will be established by the FTP client. The response code is 227 (Entering Passive Mode). In passive mode, the client initiates all data connections — making passive mode work through firewalls and NAT devices where active mode fails.

Q24.5
How secure is FTP traffic?
HINT

Think about what information is visible in the command channel and what this means for security.

ANSWER

FTP is not secure. The FTP user name and password are sent in clear text on the command channel. Any analyst capturing traffic between the FTP client and server can read the credentials directly from the PASS command. File contents are also sent in clear text on the data channel. For secure file transfers, use SFTP (SSH File Transfer Protocol) or FTPS (FTP over TLS), which encrypt both credentials and data.

Q24.6
What is the syntax for capture and display filters for FTP command traffic running over port 21?
HINT

Note that the capture filter and display filter syntaxes differ.

ANSWER

For FTP command channel traffic: Capture filter: tcp port 21. Display filter: ftp. For FTP data channel: capture filter = tcp port 20 (if using standard active mode port). Display filter: ftp-data. To view both command and data channels: display filter ftp || ftp-data. Note: the ftp display filter only works if the traffic uses port 21 — for non-standard ports use tcp.port==<port>.
