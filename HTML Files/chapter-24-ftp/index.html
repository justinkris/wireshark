    Chapter 24: FTP

    Chapter 24 covers FTP (File Transfer Protocol) — an older clear-text protocol using two TCP connections: a control channel (port 21) and a separate data channel. You'll analyze FTP commands and responses, active vs. passive mode, and use Follow TCP Stream to extract transferred files.

    Guided Analysis — FTP Control Channel
    Concept — Q1
    FTP uses two separate TCP connections. What are they, and which port does each use? Why does FTP use two connections instead of one?
    Control channel: TCP port 21 — carries FTP commands (USER, PASS, LIST, RETR, STOR) and server responses (220, 230, 226, etc.). Data channel: a dynamically negotiated port — carries the actual file data or directory listings. Two channels separate protocol control from data flow, allowing commands to continue during a transfer and making it easier to authenticate before any data is sent.
    Concept — Q2
    What is the difference between FTP Active Mode and FTP Passive Mode? Which mode is more firewall-friendly and why?
    Active Mode: The client tells the server which port to connect back to (PORT command), and the server initiates the data connection TO the client. This fails when the client is behind a NAT/firewall. Passive Mode (PASV): The server tells the client which port to connect to on the server side. The client initiates both connections, making it NAT/firewall friendly — no inbound connections required to the client.
    Trace: ftp trace — Q3
    Apply filter ftp to see only FTP control channel commands. What sequence of FTP commands do you see for a successful file download? What response code indicates successful login?
    Typical sequence: 220 (server greeting) → USER → 331 (password required) → PASS → 230 (login successful) → PASV → 227 (entering passive mode with IP:port) → RETR filename → 150 (opening data connection) → 226 (transfer complete). Response code 230 indicates successful authentication. 530 = login failed.
    Optional Traces
    Any FTP trace
    Apply ftp to see commands, then ftp-data to see the data channel. Right-click an ftp-data packet > Follow > TCP Stream to reconstruct the transferred file. Can you identify the file type from the stream content?
    FTP trace — credential exposure
    In the FTP control stream, FTP sends credentials in clear text. In the Follow TCP Stream view, can you see the username and password? This demonstrates why FTPS or SFTP should be used instead.
    FTP trace — active vs passive
    Apply the filter ftp.request.command == "PORT" to find Active Mode connections. Apply ftp.request.command == "PASV" to find Passive Mode. What is more common in your trace?
    Review Questions
    Review Q24.1
    What Wireshark filter shows FTP commands, and what filter shows the data transfer stream?
    ftp shows the FTP control channel (commands and responses on port 21). ftp-data shows the FTP data channel (actual file content). To see both together: ftp || ftp-data. You can also use tcp.port == 21 for the control channel.
    Review Q24.2
    Why is FTP considered insecure, and what protocols replace it for secure file transfer?
    FTP transmits all data — including usernames and passwords — in plain text. Anyone capturing traffic on the path can read credentials and file contents in the Follow TCP Stream view. Secure alternatives: FTPS (FTP over TLS/SSL, still port 21 with STARTTLS or implicit TLS on port 990) and SFTP (SSH File Transfer Protocol, port 22 — entirely different protocol, not FTP over SSH).
    Review Q24.3
    What is the FTP response code for 'login successful,' and what code means 'file transfer complete'?
    230 = User logged in, proceed. 226 = Closing data connection / transfer complete. Other important codes: 220 = Service ready (server greeting), 331 = Password required, 530 = Login failed, 150 = File status okay, opening data connection. These three-digit codes follow SMTP conventions — 2xx = success, 3xx = intermediate, 4xx/5xx = error.
