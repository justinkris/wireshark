Questions

Q1

Open icmp-dest-unreachable.pcapng. What could be the reason why this ICMP ping is unsuccessful? Who responds to the pings and what does the host indicate?

Your Answer
Model Answer
The local router is responding to the ICMP Echo Requests with ICMP Destination Unreachable/Host Unreachable (Type 3, Code 1) messages. This means the router attempted to ARP for the target host but received no ARP reply, indicating the target host is not currently reachable on the local network — it may be powered off, disconnected, or using a different IP address.
Q2

Open icmp-payload.pcapng. What is in the payload of these ICMP packets? Why would this type of traffic be a security concern? Why can't you follow the stream to reassemble the communications?

Your Answer
Model Answer
The payload of ICMP packets can carry arbitrary data, and some tools deliberately put text or binary data in ICMP payloads to covertly tunnel information through firewalls that allow ICMP. This is a security concern because it provides a covert channel that bypasses port-based filtering. You cannot follow an ICMP stream because ICMP is connectionless and Wireshark's Follow Stream feature only works for TCP, UDP, and SSL sessions.
Q3

Open icmp-ping-basic.pcapng. This is a standard ping process. How are the separate ICMP Echo requests distinguished from each other?

Your Answer
Model Answer
Each ICMP Echo Request in a ping sequence is distinguished by a unique Sequence Number field in the ICMP header. The Identifier field groups requests belonging to the same ping session, while the Sequence Number increments with each successive Echo Request, allowing the receiver to match replies to their corresponding requests.
Q4

Open icmp-ping-2signatures.pcapng. What is in the payload of these ICMP packets? How would you create a display filter to show only ICMP Echo packets that contain one or the other payload?

Your Answer
Model Answer
Different operating systems and ping implementations embed different data patterns in ICMP Echo Request payloads. Windows uses a repeating alphabet sequence (abcdefghijklmnopqrstuvwxyz...), Linux uses a counter-based byte sequence, and tools like hping3 allow arbitrary payloads. Examine the Data field in the ICMP dissection to identify the pattern. To filter for a specific payload, use `data contains XX:YY:ZZ` where XX:YY:ZZ are the leading hex bytes of that payload signature — for example, Windows payloads start with `61:62:63` (the ASCII letters "abc"). Combine with `icmp.type==8` to restrict to Echo Requests only.
Q5

Open icmpredirect.pcapng. Map out what is happening. What MAC addresses are used? Why are there two ICMP Echo Replies in the trace file?

Your Answer
Model Answer
An ICMP Redirect (Type 5) is sent by a router telling a host to use a better next-hop for a specific destination. The host initially sent its packet to the wrong router, which still forwarded the packet to the correct destination while simultaneously sending the Redirect back to the host. The two ICMP Echo Replies appear because the original Echo Request was forwarded by the first router and the destination host replied — that reply travels back through the network and arrives at the capture point. Track the MAC addresses in each frame to map which device is the router, the redirect sender, and the end host.
Q6

Open icmp-traceroute-2011.pcapng. Did this traceroute reach the target host? Were all routers along the path discovered? How many hops away is the target?

Your Answer
Model Answer
The traceroute did reach the target or ran out of TTL hops depending on the specific trace; the important concept is that each router along the path is discovered when it receives a packet with TTL=1 and responds with an ICMP Time Exceeded/TTL Exceeded in Transit (Type 11, Code 0) message. Routers that do not generate this response appear as asterisks (*) in the traceroute output and cannot be mapped.
Q7

Open icmp-traceroute-normal.pcapng. This classic ICMP-based traceroute shows the dependency on the Time to Live Exceeded response. Were all routers along the path discovered?

Your Answer
Model Answer
This traceroute uses ICMP Echo Requests with incrementing TTL values to discover each router along the path. Routers that do not generate ICMP Time Exceeded responses (because they are configured to suppress them, or are rate-limiting ICMP) will not appear in the traceroute output and are listed as undiscovered hops.
Q8

Open ipv6-pinginipv4.pcapng. What ICMP Type number is used for ICMPv6 Echo Requests and Echo Replies? How many routers can the Echo Requests and Replies cross from the capture point?

Your Answer
Model Answer
ICMPv6 uses Type 128 for Echo Requests and Type 129 for Echo Replies — these are analogous to ICMPv4 Types 8 and 0. Because the packets are encapsulated in an IPv4 header for 6to4 transport, the hop count visible in the outer IPv4 TTL field limits how many IPv4 routers the encapsulated packet can traverse.
