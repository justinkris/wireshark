ICMP is the network's voice — it tells you when and why things go wrong.

From ping to traceroute to Path MTU Discovery, ICMP is everywhere in network operations.

💡THINK FIRST · PURPOSE OF ICMP

ICMP carries error and informational messages — but it doesn't fix problems itself. If a router can't forward a packet because TTL expired, it sends ICMP Type 11. But what determines whether the SENDING host does anything with that ICMP message? What would happen if all ICMP messages were blocked?

HINT

Consider: ICMP is advisory. The host receives ICMP messages but is not required to act on them. What critical network function depends on ICMP Type 3, Code 4 messages reaching the sender?

MODEL ANSWER

ICMP provides error reporting and diagnostic messaging — but it doesn't retransmit lost packets or establish connections. Hosts use ICMP messages to learn about network conditions (e.g., better routes via Redirect, path MTU via Type 3 Code 4). If ICMP is blocked: Path MTU Discovery (PMTUD) fails — TCP connections stall because hosts can't learn the MTU of the path (Black Hole problem). Traceroute stops working. Ping-based connectivity tests fail. ICMP filtering for security has trade-offs; blocking all ICMP creates serious operational problems.

The Purpose of ICMP

ICMP (Internet Control Message Protocol) is used as a messaging system for errors, alerts, and general notifications on an IP network. ICMP is defined in RFC 792. There are many ICMP message types including:

  • Echo messages — used by ping and traceroute to test end-to-end connectivity. Too many might signal a reconnaissance process or Denial of Service attack.
  • Redirect messages — used by routers to let the source know there is a better path to a destination. If this packet is not sent by a router, it should be considered suspect.
  • Destination Unreachable messages — tell the source host that their packet could not be delivered. A large number of these reply packets could indicate an unsuccessful UDP port scan or a service not running properly.

By examining the ICMP traffic on your network for a few hours or days, you can determine how efficiently the network is designed and spot numerous configuration errors, functional problems, or security breaches. ICMP is defined in RFC 792.

KEY ROLE: ICMP IN PATH MTU DISCOVERY

ICMP Type 3, Code 4 (Fragmentation Needed, Don't Fragment Bit Set) is critical for TCP connections. When a router can't forward a packet because the MTU is too small and DF=1, it sends this ICMP back to the source. The source adjusts its packet size. If firewalls block this ICMP type, TCP connections stall silently — called the "Black Hole" problem. Never block ICMP Type 3.

🧠
MENTAL NOTE
ICMP purpose: error reporting (Dest Unreachable, Time Exceeded), routing advice (Redirect), diagnostics (Echo Request/Reply). RFC 792. ICMP does NOT fix problems — it advises. Blocking ICMP Type 3 causes Black Hole (PMTUD failure). Key: ICMP messages often trigger based on original packet contents.

💡THINK FIRST · NORMAL ICMP TRAFFIC

Wireshark shows ICMP using default coloring rules. During a traceroute, you'll see a distinctive pattern of alternating Echo Requests and Time Exceeded messages — the "striping" effect. What creates this striping? How does traceroute use TTL to map routers along a path?

HINT

Traceroute sends packets with TTL=1, 2, 3... How does this cause each router along the path to reveal its IP address? What ICMP message type does each router send back?

MODEL ANSWER

Traceroute works by sending packets with incrementing TTL: TTL=1 causes the first router to discard and send ICMP Time Exceeded (Type 11, Code 0) revealing its IP. TTL=2 causes the second router to do the same. This continues until the destination is reached. The striping in Wireshark appears because each TTL group generates a Time Exceeded from a different router IP. ICMP-based traceroute uses ICMP Echo Requests. TCP-based traceroute uses TCP SYNs. UDP-based traceroute (Unix default) uses UDP with unusual port numbers. All trigger ICMP Time Exceeded responses from intermediate routers.

Analyze Normal ICMP Traffic

Normal ICMP traffic comes from three main operations: ping, traceroute, and error responses. In this book, normal ICMP traffic includes ICMP ping tests and ICMP-based traceroute traffic.

ICMP-Based Ping

ICMP ping uses Type 8 (Echo Request) and Type 0 (Echo Reply). Each ping exchange shows:

  • Echo Request from source to target — Type 8, Code 0
  • Echo Reply from target back to source — Type 0, Code 0
  • The Identifier and Sequence Number fields link requests to replies
  • The Data field contains payload (usually repeating pattern)

MEASURE RTT WITH ICMP FILTER

Set the Time column to Seconds Since Previous Displayed Packet and apply an icmp filter to get precise round-trip time values from any capture location. Wireshark's timing is typically more granular than the command-line ping response time — this gives you per-packet RTT measurements.

ICMP-Based Traceroute

ICMP traceroute uses Echo Requests with incrementing TTL values. There are three variations:

  • ICMP-based (Windows default): sends ICMP Echo Requests with TTL=1, 2, 3... Each router along the path responds with ICMP Time Exceeded (Type 11, Code 0)
  • UDP-based (Unix/Linux default): sends UDP packets to high-numbered ports with incrementing TTL
  • TCP-based: sends TCP SYN packets with incrementing TTL — used to test through firewalls

When Wireshark's default colorization is enabled, traceroute traffic appears as alternating colored stripes — ICMP Echo Requests mixed with ICMP Time Exceeded responses from intermediate routers.

💡THINK FIRST · ICMP PROBLEMS

An ICMP Redirect (Type 5) message from a router tells a host to use a different gateway for a specific destination. Why is this message a security concern if not sent by a router? What would happen if a malicious host sent a spoofed Redirect message?

HINT

Think about what a host does when it receives an ICMP Redirect — it updates its routing table. Who else could send a spoofed Redirect and why would that be dangerous?

MODEL ANSWER

ICMP Redirect (Type 5) tells the receiver to update its routing table with a new next-hop for a destination. If received from a router, it's legitimate — the router found a better path. If a non-router sends a spoofed Redirect, it can redirect a host's traffic to the attacker (man-in-the-middle attack). Legitimate use: a router on the same subnet as the sender detects that the sender is routing through it unnecessarily, and redirects the sender to use the correct router directly. Security rule: Redirect packets not sourced from a router should be treated as suspect.

Analyze ICMP Problems

Ping Failure

One common ICMP problem is an echo test that does not receive a reply, implying there is no connectivity to a target. Identifying the point where the ICMP traffic is dropped requires moving the Wireshark system along the path until you reach the point where packet loss occurs.

NO ICMP REPLY — WHAT TO CHECK

When ICMP Echo Requests go unanswered: (1) Target host is down or unreachable. (2) Firewall is silently dropping pings. (3) Target OS has ping disabled. (4) Network path is broken. Start by pinging the default gateway. If that succeeds, progressively ping hosts closer to the target to find the failure point.

ICMP Redirect

ICMP Redirect packets (Type 5) are sent by routers when they receive a packet they must forward but detect there is a better next-hop on the same segment as the original sender. The router forwards the packet AND sends an ICMP Redirect to tell the sender to use the better route directly next time.

Upon receipt of an ICMP Redirect (Type 5, Code 1 — Redirect Datagram for the Host), a host should add a dynamic route entry to its routing tables and begin using the new routing information immediately.

ICMP Redirect Codes:

  • Code 0: Redirect Datagram for the Network (or subnet)
  • Code 1: Redirect Datagram for the Host
  • Code 2: Redirect Datagram for the Type of Service and Network
  • Code 3: Redirect Datagram for the Type of Service and Host

Destination Unreachable Messages

ICMP Destination Unreachable (Type 3) packets contain the IP header and at least the next 8 bytes of the packet that triggered the ICMP response. By examining this embedded packet, you can determine why the Destination Unreachable was sent.

ICMP Destination Unreachable responses to TCP handshake connection requests (Port Unreachable) are unusual — TCP connections should elicit either a SYN/ACK or a TCP Reset. An ICMP response to a TCP handshake is a likely indication that a host-based firewall is blocking a port (verbose host firewall).

ICMP REVEALS THE TRIGGERING PACKET

ICMP error messages (Type 3, 4, 5, 11, 12) include the IP header + first 8 bytes of the original packet that caused the error. This allows you to identify: what protocol was running, what source/destination ports were involved, and reconstruct what went wrong. Examine the embedded headers in ICMP error packets!

🧠
MENTAL NOTE
Redirect (Type 5): legitimate from routers = routing optimization; from non-routers = potential MitM attack. Dest Unreachable (Type 3): contains embedded IP header + 8 bytes of original packet. Code 3 (Port Unreachable) for TCP = verbose firewall (should get RST instead). Time Exceeded (Type 11) = TTL expired or reassembly timeout.

💡THINK FIRST · ICMP PACKET STRUCTURE

ICMP packets do not contain TCP or UDP headers — what does this mean for port-based filtering? An ICMP Type 3 (Destination Unreachable) packet embeds the original IP header. What specifically does this embedded header allow you to determine?

HINT

Think about why ICMP packets can't be filtered by port number. Also consider what information the embedded IP header inside a Type 3 ICMP packet gives you about the original communication that failed.

MODEL ANSWER

ICMP has no port numbers — port-based firewalls can't selectively block some ICMP messages based on port. They must allow all ICMP or none (or filter by Type/Code). The embedded IP header in Type 3/5/11/12 packets includes: source/destination IP, protocol (TCP/UDP), and the first 8 bytes of data (which includes the source/destination ports for TCP/UDP). This lets you identify exactly which connection caused the ICMP error — even though the ICMP itself has no port fields.

Dissect the ICMP Packet Structure

ICMP packets do not contain a UDP or TCP header — port filtering settings cannot affect ICMP traffic. ICMP packets only contain three required fields after the IP header: type, code, and checksum. Some ICMP packets contain additional fields to provide information or details on the message.

Type Field

The Type field identifies the category of ICMP message. Key ICMP Type values:

  • Type 0: Echo Reply [RFC 792]
  • Type 3: Destination Unreachable [RFC 792]
  • Type 4: Source Quench [RFC 792] — deprecated
  • Type 5: Redirect [RFC 792]
  • Type 8: Echo Request [RFC 792]
  • Type 9: Router Advertisement [RFC 1256]
  • Type 10: Router Solicitation [RFC 1256]
  • Type 11: Time Exceeded [RFC 792]
  • Type 12: Parameter Problem [RFC 792]
  • Type 13: Timestamp [RFC 792]
  • Type 14: Timestamp Reply [RFC 792]

Code Field

The Code field provides more detail within a Type. Type 3 (Destination Unreachable) Codes:

  • Code 0: Net Unreachable
  • Code 1: Host Unreachable
  • Code 2: Protocol Unreachable
  • Code 3: Port Unreachable
  • Code 4: Fragmentation Needed, Don't Fragment Bit Set
  • Code 5: Source Route Failed
  • Code 9: Communication with Destination Network Administratively Prohibited
  • Code 10: Communication with Destination Host Administratively Prohibited
  • Code 11: Network Unreachable for Type of Service
  • Code 13: Communication Administratively Prohibited (firewall)

Type 11 (Time Exceeded) Codes: Code 0: Time to Live Exceeded in Transit; Code 1: Fragment Reassembly Time Exceeded

Type 5 (Redirect) Codes: Code 0: Network; Code 1: Host; Code 2: ToS+Network; Code 3: ToS+Host

Checksum Field

The ICMP checksum covers the ICMP header and data (unlike IP checksum which only covers the IP header). Unlike TCP and UDP, the ICMP checksum does NOT include a pseudo-header from the IP layer.

TYPE 3 CODE 13 — WHO SENDS IT?

ICMP Type 3, Code 13 (Communication Administratively Prohibited) is typically generated by a verbose firewall. Most firewalls silently discard blocked packets rather than send this notification (which would reveal the firewall's presence). Seeing Code 13 in a trace often means the blocking device is explicitly notifying the sender — useful for troubleshooting but potentially a security information leak.

🧠
MENTAL NOTE
ICMP: Type + Code + Checksum (no ports!). Type 3 = Dest Unreachable (Code 4 = DF needed, Code 13 = firewall). Type 5 = Redirect. Type 8/0 = ping. Type 11 = TTL exceeded. ICMP error messages embed the IP header + first 8 bytes of triggering packet. No port filtering possible — filter by icmp.type and icmp.code.

💡THINK FIRST · ICMPv6

ICMPv6 is far more than just the IPv6 equivalent of ICMPv4 — it takes on functions that were separate protocols in IPv4. What IPv4 protocols does ICMPv6 completely replace? What does this mean for network operation without ICMPv6?

HINT

In IPv4: ARP resolves MAC addresses, IGMP handles multicast group management, and DHCP handles address configuration. What happens to these functions in IPv6?

MODEL ANSWER

ICMPv6 replaces: (1) ARP → replaced by Neighbor Discovery Protocol (NDP) using ICMPv6 Types 135/136. (2) IGMP → replaced by MLD (Multicast Listener Discovery) using ICMPv6 Types 130-132. (3) Router Discovery → Router Solicitation/Advertisement (Types 133/134). ICMPv6 is also required for IPv6 PMTUD (Type 2 - Packet Too Big), duplicate address detection (DAD), and SLAAC. Without ICMPv6, IPv6 networks cannot function — you cannot block ICMPv6 the way you might block ICMPv4 pings.

Analyze ICMPv6 Traffic

ICMPv6 is defined in RFC 4443. It performs far more functions than ICMPv4, replacing ARP and IGMP and enabling IPv6 auto-configuration.

ICMPv6 vs ICMPv4

ICMPv6 handles all the same error reporting as ICMPv4, plus many additional functions:

  • Neighbor Discovery (NDP) — replaces ARP entirely. Uses ICMPv6 Types 135 (Neighbor Solicitation) and 136 (Neighbor Advertisement)
  • Router Discovery — Type 133 (Router Solicitation), Type 134 (Router Advertisement). Hosts use RAs for SLAAC
  • Duplicate Address Detection (DAD) — hosts send Neighbor Solicitation with :: source before using an IPv6 address
  • Path MTU Discovery — Type 2 (Packet Too Big) replaces ICMP Type 3 Code 4
  • Multicast Listener Discovery (MLD) — Types 130-132, replaces IGMP

Key ICMPv6 Type Numbers

  • Type 1: Destination Unreachable | Type 2: Packet Too Big | Type 3: Time Exceeded | Type 4: Parameter Problem
  • Type 128: Echo Request | Type 129: Echo Reply
  • Type 130: MLD Listener Query | Type 131: MLD Report | Type 132: MLD Done
  • Type 133: Router Solicitation | Type 134: Router Advertisement
  • Type 135: Neighbor Solicitation | Type 136: Neighbor Advertisement
  • Type 137: Redirect | Type 138: Router Renumbering
  • Type 143: MLDv2 Report | Type 148: SEND Certificate Path | Type 151-153: Multicast Router Discovery

ICMPv6 Type 1 Destination Unreachable Codes

  • Code 0: No route to destination
  • Code 1: Communication with destination administratively prohibited
  • Code 2: Beyond scope of source address
  • Code 3: Address unreachable (catch-all)
  • Code 4: Port unreachable
  • Code 5: Source address failed ingress/egress policy
  • Code 6: Reject route to destination

ICMPv6 IS CRITICAL — NEVER BLOCK ALL OF IT

Unlike ICMPv4, you cannot safely block all ICMPv6 traffic. NDP (which replaces ARP) runs over ICMPv6. Blocking it prevents hosts from finding their default gateway, discovering neighbors, or performing DAD. At minimum, Types 133-136 must be allowed for IPv6 to work. Selectively block only specific types (like Type 128 Echo Requests for security) if needed.

FILTER ICMPv6 NEIGHBOR SOLICITATION

DAD uses Neighbor Solicitation from :: (unspecified address): filter (ipv6.src==::) && (icmpv6.type==135). This tells you which hosts are performing duplicate address detection — useful for troubleshooting IPv6 address assignment problems. The target address in the NS is the address being tested.

🧠
MENTAL NOTE
ICMPv6 replaces ARP (NDP Types 135/136), IGMP (MLD 130-132), Router Discovery (133/134). Type 2 = Packet Too Big (replaces ICMP Type 3 Code 4). Type 128/129 = Echo Request/Reply. DAD = Neighbor Solicitation from :: to solicited-node multicast. CANNOT block all ICMPv6 — IPv6 fails without it.

Display Filter Reference

Capture filter syntax: icmp (IPv4) or icmp6 (IPv6). Display filter syntax: icmp or icmpv6.

icmp.type==8 — ICMP ping request
icmp.type==8 || icmp.type==0 — ICMP ping request or response
(icmp.type==8) && !(icmp.code==0) — Unusual ICMP ping packets
icmp.type==13 || icmp.type==15 || icmp.type==17 — Timestamp/Info Requests (OS fingerprinting)
tcp && icmp.type==3 && (icmp.code==1 || icmp.code==2 || icmp.code==3) — ICMP Dest Unreachable response to TCP
icmp.type==11 — Time to Live Exceeded (traceroute?)

Case Study 1
The Dead-End Router
Network Configuration Problem Diagnosed with ICMPv6 Analysis

My customer complained that some of their hosts could not reach the internet on certain days — they would reboot their workstations and everything would work fine.

The traffic showed the clients transmitting Router Solicitations because the default gateway provided by the DHCP server did not reside on the local network.

The accounting server, a Sun host, was configured to respond with Router Advertisements. That Sun host was not a router, however. If the Sun host's Router Advertisement arrived before the Cisco router's Router Advertisement, the client used the Sun host's IP address in its routing tables as the default gateway.

When the clients received the Router Advertisements from the accounting server, they would update their routing tables with the IP address of the accounting server as their default gateway. When the clients wanted to communicate with hosts that were on other networks, they would consult their routing tables and send the packets to the default gateway (the accounting server).

Packets sent to the Sun box for routing were discarded by that box because it didn't really offer routing services — this caused the isolated host problem.

It was easy to spot the problem in just a few minutes with Wireshark.

🧠
MENTAL NOTE
Filter ICMP Type 13/15/17 for OS fingerprinting. ICMP Redirect from non-routers = suspicious. ICMPv6 Router Advertisements can be mis-sent by non-routers — always verify RA source. DAD filter: (ipv6.src==::) && (icmpv6.type==135). ICMP Type 3 Code 4 critical for PMTUD.

CHAPTER SUMMARY

TL;DR — Chapter 18

ICMP offers a messaging service to indicate network configuration problems, unavailable services, hosts that are too far away from each other, fragmentation problems and more.

ICMP packets do not contain TCP or UDP headers — port filtering cannot block ICMP traffic.

Many ICMP packets contain the original header that triggered the ICMP packet.

ICMP Echo Requests are commonly used for standard ping tests and traceroute operations.

ICMPv6 plays several very important roles in IPv6 communications including duplicate address detection, neighbor discovery and more.

Review Questions

Q18.1
What is the purpose of ICMP?
HINT

Think about the three main categories of ICMP messages and what network operations depend on them.

ANSWER

ICMP is used as a messaging system for errors, alerts, and general notifications on an IP network. ICMP provides: (1) Error reporting — Destination Unreachable (Type 3) when packets can't be delivered, Time Exceeded (Type 11) when TTL expires; (2) Network advisories — Redirect (Type 5) for better routing paths; (3) Diagnostics — Echo Request/Reply (Types 8/0) for ping testing. ICMP is defined in RFC 792.

Q18.2
What type of device might generate an ICMP Type 3, Code 13 (Destination Unreachable, Communication Administratively Prohibited) packet?
HINT

Think about who sends ICMP error messages — and why most security devices prefer not to send this particular type.

ANSWER

This packet might be generated by a verbose firewall. Many firewalls will silently discard blocked packets rather than send this packet — a verbose firewall explicitly notifies the sender that the communication is blocked. Sending this ICMP response reveals that a firewall is present (a firewall fingerprinting opportunity for an attacker). For security, most firewalls are configured to silently drop rather than send Code 13.

Q18.3
You have captured only ICMP packets on your network. How can you determine what triggered the ICMP Type 3 (Destination Unreachable) packets on your network?
HINT

Remember that ICMP error messages are not self-contained — they carry information about the packet that triggered them.

ANSWER

ICMP Type 3 packets contain the IP header and at least the next 8 bytes of the packet that triggered this response. Examine the IP header and bytes following the ICMP portion to determine why this packet was sent. In Wireshark, expand the ICMP section and look for the embedded "Internet Protocol" and "User Datagram Protocol" or "Transmission Control Protocol" headers inside the ICMP error message. This reveals the original source/destination IPs and port numbers that caused the Destination Unreachable.

Q18.4
Which ICMPv4 and ICMPv6 packets are used for the standard ICMP-based ping process?
HINT

Ping uses two message types — one from the sender and one from the receiver. The ICMPv4 and ICMPv6 type numbers differ.

ANSWER

For the standard ICMPv4 ping: Type 8 (Echo Request) and Type 0 (Echo Reply). For ICMPv6: Type 128 (Echo Request) and Type 129 (Echo Reply). The Identifier and Sequence Number fields in both protocols link specific requests to their replies. Note: ICMP-based traceroute processes use Echo Requests with incrementing TTL values to elicit ICMP Time Exceeded (Type 11) responses from routers along the path.

Q18.5
What should a host do when it receives an ICMP Type 5, Code 0 (Redirection, Redirect Datagram for the Network/Subnet) packet?
HINT

Think about what information is in the Redirect packet and what the host does with it.

ANSWER

When a host receives an ICMP Type 5, Code 0 (Redirection, Redirect Datagram for the Network/Subnet) packet, it should update its routing tables with the gateway address included in the ICMP packet. When it wants to communicate with that network again at a later time, it will use the new gateway entry in its routing tables. Important: Redirect packets should only be trusted when sourced from a router on the local segment. Redirect messages from non-router hosts should be treated as a potential man-in-the-middle attack.

Q18.6
What is the syntax for capture and display filters for ICMPv4 and ICMPv6 traffic?
HINT

Note that the capture filter and display filter syntaxes differ slightly.

ANSWER

For ICMPv4: Capture filter: icmp — Display filter: icmp
For ICMPv6: Capture filter: icmp6 — Display filter: icmpv6
To capture all ICMP including both versions: icmp or icmp6. To display all: icmp or icmpv6. Additional filters: icmp.type==8 (ping requests), icmp.type==3 (destination unreachable), icmpv6.type==135 (Neighbor Solicitation).

Q18.7
What ICMPv6 packet is used to check for duplicate IP address assignment?
HINT

IPv6 hosts perform Duplicate Address Detection (DAD) before fully claiming an address. What ICMPv6 type is used and what is notable about its source address?

ANSWER

ICMPv6 Neighbor Solicitation (Type 135) is used for duplicate address detection. When a host wants to use an IPv6 address, it first sends a Neighbor Solicitation for that address with a source address of :: (all zeros/unspecified). If another host on the network already has that address, it responds with a Neighbor Advertisement (Type 136), and the first host must not use that address. Display filter: (ipv6.src == ::) && (icmpv6.type == 135). This is why you see :: as a source address in IPv6 captures during host initialization.
