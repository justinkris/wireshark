💭 THINK FIRST · PURPOSE OF ICMP

ICMP is not a transport protocol — it carries no application data. It exists purely to send error and informational messages about IP network conditions back to the original sender.

  • ICMP is often described as "the network's error-reporting system." What critical difference does that make for how ICMP packets appear in a capture compared to TCP or UDP?
  • Many security teams configure firewalls to block all ICMP. What two important network functions can this break?
Q1 — ICMP VS TCP/UDP IN A CAPTURE
ICMP packets appear in response to other packets that triggered an error condition — they're reactive, not part of an application conversation. In a capture, ICMP appears "out of the blue" in the middle of a TCP or UDP session, signaling that something went wrong at the IP layer. Unlike TCP/UDP, ICMP has no port numbers and no connection state. It's encapsulated directly in IP (Protocol=1) and is always sourced from a network device (router, host) describing the error, not the original destination. This means in a conversation trace, ICMP messages will have the router's IP as source, not the remote server's IP.
Q2 — WHAT BLOCKING ALL ICMP BREAKS
Two critical functions that blocking all ICMP breaks: (1) Path MTU Discovery (PMTUD) — which relies on ICMP type 3 code 4 "Fragmentation Needed" messages. Without these, large packets to DF-bit-set connections are silently dropped, causing connections to hang for large data transfers while small packets work fine. (2) Traceroute and network diagnostics — without ICMP Time Exceeded (type 11) responses, path discovery fails. Additionally, blocking ICMPv6 entirely breaks IPv6 neighbor discovery and makes IPv6 unusable.
Section 1

Purpose of ICMP

ICMP (RFC 792) is a Layer 3 protocol used by IP devices to send error and informational messages. It operates inside IP packets (Protocol field = 1). ICMPv6 is the IPv6 equivalent (IPv6 Next Header = 58).

Key principle: ICMP is always generated by a network device (router or host) in response to a problematic packet. The source IP of an ICMP error message is always the device reporting the error, not the original destination.

ICMP packet structure ICMP structure: Type (8 bits) + Code (8 bits) + Checksum (16 bits) + variable data. Type identifies the category; Code provides detail within that category. The original triggering packet's IP header + first 8 bytes of its payload are usually included in the ICMP error data field.
🧠
MENTAL NOTE
ICMP = Protocol 1 (IPv4), Next Header 58 (IPv6). Error messages are reactive — generated by routers/hosts in response to problems. Always source = the reporting device, not the destination. No port numbers. Blocking all ICMP breaks PMTUD and path diagnostics.

💭 THINK FIRST · ICMP MESSAGE TYPES & CODES

Not all ICMP messages indicate errors. Some are informational (ping, timestamp). Knowing the type/code combination is the difference between diagnosing a routing problem and a firewall rule.

  • You see ICMP type 3, code 1 in a trace following a UDP packet. What exactly does this mean, and who sent the ICMP message?
  • What is the difference between ICMP type 3 code 1 (Host Unreachable) and ICMP type 3 code 3 (Port Unreachable)? At what layer does each originate?
Q1 — ICMP TYPE 3 CODE 1
Type 3 Code 1 is "Destination Unreachable — Host Unreachable." This means a router tried to forward the packet to the destination host but could not find a route to that host or the host did not respond to ARP. The ICMP message was sent by the router that determined the host was unreachable, not by the destination host itself (which is unreachable). This is different from the destination host saying the port is closed.
Q2 — HOST UNREACHABLE VS PORT UNREACHABLE
ICMP type 3 code 1 (Host Unreachable) is generated by a router when it cannot forward a packet to the destination host — it's a Layer 3 (routing) failure. The router sends this because no ARP reply came back for the destination IP, or because there's no route to the subnet. ICMP type 3 code 3 (Port Unreachable) is generated by the destination host itself when it receives a UDP packet but has no process listening on that port number. It's a Layer 4 failure at the endpoint. The source IP of the ICMP will tell you who sent it: if it's the router, it's a routing/reachability problem; if it's the target host, the host is up but the port is closed.

💭 THINK FIRST · PING ANALYSIS

Ping is the most basic connectivity test, but there's more in a ping exchange than just "is it alive?" — round-trip time, TTL values, payload sizes, and response patterns all tell a story.

  • A ping to a remote host returns with TTL=56 in the Echo Reply. The OS you're testing from uses initial TTL=64. What can you infer about the network path?
  • You send 4 pings to a server and receive 3 replies. The missing reply is packet 3. What are two possible explanations?
Q1 — TTL=56 IN ECHO REPLY
The Echo Reply arrived with TTL=56. Since ICMP Echo Replies from typical Linux/Unix hosts start with TTL=64, the reply has traversed 64 - 56 = 8 hops from the source. This allows you to estimate the distance in hops without running traceroute. If the reply came from a Windows host (initial TTL=128), it traveled 128 - 56 = 72 hops. If it came from a Cisco router (initial TTL=255), it traveled 255 - 56 = 199 hops. The TTL in the reply is a distance indicator — useful for rough topology mapping.
Q2 — MISSING PING REPLY
Two explanations for a missing ping reply: (1) Packet loss — the 3rd Echo Request was dropped (or the 3rd Echo Reply was dropped) somewhere in the network path. A single lost packet in four pings is a 25% loss rate, which would severely affect real-time applications. (2) Rate limiting — some routers and firewalls rate-limit ICMP processing. The router may respond to the first few pings and then temporarily deprioritize further ICMP traffic. This is normal behavior designed to protect routers from ICMP floods, but it can mislead administrators into thinking there is packet loss when the path is actually healthy.
Section 3

Ping Analysis

ICMP Echo Request (type 8) and Echo Reply (type 0) are the ping protocol. Each contains an Identifier (matches request to reply), a Sequence Number (increments with each ping), and a payload (default 32 bytes on Windows, 56 bytes on Linux).

In Wireshark, ping appears as paired type 8 / type 0 packets with matching Identifiers and Sequence Numbers. Missing sequence numbers indicate lost packets.

FilterWhat It Shows
icmp.type == 8Ping requests (Echo Request)
icmp.type == 0Ping replies (Echo Reply)
icmpAll ICMP traffic
icmp.seq == 5Specific ping sequence number
Measuring RTT in Wireshark Delta time between Echo Request and Echo Reply in Wireshark's Time column (set to "Seconds since previous displayed packet") gives you the round-trip time for each individual ping, more granularly than the ping command's summary.
🧠
MENTAL NOTE
Ping = type 8 (request) + type 0 (reply). Identifier links request/reply pair. Sequence number increments. TTL in reply = initial TTL - hops traversed. Windows default payload=32 bytes, Linux=56 bytes. Rate limiting ≠ packet loss — check with larger ping samples.

💭 THINK FIRST · TRACEROUTE ANALYSIS

Traceroute works by deliberately exploiting TTL expiration and collecting ICMP Time Exceeded responses from each router in the path. The resulting map reveals the route packets take and the latency at each hop.

  • Explain the exact mechanism by which traceroute discovers each hop's IP address. What specific sequence of events produces each line of traceroute output?
  • A traceroute shows asterisks (*) for hops 8, 9, and 10, but then hops 11 onwards respond normally. What does this tell you?
Q1 — HOW TRACEROUTE DISCOVERS EACH HOP
Traceroute sends a packet (UDP to a high port, or ICMP Echo Request, depending on the OS) with TTL=1. The first router decrements TTL to 0, drops the packet, and sends back ICMP Time Exceeded (type 11, code 0). The source IP of this ICMP is the router's IP — traceroute records it as Hop 1. Traceroute then sends the next packet with TTL=2; the first router passes it (TTL becomes 1) and the second router drops it (TTL becomes 0) and sends back ICMP Time Exceeded — that's Hop 2. This continues until the packet reaches the destination, which sends back ICMP Echo Reply (or ICMP Port Unreachable for UDP traceroute). Each "line" of output typically shows 3 probe packets (hence 3 RTT values per hop). The destination is identified when the reply is not ICMP Time Exceeded.
Q2 — ASTERISKS IN TRACEROUTE OUTPUT
Asterisks mean no ICMP Time Exceeded was received for those hops within the timeout period. But hops 11 onwards respond — so the destination is reachable. This means routers at hops 8, 9, 10 are either: (1) configured to not send ICMP Time Exceeded (many firewalls and load balancers block ICMP type 11 outbound for security reasons), or (2) are present in the path but process ICMP at very low priority and the responses arrive after traceroute's timeout. The fact that subsequent hops respond proves the path continues through those routers — they just don't announce themselves.
Section 4

Traceroute Analysis

Traceroute (Windows: tracert, Unix: traceroute) maps the network path by sending probe packets with incrementally increasing TTL values. Each router that drops a packet due to TTL expiration sends back an ICMP Time Exceeded message, revealing its IP address.

Windows tracert uses ICMP Echo Requests. Unix/Linux traceroute uses UDP by default (to high port numbers, typically 33434+). Wireshark will show the probes and corresponding ICMP Time Exceeded replies.

Filter for traceroute hops In Wireshark, use the display filter icmp.type == 11 to isolate all Time Exceeded messages — these are the traceroute responses. Each will have a different source IP corresponding to a different router hop.
Asymmetric routing Asymmetric routing: outbound and return paths may traverse different routers. Traceroute only shows the outbound path (the path your probes take). The return path may be completely different.
🧠
MENTAL NOTE
Traceroute = TTL increments from 1 upward. Each router sends ICMP type 11 (Time Exceeded) when TTL=0. Final destination sends Echo Reply (ICMP tracert) or Port Unreachable (UDP traceroute). Asterisks = ICMP type 11 blocked, NOT necessarily no route. Traceroute shows outbound path only.

💭 THINK FIRST · ICMPv6

ICMPv6 is far more than just the IPv6 version of ping. It completely replaces ARP and is fundamental to IPv6 neighbor discovery, address autoconfiguration, and router discovery. Blocking ICMPv6 can break IPv6 entirely.

  • What ARP functions does ICMPv6 replace, and through what ICMPv6 message types?
  • Why is it especially dangerous to block all ICMPv6 at a firewall, compared to blocking all ICMPv4?
Q1 — ICMPv6 REPLACING ARP
ICMPv6 Neighbor Discovery Protocol (NDP) replaces ARP entirely. The specific message types: Neighbor Solicitation (type 135) replaces ARP Request — sent to the Solicited-Node multicast address to find the MAC of an IPv6 address. Neighbor Advertisement (type 136) replaces ARP Reply — contains the MAC address. Router Solicitation (type 133) is sent by hosts to discover routers (replaces DHCP-based gateway discovery). Router Advertisement (type 134) is sent by routers periodically, containing the network prefix, default gateway, and configuration flags. Additionally, Redirect (type 137) replaces ICMP redirect.
Q2 — BLOCKING ALL ICMPv6
Blocking all ICMPv6 is catastrophic for IPv6: NDP (which replaces ARP) uses ICMPv6 — block it and hosts cannot discover each other's MAC addresses or find the default router. Stateless Address Autoconfiguration (SLAAC), which IPv6 hosts use to self-assign addresses, depends on Router Advertisements (ICMPv6 type 134). Path MTU Discovery in IPv6 relies on ICMPv6 type 2 (Packet Too Big) — without it, all IPv6 connections over non-standard MTU paths fail silently. In comparison, blocking all ICMPv4 mainly breaks ping and traceroute (and PMTUD for IPv4) — bad, but IPv4 can still function. Blocking all ICMPv6 makes IPv6 non-functional.
Section 5

ICMPv6 (RFC 4443) serves both the error-reporting function of ICMPv4 and completely replaces ARP through the Neighbor Discovery Protocol (NDP). It is mandatory for IPv6 operation.
