    Chapter 20: TCP

    Chapter 20 dives deep into TCP — the reliable, ordered, connection-oriented transport protocol that powers HTTP, FTP, SMTP, and most application protocols. You'll analyze the three-way handshake, sequence/acknowledgment numbers, window scaling, and TCP errors including retransmissions, zero windows, and resets.

    Guided Analysis — TCP Three-Way Handshake
    Concept — Q1
    Describe the TCP three-way handshake sequence. What flags are set in each of the three packets, and what does each packet establish?
    1. SYN: Client sends SYN with its ISN (Initial Sequence Number). 2. SYN-ACK: Server acknowledges (ACK = client ISN+1) and sends its own SYN with its own ISN. 3. ACK: Client acknowledges server's SYN (ACK = server ISN+1). After this exchange, both sides have agreed on ISNs and the connection is established. Apply filter tcp.flags.syn==1 to find handshakes.
    Concept — Q2
    What is TCP Window Scaling, and why does it matter for high-bandwidth or high-latency paths? What Wireshark Expert Info message warns about missing window scaling?
    Window Scaling (RFC 1323) extends the 16-bit TCP window field by a scale factor negotiated in the SYN/SYN-ACK. Without it, the max window is 65,535 bytes — a bottleneck on high-BDP (bandwidth-delay product) paths. Wireshark shows 'TCP window scaling used but not understood' or similar Expert Info when it captures mid-stream without seeing the handshake, making window sizes appear incorrectly small.
    Concept — Q3
    What does a TCP RST (Reset) indicate, and what are two common causes you might see in a Wireshark trace?
    RST abruptly terminates a TCP connection without the normal FIN handshake. Common causes: (1) A host receives a packet for a port where no service is listening — it responds with RST/ACK. (2) A stateful firewall or IDS forcibly terminates a suspected malicious connection. Filter: tcp.flags.reset==1. RSTs appearing in bursts often indicate port scanning or refused connections.

    Review Questions
    Review Q20.1
    What is the difference between a TCP FIN teardown and a TCP RST? When would you expect each?
    FIN is a graceful connection close — both sides send FIN and ACK in a four-packet exchange, allowing any in-flight data to be delivered. RST is an immediate abort — all data in transit is discarded. Expect FIN when an application closes normally. Expect RST when no service is listening on a port, a firewall blocks the connection, or a connection is forcibly terminated.
    Review Q20.2
    Explain TCP's sliding window mechanism and how it relates to throughput.
    The TCP window advertises how many bytes the receiver can accept before requiring an ACK. A larger window allows more data in flight simultaneously, enabling higher throughput on high-latency links. If the window shrinks to zero (Zero Window), the sender must pause until the receiver opens the window again. Throughput is limited by: min(congestion window, receiver window) / RTT.
    Review Q20.3
    What Wireshark filter finds TCP retransmissions, and what are the two types Wireshark distinguishes?
    tcp.analysis.retransmission finds standard retransmissions (RTO expired, no ACK received). tcp.analysis.fast_retransmission finds fast retransmissions (triggered by 3 duplicate ACKs, faster than waiting for RTO). Seeing many fast retransmissions suggests packet loss on the path; seeing mostly RTO retransmissions suggests severe loss or a very high-latency link.
    Review Q20.4
    What is the Wireshark filter to see all TCP Expert Info flags (any TCP anomaly)?
    tcp.analysis.flags matches any packet where Wireshark's TCP analysis engine has set an expert flag — retransmissions, duplicate ACKs, zero windows, window updates, out-of-order segments, etc. This is the fastest way to get a high-level view of all TCP problems in a trace.

    Quick Reference

    tcp.flags.syn==1
    Find SYN packets — handshake starts or mid-stream retransmission of SYN.
    tcp.analysis.retransmission
    Standard retransmission (RTO). See also tcp.analysis.fast_retransmission.
    tcp.flags.reset==1
    RST — abrupt teardown. Ports not listening, firewall block, IDS action.
    tcp.analysis.flags
    Any TCP Expert anomaly flag — the Swiss Army filter for TCP problems.
    Zero Window
    Receiver buffer full; sender must pause. Filter: tcp.analysis.zero_window.
